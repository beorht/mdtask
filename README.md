# mdtask

Веб-платформа для практических заданий в стиле mdBook: преподаватель публикует задания (Markdown), студенты сдают файлы решений, а также отдельный **тренажёр SQL** для практики запросов к SQLite прямо в браузере.

Это не полноценная LMS с баллами и тестами — упрощённый трекер практик с бинарным статусом сдачи (выполнено / не выполнено) плюс интерактивный SQL-тренажёр.

## Стек

- Node.js + Express 5, шаблоны EJS (серверный рендеринг, без сборки и SPA-фреймворка)
- `better-sqlite3` — единственная база данных, без ORM (сырые SQL-запросы в `src/db/index.js`)
- `express-session` — сессии, `multer` — загрузка файлов, `markdown-it` — рендер Markdown
- Тесты: `node:test` + `supertest`

## Быстрый старт

```bash
npm install
npm start        # http://localhost:42521
# или для разработки с автоперезапуском:
npm run dev
```

При первом запуске автоматически создаётся файл БД `data/mdtask.db` и наполняется тестовыми данными (см. `src/db/seed.js` и `src/db/seed-sql-exercises.js`).

### Пароли

- У всех аккаунтов общий стартовый пароль `std-snrg` (см. `src/lib/password.js`, хранится как `scrypt`-хеш с солью, без сторонних зависимостей).
- Любой аккаунт, созданный/существовавший до появления паролей (реальные студенты в `data/mdtask.db`), при первом запуске сервера после обновления автоматически переводится на этот пароль с флагом `must_change_password = 1`.
- Пока флаг установлен, `requireAuth`/`requireRole` (`src/middleware/auth.js`) редиректят любой запрос, кроме `/change-password` и `/logout`, на смену пароля — доступ к остальным разделам платформы закрыт до смены.
- Сменить пароль в любой момент можно по ссылке «Сменить пароль» в шапке (`/change-password`).

## Основной функционал

### Задания (преподаватель ↔ студент)

- Преподаватель создаёт курсы → задания: **индивидуальные** (для одного студента) или **групповые**, а групповые — либо для **конкретной группы**, либо для **всех групп сразу** (поле «Для какой группы» в форме создания, `target_group` в БД, `NULL` = все группы). Список групп берётся динамически из реальных значений `student_group` в БД — новая группа не требует правок кода.
- Условие задания пишется в Markdown прямо в браузере (редактор с превью).
- Студент видит список заданий со статусом (не сдано / на проверке / выполнено / не выполнено) — только тех, что предназначены его группе или лично ему; открывает задание, читает условие, загружает файл решения (`.zip`/`.rar`). Доступ к чужому групповому/индивидуальному заданию напрямую по ссылке также заблокирован (`canAccessAssignment` в `src/routes/student.js`).
- В сайдбаре преподавателя групповые задания дополнительно собраны в отдельные категории «Группа X» — по одной на каждую существующую группу; задание «для всех групп» попадает в категорию каждой группы.
- Преподаватель просматривает сдачи по заданию (таблица всегда показывает актуальную, самую свежую сдачу студента — включая пересдачи после отклонения, а не устаревшую отклонённую версию), выставляет статус done/not_done с комментарием; при "не выполнено" студент может пересдать.
- Загруженные файлы можно скачать прямо из таблицы сдач (`/teacher/assignment/:id/submissions/:submissionId/files/:index`) — оригинальное имя файла сохраняется для скачивания, реальное имя на диске уникально и защищено от path traversal.

Ключевые файлы: `src/routes/student.js`, `src/routes/teacher.js`, `src/lib/summary-writer.js`, `src/lib/sidebar.js`, контент — `content/src/*.md` + `content/SUMMARY.md`.

### Тренажёр SQL (раздел «SQL DataBase» в сайдбаре)

- **Теоретический материал** (`/trainer/theory`) — конспект по темам CREATE TABLE, INSERT, SELECT, WHERE, UPDATE, DELETE, DROP TABLE.
- **Практический тренажёр** (`/trainer`) — 118 заданий (по 10 на каждую из 7 базовых тем CREATE TABLE/INSERT/SELECT/WHERE/UPDATE/DELETE/DROP TABLE, 20 в теме «SELECT + WHERE: вывод данных», плюс 16 по темам DISTINCT, операторы фильтрации, ORDER BY, LIMIT, агрегатные функции и GROUP BY на общей базе магазина `products`/`orders` — `src/db/sql-exercises-query-data.js`, эталонные ответы вычисляются из эталонных решений; плюс 12 по теме «Связи между таблицами» перед JOIN — один ко многим, многие ко многим, один к одному, INSERT/UPDATE/DELETE связанных данных, выборка и подсчёты через вложенные запросы — `src/db/sql-exercises-relations-data.js`), решаются строго по порядку: следующее задание открывается только после верного решения текущего. Доступ ко всем темам открыт всем группам, включая ранее ограниченные IB/WEB.
- У каждого студента — свой файл SQLite-песочницы на задание (`data/trainer/<studentId>/<exerciseId>.db`), пересоздаётся из схемы задания перед каждым запуском, поэтому студенты никогда не конфликтуют друг с другом.
- Перед выполнением запрос проверяется (разрешён только нужный тип оператора и один statement за раз); синтаксические и логические ошибки SQLite показываются студенту прямо в интерфейсе.
- Вся история попыток сохраняется — включая неверные решения и ошибки — и видна студенту под заданием.
- Преподаватель видит сводную таблицу результатов всех студентов: `/teacher/trainer/results`.

Ключевые файлы: `src/routes/trainer.js`, `src/lib/sql-sandbox.js`, `src/db/sql-exercises-data.js`, `src/views/trainer/*`.

### Банк заданий по Python/JS

- Таблица `language_exercises` — 24 задания среднего уровня (по 2 на тему × 6 тем × 2 языка): переменные, арифметические операции, условия, циклы, функции, модули.
- В отличие от SQL-тренажёра, здесь **нет** песочницы/автопроверки — это справочный банк условий для ручной выдачи и проверки преподавателем, а не интерактивный тренажёр.
- Данные и seed: `src/db/language-exercises-data.js`, `src/db/seed-language-exercises.js`; чтение — `db.getLanguageExercises('python' | 'javascript')`.
- Показывается студентам в разделах `/subjects/python` и `/subjects/javascript` («Банк задач», страница задачи — `/subjects/<язык>/bank/<id>`), только для чтения, без сдачи.

### Главная страница студента и предметы

- `/` — отдельная главная без бокового меню: карточки предметов (SQL-тренажёр, Python, JavaScript), сводка по заданиям со сдачей и ближайшие сроки.
- У каждого предмета своя страница и своё боковое меню: `/subjects/sql` (темы: теория + практика), `/subjects/python` и `/subjects/javascript` (общие задания со сдачей по разделам `SUMMARY.md` + банк задач своего языка).
- Страница задания (`/assignment/:id`) показывает навигацию того языка, из которого её открыли (`?subject=`), иначе — последнего открытого.
- Код: `src/lib/student-home.js`, `src/lib/subjects.js`, `buildSidebarTree({ subject })` в `src/lib/sidebar.js`.

## Структура проекта

```
src/
  server.js            # фабрика Express-приложения
  db/                   # better-sqlite3: schema.sql, index.js (запросы, prepared-statement кэш), seed*.js
  lib/                  # markdown, sidebar, summary parser/writer, sql-sandbox, password (scrypt-хеширование)
  middleware/auth.js     # requireRole / requireAuth (+ редирект на смену пароля)
  routes/               # auth (login/change-password/logout), student, teacher, trainer
  views/                # EJS-шаблоны (в т.ч. change-password.ejs)
content/
  SUMMARY.md            # оглавление в стиле mdBook
  src/                  # markdown-файлы заданий
public/                 # css/js без сборки
tests/                  # node:test + supertest
docs/plan.md            # исходное ТЗ проекта (RU)
```

## Оптимизация БД

- `journal_mode = WAL` (для файловой БД) + `synchronous = NORMAL`, увеличенный `cache_size`, `temp_store = MEMORY` — читатели не блокируются на время записи, что важно при одновременной сдаче заданий целой группой.
- Индексы под частые выборки: `assignments(target_group)`, `users(student_group)`, композитный `submissions(assignment_id, student_id)`.
- Prepared-стейтменты кэшируются на уровне модуля (`prepared()` в `src/db/index.js`) — `better-sqlite3` сам их не кэширует, повторная подготовка одного и того же SQL на каждый вызов под нагрузкой заметна.
- Горячий путь «задания студента» (дашборд/сайдбар) ходит в БД с фильтрацией по индексу (`getAssignmentsForStudent`) вместо загрузки всей таблицы и фильтрации в JS на каждый запрос.

## Статус готовности

Реализовано и покрыто тестами (109/109 проходят): вход по ID + паролю с принудительной сменой стартового пароля, загрузка/сдача заданий (с таргетингом на группу/все группы/конкретного студента), редактор Markdown для преподавателя, статусы и пересдачи (с корректным отображением актуальной версии сдачи), скачивание загруженных файлов преподавателем, тренажёр SQL с последовательной разблокировкой, историей попыток и админ-панелью результатов, банк заданий по Python/JS в БД (без UI и автопроверки).

Не реализовано (за рамками текущего ТЗ): роль администратора для управления пользователями (сброс пароля студенту делает пока только сам студент через смену пароля), UI для банка заданий Python/JS, PostgreSQL-бэкенд (см. `docs/plan.md` — упомянут как опция для продакшена).
