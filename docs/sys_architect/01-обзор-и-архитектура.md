# 01. Обзор и общая архитектура

## 1.1. Что это

**mdtask** — учебная платформа колледжа. Преподаватель публикует задания (Markdown),
студенты загружают решения (архивы), а также проходят интерактивные тренажёры и курсы
(SQL, HTML, CSS, Linux, Emmet, «Начальный Python», «JavaScript», информационная
безопасность) и итоговые контрольные. Всё отрисовывается на сервере.

## 1.2. Технологический стек

- **Node.js + Express 5** — HTTP-сервер и маршрутизация.
- **EJS** — серверные шаблоны (`src/views/`).
- **better-sqlite3** — синхронный доступ к SQLite; сырой SQL, без ORM.
- **Нет** шага сборки, фронт-фреймворка, линтера.
- Статика (`public/`): обычный CSS/JS, плюс вендорные библиотеки (CodeMirror 5, Pyodide,
  шрифты, сборка Emmet/HTML-практики) — всё локально, без CDN (в аудиториях нет интернета).
- Тесты: `node:test` + `supertest`; Python-набор для `ib/` (`npm run test:ib`).

## 1.3. Точка входа и создание приложения

```
index.js  →  createApp()  (src/server.js)  →  app.listen(PORT)
```

`index.js` минимален: вызывает `createApp()` и слушает `PORT` (по умолчанию `42521`).

`src/server.js` (`createApp`) настраивает Express и монтирует роутеры. Порядок настройки:

1. `view engine = ejs`, каталог шаблонов `src/views`.
2. `trust proxy` — только если задан `TRUST_PROXY` (нужно за reverse-proxy, чтобы `req.ip`
   был адресом клиента; это важно для проверки «компьютер аудитории» на контрольной).
3. Статика из `public/` (`express.static`) — **до** лимитера частоты, т.е. статика под
   лимит не попадает.
4. Парсеры тела: `urlencoded` (формы) и `json` с лимитом `1mb` (редакторные задания шлют
   целые файлы исходников).
5. **Сессии** (`express-session` + собственный SQLite-store, см. §1.6).
6. `GET /health` → `200 ok` (проверка живости; используется в скрипте перезапуска).

### Мидлвар актуализации студента

После сессий, до роутеров, стоит мидлвар, который на **каждый запрос** для вошедшего
студента перечитывает его `group` и `name` из БД:

```js
app.use((req, res, next) => {
  const cached = req.session && req.session.user;
  if (!cached || cached.role !== 'student') return next();
  const fresh = require('./db').getUserById(cached.id);
  if (!fresh) return req.session.destroy(() => res.redirect('/login')); // удалённый аккаунт — выход
  if (fresh.group !== cached.group || fresh.name !== cached.name) {
    req.session.user = { ...cached, group: fresh.group, name: fresh.name };
  }
  next();
});
```

Следствие: после переноса студента в другую группу (`scripts/fixes/*-regroup.js`) ему
**не нужно** перелогиниваться — новая группа подхватится на следующем запросе.

## 1.4. Порядок монтирования роутеров (важно!)

Общий лимитер частоты (`src/lib/rate-limit.js globalLimiter`) ставится первым, затем:

```
authRoutes            // /login, /logout, /change-password
subjectGuard          // ограничение набора предметов для группы (GROUP_SUBJECTS)
ibRoutes              // /subjects/ib/*  — ДО studentRoutes
emmetRoutes           // /subjects/emmet/*
htmlCourseRoutes      // /subjects/html/*
linuxCourseRoutes     // /subjects/linux/*
cssCourseRoutes       // /subjects/css/*
pythonCourseRoutes    // /subjects/python/*
jsCourseRoutes        // /subjects/javascript/*
webExamRoutes         // /exam/web-final-1 (прочие id пропускает дальше)
examRoutes            // /exam/*
studentRoutes         // /, /subjects/:key, /assignment/*  — главная студента
teacherRoutes         // редиректы старых /teacher/*, POST /api/preview
trainerRoutes         // /trainer (SQL)
adminRoutes           // /admin/*
```

Затем общий `404` (`res.render('404')`).

**Почему порядок критичен:** у `studentRoutes` есть параметрический маршрут
`/subjects/:key`. Если бы он стоял раньше предметных роутеров, он перехватывал бы
`/subjects/ib`, `/subjects/emmet`, `/subjects/html` и т.д. и отдавал 404. Поэтому все
конкретные предметы монтируются **до** `studentRoutes`. Аналогично `webExamRoutes` стоит
до `examRoutes` и пробрасывает чужие id контрольных дальше.

`subjectGuard` (из `src/lib/test-access.js`) монтируется до предметных роутеров: он
закрывает группам предметы вне их набора (`GROUP_SUBJECTS`, `GROUP_HIDDEN_SUBJECTS`) —
страницы `/subjects/<key>`, `/trainer`, `/ib` отвечают 404, если предмет группе не положен.

## 1.5. Аутентификация и роли

Код: `src/middleware/auth.js`, пароли — `src/lib/password.js`.

- Сессионная аутентификация. `req.session.user = { id, role, name, group, mustChangePassword }`.
- Две роли: `student` и `teacher`.
- `requireAuth` — пускает любого вошедшего; `requireRole('teacher')` — только преподавателя
  (иначе `403`); неавторизованного — редирект на `/login`.
- Пока у пользователя `mustChangePassword = 1`, оба мидлвара принудительно редиректят на
  `/change-password` (кроме путей `/change-password` и `/logout`). Так новый аккаунт обязан
  сменить пароль до начала работы.
- **Пароли:** `crypto.scryptSync`. Формат хранения — `{ password_salt, password_hash }`
  (hex). Формат должен оставаться **байт-совместимым** с `ib/server/app.py`, который
  проверяет те же хеши. Общий пароль по умолчанию — `DEFAULT_PASSWORD` (`std-snrg`).

Вся админка закрыта одной строкой в `src/routes/admin.js`:

```js
router.use('/admin', requireRole('teacher'));
```

## 1.6. Сессии (без внешнего пакета-хранилища)

- Хранилище — собственное, в таблице `sessions` SQLite (`src/lib/session-store.js`), без
  доп. npm-зависимости.
- `maxAge` 12 часов, `rolling: true` (срок продлевается при активности), `httpOnly`,
  `sameSite: 'lax'`.
- Секрет — из `SESSION_SECRET` или файла `data/session-secret`.
- Так как сессии в БД, **перезапуск сервера не разлогинивает** студентов (важно во время
  контрольных).
- Исключение: сессии терминала ИБ живут в Python-процессе и теряются при его перезапуске.

Защита входа: `src/lib/login-throttle.js` — учёт неудачных попыток по IP и логину (таблица
`login_attempts`), чтобы ограничить перебор пароля.

## 1.7. Группы и доступ к предметам

- Группы берутся из различных значений `users.student_group` (не из жёсткого списка).
- Таргетинг заданий: `target_type` = `group` | `individual`; `target_group = NULL` — всем
  группам, кроме `NO_SHARED_GROUPS` (`['PRAK','web-1']`).
- `GROUP_SUBJECTS` ограничивает группу набором предметов (например `web-1` видит только
  html, css, emmet, linux); `GROUP_HIDDEN_SUBJECTS` прячет отдельные предметы.
- Группа **`TEST`** (`hasFullAccess` в `src/lib/test-access.js`) видит задания всех групп и
  весь тренажёр открытым; скрыта из таргетинга преподавателя; никогда не блокируется
  замками тем и контрольными.
- Правило видимости задания продублировано в 4 местах (держать синхронно):
  `getAssignmentsForStudent` (БД), `src/lib/sidebar.js`, `canAccessAssignment`
  (`src/routes/student.js`), `isAssignedTo` (`src/lib/admin-data.js`).

## 1.8. Предмет «Информационная безопасность» (`ib/`) и мост

`ib/` — отдельный подпроект на Python (stdlib), со своим `ib/CLAUDE.md`.

- `src/lib/ib-bridge.js` поднимает один долгоживущий дочерний процесс
  `python3 ib/server/bridge.py` и общается с ним построчным JSON по stdin/stdout.
- `src/routes/ib.js` отдаёт страницу терминала и проксирует `/subjects/ib/<task>/api/*`
  (вызов входа несёт ключ задания — он выбирает песочницу), попутно логируя команды.
- Терминальные сессии живут в Python-процессе (теряются при перезапуске).
- Во **всех** заданиях ИБ есть меры против решения «через нейросеть» (guard, доказательство
  из вывода команд, контрольные вопросы, ловушки) — см. `CLAUDE.md` и
  `src/lib/ib-guard.js`.

## 1.9. Переменные окружения

`PORT`, `DB_PATH`, `TRAINER_DB_DIR`, `UPLOAD_DIR`, `CTF_CAESAR_DIR`, `CTF_CONFIGS_DIR`,
`CTF_TERMINAL_DIR`, `CTF_LABS_DIR`, `EXAM_DIR`, `TRUST_PROXY`, `IB_PYTHON`,

## 1.10. Эксплуатация

- Локальный перезапуск после правок в `src/`, `public/`, `content/`:
  ```bash
  lsof -ti:42521 -sTCP:LISTEN | xargs -r kill
  nohup env DB_PATH=./data/mdtask.db TRAINER_DB_DIR=./data/trainer PORT=42521 \
    node index.js > /tmp/mdtask-server.log 2>&1 & disown
  curl localhost:42521/health
  ```
  Нельзя `pkill -f "node index.js"` — убьёт и вызывающий шелл.
- Прод: удалённый сервер, **без SSH**, демон systemd `mdtask` в `/root/mdtask`; команды там
  запускает пользователь. Обновление — серверный скрипт, который трогает только код и
  сохраняет `data/`.
