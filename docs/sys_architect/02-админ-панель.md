# 02. Админ-панель `/admin` (полностью)

Админ-панель — **единственный** интерфейс преподавателя. Классический `/teacher` удалён
(`src/routes/teacher.js` только редиректит старые URL и держит `POST /api/preview`).

## 2.1. Файловая раскладка

| Слой | Файлы |
|------|-------|
| **Маршруты (ядро)** | `src/routes/admin.js` (556 строк) — dashboard, работы/проверка, задания, студенты, курсы, SQL-тренажёр, ИБ, поиск, настройки, обработка ошибок. |

## 2.2. Общий конвейер запроса в админке

Из `src/routes/admin.js`:

1. `router.use('/admin', requireRole('teacher'))` — доступ только преподавателю.
2. Мидлвар общих `res.locals` на каждую админ-страницу:
   - `user` (из сессии), `view` (хелперы), `icon`, `STATUS_META`;
   - `flash` — одноразовое сообщение из `req.session.flash` (после чтения удаляется);
   - `nav = ''`, `searchQuery = ''` (переопределяются на странице);
   - `reviewCount` — число работ в очереди проверки (для бейджа в навигации и «колокольчика»);
     вычисляется через `data.reviewQueue(data.loadContext())` в `try/catch`.
3. Локальные помощники:
   - `flash(req, type, text)` — положить сообщение в сессию;
   - `render(res, template, nav, locals)` → `res.render('admin/'+template, {nav, ...locals})`;
   - `notFound(res, text)` → статус 404 + шаблон `error`.
4. В конце файла — два «хвостовых» мидлвара на `/admin`:
   - неизвестная страница → `notFound(res)` (дружелюбный 404);
   - обработчик ошибок (4 аргумента) → `console.error` + статус 500 + шаблон `error` с кнопкой «Повторить».

### Трёхслойная схема страницы

Почти каждая страница устроена одинаково:

```
route (admin*.js)  →  data.<fn>(ctx, filters)  (admin-data.js)  →  render(res, 'тема', 'nav', locals)
```

Маршрут парсит фильтры из `req.query`, зовёт чистую функцию-агрегатор из `admin-data.js`,
отдаёт результат в EJS. Вся «бизнес-логика» (что считать выполненным, что просроченным, как
отсортировать очередь) живёт в `admin-data.js` и покрыта тестами.

### `loadContext()` — единая загрузка данных на запрос

`admin-data.loadContext()` разово тянет `users`, `courses`, `assignments`, `submissions` и
строит индексы в памяти:

- `userById`, `courseById`, `assignmentById` — Map по id;
- `latestByPair` — Map `"<assignmentId>::<studentId>" → последняя сдача` (пересдача после
  отклонения — новая строка в цепочке; преподаватель всегда работает с текущей попыткой;
  при равных таймстемпах побеждает более поздняя строка — то же правило, что у
  `getLatestSubmission` с `ORDER BY rowid`);
- `works` — массив «последняя сдача на пару (задание, студент)» с посчитанным статусом и
  флагом «сдано с опозданием», отсортированный от новых к старым.

Датасет небольшой (несколько групп), поэтому джойны делаются в JS — проще и быстрее десятка
точечных запросов на страницу.

## 2.3. Навигация (сайдбар)

`src/views/admin/partials/sidebar.ejs`. Хелпер `navItem(key, href, label, icon, badge)`
подсвечивает активный пункт (`nav === key`) и ставит бейдж. Группы пунктов:

- **Dashboard** → `/admin`
- **Обучение**: Курсы `/admin/courses`, Задания `/admin/assignments`, Студенты `/admin/students`
- **Проверка**: Работы студентов `/admin/submissions` (бейдж = `reviewCount`)
- (без подписи) Тренажёр `/admin/trainer`, Emmet `/admin/emmet`, HTML `/admin/html`,
  CSS `/admin/css`, Начальный Python `/admin/python-course`, JavaScript `/admin/js-course`,
  Инфобез `/admin/ib`, Контрольная IB `/admin/exam`, Контрольная WEB `/admin/web-exam`
- внизу: **Доступ к темам** `/admin/locks`, **Настройки** `/admin/settings`

Иконки — inline-SVG из карты `ICON_PATHS` в `admin-view.js` (без картинок/шрифтовых иконок).

## 2.4. Модель статусов

`STATUS_META` в `admin-data.js` — единый словарь статусов. Статус **никогда не передаётся
только цветом**: у каждого есть иконка-символ и текст.

| Ключ | Метка | Значок | Тон |
|------|-------|--------|-----|
| `pending` | На проверке | ● | pending |
| `resubmitted` | Пересдача | ↻ | info |
| `done` | Выполнено | ✓ | done |
| `not_done` | Не выполнено | × | failed |
| `sent_back` | На пересдаче | ↻ | warning |
| `overdue` | Просрочено | ! | failed |
| `not_submitted` | Не сдано | – | muted |
| `in_progress` | В процессе | ◐ | info |

Правила:

- `submissionStatusKey(sub)` — статус одной (последней) сдачи: `pending`→`pending`/`resubmitted`
  (если есть `parentSubmissionId`), `done`→`done`, иначе `sent_back` (если `resubmitAllowed`) или `not_done`.
- `pairStatusKey(ctx, assignment, student)` — статус пары: если сдачи нет, то `overdue`
  (прошёл дедлайн) или `not_submitted`.
- `isPastDue` использует тот же порог, что приём решений у студента (`canSubmit`), поэтому
  «Просрочено» в админке совпадает с «Приём закрыт» у студента.
- «На пересдаче» = `not_done` + `resubmit_allowed = 1` — студент может загрузить после дедлайна.

Партиал `partials/status.ejs` рендерит бейдж статуса по ключу.

## 2.5. Разделы и маршруты

### Dashboard — `GET /admin`

`data.dashboard(ctx)`: карточки-счётчики (на проверке, студентов, заданий, просрочено),
сводка по ИБ (`ib.today / ib.solved`) и первые 8 работ очереди. Счётчики — ссылки на
соответствующие разделы.

### Работы студентов и проверка — `/admin/submissions`

- `GET /admin/submissions` — список работ. Фильтры (`normalizeWorkFilters`): вкладка
  (`all | review | checked | resubmissions`), поиск `q`, курс, группа, статус, период
  (`today|week|month`). `data.filterWorks` применяет фильтры; на вкладке «review» список
  идёт как очередь (старые первыми), иначе — новые первыми. `data.tabCounts` — счётчики вкладок.
- `GET /admin/submissions/:id` — **страница проверки** (шаблон `review`). Собирает:
  - файлы сдачи (`buildFiles`): для zip — список входов; изображения/PDF (диаграммные задания)
    отмечаются как media;
  - предпросмотр (`pickPreview`): по умолчанию открывается первый читаемый исходник в первом
    zip или первое изображение/PDF — чтобы преподаватель сразу видел код; текст подсвечивается
    (`highlightToHtml`);
  - историю сдач пары, позицию в очереди, кнопку «Следующая работа» (`data.nextInQueue`),
    условие задания (Markdown → HTML), флаг опоздания.
- `POST /admin/submissions/:id/review` — вердикт. `VERDICTS`: `done|not_done|resubmit`.
  Зовёт `reviewSubmission(...)`. Если в форме `next=1` — редирект на следующую работу очереди
  (или на вкладку review, если очередь пуста), иначе — назад на страницу работы.
- `GET /admin/submissions/:id/files/:index` — выдача файла. Изображения/PDF с `?inline=1`
  открываются в странице (`Content-Disposition: inline`, `X-Content-Type-Options: nosniff`),
  остальное — скачиванием (`res.download`).

### Задания — `/admin/assignments`

- `GET /admin/assignments` — список (`assignmentRows`). Фильтры: `q`, курс, тип
  (`group|individual`), состояние (`review|open|closed`). Для каждой строки — курс, цель
  (`describeTarget`: индивидуальное/групповое/все группы), статистика (назначено/сдано/
  проверено/на проверке), признак просрочки.
- `GET /admin/assignments/new` + `POST /admin/assignments` — создание. Форма парсится
  `parseAssignmentForm`; Markdown-тело пишется на диск (`createAssignmentWithContent`,
  `content/src/**`, индекс `content/SUMMARY.md`). Если тела нет — подставляется заготовка.
- `GET /admin/assignments/:id` — карточка задания (`assignmentDetail`): цель, статистика,
  построчно студенты со статусами, условие (Markdown→HTML).
- `GET /admin/assignments/:id/edit` + `POST .../edit` — правка заголовка, дедлайна и Markdown
  (`updateAssignmentWithContent`). Пустые заголовок/дедлайн — ошибка формы.

### Студенты — `/admin/students`

- `GET /admin/students` — список (`studentRows`), фильтры `q` и группа. По каждому: сколько
  назначено/выполнено/на проверке, последняя активность (учитывает и SQL-тренажёр).
- `GET /admin/students/:id` — профиль (`studentProfile`): задания со статусами, история сдач,
  сводка по SQL-тренажёру и по ИБ (`ibProgressForStudent`).

### Курсы — `/admin/courses`

- `GET /admin/courses` — список (`courseRows`): по курсу число заданий, уникальных студентов,
  работ на проверке.
- `GET /admin/courses/:id` — детали курса (`courseDetail`): сводка + строки заданий.

### SQL-тренажёр — `/admin/trainer`

- `GET /admin/trainer` — обзор (`trainerOverview`): по студентам сколько решено всего и по
  темам, последняя активность. Фильтры `q`, группа.
- `GET /admin/trainer/results` — матрица «студент × упражнение» (`trainerMatrix`),
  упражнения сгруппированы по темам.
- `GET /admin/trainer/mistakes` — частые ошибки (`trainerMistakes`, движок
  `src/lib/sql-mistakes.js`), фильтр по теме.
- `GET /admin/trainer/:studentId/:exerciseId` — попытки одного студента по упражнению:
  условие, список попыток, разбор ошибок (`buildReport`, `classifyAttempt`).

### Информационная безопасность — `/admin/ib`

- `GET /admin/ib` — результаты по заданиям ИБ в одном месте. `admin-data.js` собирает:
  - `ibResults` — задание №3 «Доступ к защищённой базе» (Цезарь): решено/не решено, ответы;
  - `ibConfigResults` — задание №4 (конфиги): прогресс автопроверки (пройдено/всего) и целевые
    значения студента;
  - `ibTerminalResults` — задание №5 (терминал-тренажёр): этапы, текущий этап, неверные ответы,
    активность из журнала команд;
  - `ibLabResults` — задания на общем движке `lab_task.py` (№6–№9: incident, ssh, logs, grep,
    а также perms/procs) с личными значениями и «сигналами» антисписывания.
  - Фильтры `q`, группа, `pick=<task>` — взвешенный случайный выбор студентов на устную
    проверку (`pickForOral`: чем больше сигналов списывания, тем выше вес).
- `GET /admin/ib/terminal/:id` — разбор задания №5 у одного студента (этапы, ответы, журнал,
  блок сигналов `integrityDetail`).
- `GET /admin/ib/lab/:task/:id` — то же для заданий №6–№9 (общий шаблон `ib-terminal.ejs`,
  функции `stageTaskResults`/`stageTaskDetail`). Для `logs` добавляется детальный разбор
  (ответы с доказательством и таймингом, детектор), для `grep` — по-командный разбор.

**Сигналы антисписывания** (`taskSignals`): ловушечные ответы, ответы без доказательства в
выводе команд, неверные контрольные вопросы, заблокированные вставки, «набор без клавиш»,
слишком быстрые решения сложных заданий. Для каждого считается `weight` — он же используется
при выборе на устную проверку.

### Итоговые контрольные — `/admin/exam` и `/admin/web-exam`

Подключаются как подмодули (`admin-exam.js`, `admin-web-exam.js`). Выдача/пересборка
вариантов, открытие/закрытие практики, оценивание отчётов и программ, предпросмотр
приложения студента (WEB), выгрузка zip. Подробности — в `docs/exam-ib-plan.md` и
`docs/web-exam-plan.md`.

### Страницы предметов-тренажёров

Каждый предмет с автопроверкой имеет свою админ-страницу с матрицей «студент × шаг»,
сигналами (вставки, уход со страницы, «набрано не руками»), карточкой студента с кодом и
журналом, кнопкой «Сбросить»:

- Emmet — `/admin/emmet` (`admin-emmet.js`)
- HTML — `/admin/html` (`admin-html.js`)
- CSS — `/admin/css` (`admin-css.js`)
- Начальный Python — `/admin/python-course` (`admin-python-course.js`)
- JavaScript — `/admin/js-course` (`admin-js-course.js`)

Пример (`admin-html.js`):

```js
router.get('/admin/html', (req, res) => {
  const group = course.HTML_GROUPS.includes(req.query.group) ? req.query.group : '';
  const filters = { q: (req.query.q||'').trim(), pick: req.query.pick === '1', group };
  render(res, 'html-course', 'html', { ..., o: courseAdmin.overview(filters), groups: course.HTML_GROUPS });
});
router.get('/admin/html/students/:id', ...);         // карточка студента
router.post('/admin/html/students/:id/reset', ...);  // сброс прогресса (db.resetHtmlStudent)
```

У матриц HTML и CSS есть **фильтр по группам** (`?group=`), валидируемый против
`HTML_GROUPS`/`CSS_GROUPS`.

### Доступ к темам (замки/дедлайны) — `/admin/locks`

Новая функция (2026-11-02). Позволяет преподавателю для темы предмета **по группе** или
**по конкретному студенту**: закрыть сейчас (`lock`), поставить жёсткий дедлайн (`deadline`,
после даты закрыто) или открыть одному студенту вопреки групповому замку (`allow`).

Слои:

- **Ядро** `src/lib/topic-locks.js`: `lockState(subject, topicKey, user)` →
  `{locked, forcedOpen, deadline, deadlineText, overdue, reason, note, scope}`;
  приоритет **студент > группа > обычное открытие тем**; TEST/`hasFullAccess` не блокируется;
  замок контрольной (`examLockFor`) — отдельный и важнее. Также `requireTopicOpen` — мидлвар.
- **Таблица** `topic_overrides` (`src/db/topic-locks.js`): `scope` (group|student),
  `target` (имя группы|id студента), `mode` (lock|deadline|allow), `deadline`, `note`.
  Дедлайны хранятся в UTC, показываются в +05.
- **Подключение предмета**: предмет вызывает `lockState` в своём `topicsForStudent` (ставит
  `adminLocked`/`deadline(Text)`/`overdue`/`lockReason`, форсит `theory/practiceOpen`) и
  отдаёт **423** на вход в закрытую тему. Сейчас подключены только **HTML и CSS**
  (роуты отдают 423, страница предмета показывает значок 🔒/дедлайна). Ожидают подключения:
  Emmet, SQL-тренажёр, Linux, курсы JS/Python, бейджи в сайдбаре и на карточках главной.
- **Админ-UI**: `src/routes/admin-locks.js` + `src/lib/admin-locks.js` + реестр
  `src/lib/subject-topics.js` + шаблон `src/views/admin/locks.ejs`. Страница также показывает
  **выполнение по темам** (кто из студентов группы завершил тему).

Маршруты:

- `GET /admin/locks?subject=&scope=&group=&student=` — страница. `pageData` строит список
  предметов, выбранный предмет, режим (группа/студент), темы с текущим override и статусом
  выполнения.
- `POST /admin/locks/set` — сохранить настройку. Валидация: `mode ∈ {lock,deadline,allow}`;
  `allow` — только для `scope=student`; `deadline` требует дату. Дата приходит из
  `datetime-local` (+05) и переводится в UTC (`fromLocalInput`). Пишет `db.setTopicOverride`.
- `POST /admin/locks/clear` — снять настройку (`db.clearTopicOverride`).

`redirectBack` возвращает на ту же вкладку (сохраняет subject/scope/group|student).

Реестр предметов (`subject-topics.js`): `SUBJECTS = {html, css}`, каждый даёт
`{key, title, groups, topics:[{key,title,total}], overview(group)}`; функции `list()`,
`get()`, `completion(subjectKey, group)` (Map тема → {total, done, students[]}),
`studentsOf(subjectKey)`. Растёт по мере подключения новых предметов к замкам.

### Настройки — `/admin/settings`

`GET /admin/settings` — сводные счётчики (студенты, задания, курсы). Шаблон `settings`.

### Глобальный поиск — `/admin/search`

`data.search(ctx, q)` ищет по студентам, заданиям, курсам и работам (по 5–8 на тип).
`GET /admin/search` — если `?format=json`, отдаёт JSON (для живого поиска в топбаре,
`data-live-search`); иначе рендерит страницу результатов. Поле поиска — в топбаре
(`partials/start.ejs`).

## 2.6. Хелперы вью (`admin-view.js`)

Доступны во всех админ-шаблонах через `res.locals`:

- `icon(name, class)` — inline-SVG по имени из `ICON_PATHS`.
- `formatDate`, `formatDateTime`, `relativeTime` (с русским склонением), `formatSize`.
- `initials(name)`, `shortName(name)` («Иванов И.» для плотных таблиц).
- `queryString(params, overrides)` — сборка query-строки с отбрасыванием пустых значений
  (для сохранения фильтров в ссылках).
- `plural(n, one, few, many)` — русское склонение.

## 2.7. Каркас страницы (layout)

Общего layout-движка нет — каждый admin-шаблон включает партиалы начала/конца:

- `partials/start.ejs` — `<head>` (тема из `localStorage` до загрузки CSS, шрифты,
  `admin.css`, `admin.js` с `defer`), топбар (меню, лого, заголовок раздела, глобальный
  поиск, переключатель темы, «колокольчик» с `reviewCount`, меню пользователя), открывает
  `.a-shell` → сайдбар + `.a-main`, выводит `flash`.
- `partials/end.ejs` — закрывает `main`/`shell`, диалог подтверждения (`<dialog>` для
  опасных действий, управляется `admin.js`).
- `partials/status.ejs` — бейдж статуса.
- `partials/empty.ejs` — пустое состояние списков.

Шаблон страницы: `<%- include('partials/start') %> … <%- include('partials/end') %>`.

## 2.8. Клиентский JS админки (`public/js/admin.js`)

Отвечает за: мобильное меню (сайдбар + backdrop), выпадающее меню пользователя,
переключатель темы, живой глобальный поиск (fetch `?format=json`), закрытие `flash`,
диалог подтверждения опасных действий (кнопки `data-confirm`), автосабмит фильтров
(`data-autosubmit`). Админские страницы темизируются независимо от студенческих.

## 2.9. Связь с данными

Админка читает/пишет те же таблицы, что и студенческая часть, через `src/db` (см.
[04-данные.md](04-данные.md)). Ключевые функции, которые зовёт админка:
`getUsers`, `getCourses`, `getAssignments`, `getSubmissions`, `reviewSubmission`,
`getSubmissionById`, `createAssignment`, `updateAssignmentMeta`, `getSqlExercises`,
`getAllSqlAttempts`, функции ИБ (`getCaesarSecrets`, `getConfigTasks`, `getTerminalTasks`,
`getLabTasks`, журналы, guard-события), `setTopicOverride`/`clearTopicOverride`/
`listTopicOverrides`, и `reset*Student` для сброса прогресса предметов.
