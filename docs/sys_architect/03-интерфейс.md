# 03. Архитектура интерфейса

Интерфейс — серверный рендеринг (EJS) плюс обычный CSS/JS в `public/`. Две независимые
ветви оформления: **студенческая** (`theme.css` + `components.css`, светлая/тёмная тема) и
**админская** (`admin.css`, самодостаточна).

## 3.1. Шаблоны EJS (`src/views/`)

### Студенческая ветвь

Корневые страницы и предметы:

- `login.ejs`, `change-password.ejs`, `403.ejs`, `404.ejs`.
- `student-home.ejs` — главная студента (карточки предметов).
- `subject-sql.ejs`, `subject-ib.ejs`, `subject-language.ejs`, `subject-course.ejs` —
  страницы предметов разных типов.
- `assignment-view.ejs`, `bank-exercise.ejs`, `course-theory.ejs` — задание, банк, теория.
- `exam-locked.ejs`, `topic-locked.ejs` — страницы-заглушки 423 (закрыто контрольной /
  админским замком темы).
- Каталоги предметов-тренажёров: `emmet/`, `html-course/`, `css-course/`, `linux-course/`,
  `python-course/`, `js-course/`, `trainer/` (SQL), `exam/`, `web-exam/`,
  `ib-task.ejs`/`ib-theory.ejs`/`ib-detector.ejs`.

Общие партиалы (`src/views/partials/`):

- `head.ejs` — общий `<head>`: тема по умолчанию (dark) ставится **до** загрузки CSS, чтобы
  не было вспышки; подключает `theme.css` + `components.css` и шрифты.
- `header.ejs`, `sidebar.ejs`, `scripts.ejs` — шапка, боковая навигация, подключение скриптов.
- `back-btn.ejs` — общая кнопка «назад» (`.back-btn`, с `back-btn-sm` для сайдбара).
- `status-label.ejs` — бейдж статуса на студенческой стороне.

### Админская ветвь (`src/views/admin/`)

Отдельный набор шаблонов (см. [02](02-админ-панель.md)) со своими партиалами
`admin/partials/` (`start.ejs`, `end.ejs`, `sidebar.ejs`, `status.ejs`, `empty.ejs`,
`ib-signals.ejs`, `ib-oral.ejs`). Админка **не** подключает студенческие стили.

### Приём каркаса

Общего layout-движка нет. Каждая страница включает партиалы начала/конца:
`<%- include('partials/head') %> … <%- include('partials/scripts') %>` (студент) или
`<%- include('partials/start') %> … <%- include('partials/end') %>` (админ). Локали в
шаблоны приходят из `res.locals` (общие) и из объекта, переданного в `res.render`.

## 3.2. Общие UI-компоненты (договорённости)

Чтобы интерфейс был единым, в проекте зафиксированы общие компоненты — новые страницы
обязаны их переиспользовать, а не изобретать свои:

- **Кнопки темы/практики** — `.topic-btn` из `components.css`: `topic-btn-theory`
  («📖 Теория»), `topic-btn-practice` («🧪 Практика» + счётчик `solved/total`, модификаторы
  `is-done`/`is-locked`), `topic-btn-none`, `topic-btn-lg`. Эталон разметки —
  `src/views/subject-sql.ejs` и `src/views/html-course/index.ejs`.
- **Кнопки «назад»** — общий пилюльный `partials/back-btn.ejs` (`.back-btn`); на страницах
  Emmet/HTML-практики — `.home-link` в стиле «Тетрадь»; в админке — `.a-btn-back`.
- **Бейджи статусов** — через `STATUS_META` (единые иконка+текст, не «только цвет»).
- Значок/дедлайн замка темы: `topic-lock-badge` / `topic-deadline-badge` (светлая и тёмная).

## 3.3. Статика `public/`

```
public/
  css/     admin.css, theme.css, components.css, code-theme.css,
           css-course.css, html-boxes.css, linux-course.css
  js/      admin.js, theme-toggle.js, sidebar.js, tabs.js, typing-monitor.js,
           sql-trainer.js, css-check.js, css-course.js, html-examples.js,
           css-examples.js, linux-fs.js, linux-course.js,
           python-course.js, python-worker.js, python-course-theory.js,
           js-course.js, js-worker.js, js-runner.js, js-course-theory.js,
           code-editor.js, editor-preview.js, exam*.js, web-runner.js,
           web-exam.js, ib-guard.js, ib-detector.js
  vendor/  CodeMirror 5, Pyodide (+ sqlite3), шрифты, сборка Emmet/HTML-практики
  img/     logo.png (исходник), logo-mark.png, favicon.png, apple-touch-icon.png
```

- Всё вендорное — **локально** (в git), не с CDN и не из Google Fonts: в аудиториях нет
  интернета. Тест проверяет, что ни одна страница/скрипт/стиль/терминал не ссылается на
  внешний хост.
- Шрифты: Open Sans, JetBrains Mono (терминал ИБ), Oswald + Montserrat (страница Emmet),
  собраны `scripts/vendor/fonts.py` из @fontsource (кириллица + латиница).
- Клиентские сборки Emmet/HTML-практики — из исходников `emmet/` через
  `scripts/vendor/emmet.sh` в `public/vendor/` (на сервере сборки нет).

## 3.4. Темизация

Две палитры:

- **Тёмная (по умолчанию)** — Marple (`docs/color-marple.md`). Карточки залиты цветами
  палитры, кнопки-пилюли, фон с размытыми цветными «пятнами» на двух фиксированных слоях
  (`body::before/::after` в `theme.css`) с очень медленной анимацией «пульса» (выключается
  при `prefers-reduced-motion`).
- **Светлая** — «Тетрадь» из тренажёра Emmet (`docs/color-tetrad.md`): тёплая бумага,
  чернильный текст, деревянный акцент, блокнотная сетка в редакторах кода.

Механика переключения:

- Тема по умолчанию (`dark`) ставится атрибутом на `<html>` **до** загрузки CSS (в
  `partials/head.ejs` и в админском `start.ejs`), чтобы не было вспышки.
- Выбор пользователя хранится в `localStorage` (`theme`), применяется тем же inline-скриптом
  и переключается кнопкой (`theme-toggle.js` на студенте, `data-theme-toggle` в админке).
- Везде, где печатают код (CodeMirror, `.sql-console`, терминал ИБ) — слабая блокнотная
  сетка с размером клетки в высоту строки (`--grid-size`).

Логотип: `logo.png` — исходник; `logo-mark.png` рисуется CSS-маской в цвет текста;
`favicon.png`/`apple-touch-icon.png` вырезаны из него.

## 3.5. Клиентские движки (где они и что делают)

Весь «тяжёлый» код студент выполняет **в браузере** — сервер студенческий код не исполняет,
а лишь перепроверяет результат:

- **SQL-тренажёр** — редактор CodeMirror; запрос уходит на сервер, там выполняется в
  песочнице (`src/lib/sql-sandbox.js`) и сверяется (`sql-trainer.js`).
- **HTML/CSS/Emmet-практика** — CodeMirror (+ Emmet-движок); рендер студентского и эталонного
  результата в изолированных iframe; сверка в браузере (`css-check.js`), затем жёсткая
  перепроверка на сервере (`src/lib/emmet/validate.js`, `src/lib/css-course/cascade.js`).
- **Python-курс и контрольная** — Pyodide в Web Worker (`python-worker.js`): прогон тестов в
  браузере, сервер сверяет вывод (`src/lib/python-basics-check.js`) и правила кода (ast).
- **JavaScript-курс** — Web Worker (`js-worker.js` + `js-runner.js`): прогон тестов, фиктивные
  `fetch`/таймеры; правила кода проверяет `src/lib/js-course/rules.js`.
- **Linux-тренажёр** — виртуальная ФС и интерпретатор команд в браузере (`linux-fs.js`,
  UMD — работает и в Node); сервер переигрывает журнал команд (`src/lib/linux-course/validate.js`).
- **WEB-контрольная** — приложение студента в песочничном iframe без `allow-same-origin`
  (`web-runner.js`), со своим in-memory `localStorage`.
- **Редакторные задания** — CodeMirror (`code-editor.js`), запуск `main.py` через Pyodide,
  автосохранение черновиков.

### Контроль ввода и антисписывание

- `typing-monitor.js` + `src/lib/typing-check.js` — «набрано руками»: откуда пришли символы
  (клавиатура, Emmet, автовставка, undo) и ритм; флаги `chunk`/`autotype`/`untyped`/`refCopy`
  попадают в сигналы админки (не блокируют решение).
- `ib-guard.js` — для заданий ИБ: запрет вставки в терминал/редактор, ловушечный абзац к
  скопированному, события в `ib_guard_events`.

## 3.6. Адаптивность

Проверено на 390/600/768/1024/1280/1440px — ни одна страница не шире экрана. Мобильный блок
в конце `components.css`: кнопки шапки превращаются в иконки, `.content { min-width: 0 }`,
блоки кода и таблицы скроллятся внутри себя, меньше отступы; ≤1100px оглавление задания
скрыто, таблицы скроллятся, админские списки превращаются в карточки; ≤900px ряды тем
переносят кнопки. CSS-практика на телефоне рисует одноразмерные задачи в ширину экрана.
Новые страницы не должны быть шире экрана 390px.

## 3.7. Доступность

- Статус — всегда иконка + текст (не только цвет).
- Ссылка «К содержимому» (`a-skip`), `aria-*` на меню/выпадашках/диалогах, `role="status"`
  у flash-сообщений.
