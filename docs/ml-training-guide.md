# Как обучить свою умную модель: датасет и организация обучения

Практическая памятка-ориентир. Записано 2026-11-11. Это обзорный гайд, а не пошаговый рецепт под конкретную
задачу — но даёт верную «карту местности» и минимальный путь до первого результата.

## 0. Трезвость в начале

Модель «уровня большого ассистента» с нуля в одиночку **не обучают**: это сотни миллионов долларов, тысячи
GPU на месяцы и большая команда. И это не нужно. ~95% практической пользы достигается **не предобучением с
нуля, а дообучением открытой базовой модели**.

Лестница по стоимости и сложности (начинать сверху):

1. **Промптинг + RAG** — почти бесплатно, часто решает задачу без всякого обучения.
2. **LoRA / QLoRA-дообучение** — от одной GPU, десятки $. Учим стилю, домену, формату ответа.
3. **Полный fine-tune** — дороже (десятки GPU-часов), когда LoRA не хватает.
4. **Предобучение с нуля** — почти никогда не нужно; только свой язык/домен + очень много данных и денег.

Базовые открытые модели, с которых стоит стартовать: **Qwen, Llama, Mistral, Gemma**. Берём instruct-версию
и дообучаем её.

## 1. Датасет — это 80% успеха

Качество данных важнее их количества и важнее выбора модели.

- **Формат.** Для дообучения — инструкции:
  - SFT: пары `{запрос → ответ}`;
  - preference / DPO: триплеты `{запрос, хороший ответ, плохой ответ}`.
  - Код удобно хранить в чат-формате с системным промптом.
- **Количество.** Для узкой задачи хватает **1–10 тысяч** отличных примеров. Лучше 2 000 вылизанных, чем
  200 000 мусорных.
- **Источники.** Свои логи и задачи; открытые датасеты (проверяй лицензии!); синтетика — генерация примеров
  более сильной моделью с последующей **ручной проверкой**. Для кода — репозитории с разрешающей лицензией.
- **Чистка (решает всё):**
  - **дедупликация** — почти-дубли раздувают датасет и ведут к переобучению;
  - **фильтр качества** — убрать битое, обрезанное, с ошибками;
  - **деконтаминация** — убедиться, что примеры из тест-сета не попали в обучение (иначе метрики врут);
  - **единый формат и нормализация**;
  - **проверка правильности ответов** — для кода прогонять тесты (эталон обязан проходить, как чекер
    эталонов в этом проекте).
- **Разнообразие.** Покрыть разные формулировки и крайние случаи, а не 1000 вариаций одного.

## 2. Организация обучения

- **Инструменты:** `Axolotl`, HuggingFace `TRL`, `Unsloth` (быстро и дёшево на одной GPU), `llama-factory` —
  закрывают 90% рутины.
- **Этапы:**
  1. **SFT** — научить формату и задаче.
  2. **DPO / preference-тюнинг** — научить предпочитать ответы получше (именно так модели делают «приятными»
     в общении; это второй этап, не первый).
- **Железо:** QLoRA на модели 7–8B влезает в одну GPU с ~24 ГБ (4-битная загрузка). Инференс —
  `vLLM` / `Ollama` / `llama.cpp`.
- **Гиперпараметры (старт):** LoRA rank 16–32, learning rate ~1e-4 для LoRA, 1–3 эпохи. Много эпох →
  переобучение.

## 3. Оценка (без неё легко обмануть себя)

- Держать **отдельный тест-сет**, которого модель не видела.
- Для кода — автоматические проверки: прогон тестов на сгенерированном коде (pass/fail).
- Для «качества ответа» — набор эталонных кейсов + сравнение «до/после»; можно LLM-as-judge, но
  перепроверять руками.
- Следить за **регрессиями**: дообучение под одну задачу часто ломает другие навыки.

## 4. Минимальный путь (что сделать сейчас)

1. Взять `Qwen2.5-7B-Instruct` (или `Llama-3.1-8B-Instruct`).
2. Собрать 1–3 тыс. вылизанных примеров своей задачи в чат-формате + **отложить тест-сет**.
3. Прогнать QLoRA в Unsloth на одной GPU (есть готовые ноутбуки).
4. Померить на тест-сете, сравнить с базовой моделью, **итерировать по данным**.

## Главная мысль

**Итерируешь по данным, а не по модели.** Большинство улучшений приходит из чистки и расширения датасета,
а не из смены архитектуры или гиперпараметров.
