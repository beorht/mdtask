# Журнал действий итоговой контрольной

Как устроены логи итоговой контрольной группы IB (`/exam/ib-final-1`). Код: `src/lib/exam/log.js`,
`src/routes/exam.js`, `public/js/exam.js`, `src/lib/exam/admin.js`, `src/routes/admin-exam.js`.
План контрольной — `docs/exam-ib-plan.md`.

## Где хранятся логи

| Место | Что там | Для чего |
|---|---|---|
| `data/exam/<контрольная>/logs/<студент>.jsonl` | **Основной журнал**: одно событие на строку, у каждого студента свой файл | Полная история работы |
| `data/exam/<контрольная>/snapshots/<студент>/` | Полный код программы при каждом сохранении, запуске, проверке и отправке, например `00065-3.3-run.py` (`<seq>-<задание>-<вид>.py`, вид: `draft`, `run`, `check`, `submit`) | Видно, как менялся код |
| Таблица `exam_events` в базе | Короткая копия каждого события (первые 300 символов подробностей) | Быстрые таблицы в админке |

Файл журнала только дописывается (`appendFileSync`), старые строки не меняются. Журналы разных
студентов не смешиваются, поэтому работу каждого можно восстановить по шагам. Node обрабатывает
запросы по одному, поэтому строки не перемешиваются.

## Как выглядит событие

```json
{"ts":"2026-10-20T04:48:35.585Z","seq":1,"student":"st-ib-601","exam":"ib-final-1",
 "stage":null,"task":null,"type":"session_start","data":{"userAgent":"..."},
 "session":"fb259919","ip":"::ffff:192.168.102.172"}
```

| Поле | Значение |
|---|---|
| `ts` | Время сервера (UTC) |
| `seq` | Номер события у студента: 1, 2, 3… без пропусков. После перезапуска сервера нумерация продолжается: последний номер читается из конца файла |
| `stage` / `task` | Где студент находился: этап (1–6) и задание (например `3.3`) |
| `type` | Что произошло (списки ниже) |
| `data` | Подробности события |
| `session` | Хэш сессии из 8 символов (SHA-256), а не сама сессия. По нему видно, что студент заходил заново |
| `ip` | Адрес компьютера |
| `clientTs` | Время браузера (только у событий из браузера) |
| `server` / `origSeq` | Появились после объединения с архивом временного сервера (`scripts/exam/merge-archive.js`): откуда событие (`here` / `archive`) и какой номер у него был там |

Ограничения размера:

- строка внутри события — до 4000 символов (длиннее обрезается с «…»), массив — до 200 элементов;
- всё событие — до 20 000 символов; если больше, вместо подробностей записывается `{"truncated": true}`.

Если запись в журнал не удалась, сервер пишет ошибку в консоль (`exam log: …`), а действие
студента всё равно выполняется: из-за лога работа не теряется.

## Откуда берутся события

### 1. Сервер

Сервер записывает всё, что проходит через него. Подделать эти события со страницы нельзя.

| Тип | Когда |
|---|---|
| `session_start` | Вход в контрольную (с `userAgent`) |
| `page_view` | Открытие каждой страницы контрольной |
| `device` | Первый вход с компьютера: IP, MAC, имя ПК аудитории |
| `device_change` | Студент перешёл на другой компьютер |
| `device_blocked` | Отказ: компьютер не из аудитории (режим `block`) |
| `terminal_login`, `terminal_logout` | Вход в терминал и выход; неверный логин записывается с тем, что было введено |
| `terminal_cmd` | **Каждая команда терминала.** Терминал работает через сервер экзамена, поэтому записываются команда (до 2000 символов), приглашение, режим и вывод (до 3000 символов). Скрытый ввод, например пароль, записывается как «(скрытый ввод)», очистка экрана — «(clear)» |
| `flag_answer` | Ответ на вопрос этапов 1, 2, 5: что введено и верно ли. Повторный ответ на решённое задание отмечается `already` |
| `draft_save` | Сохранение черновика кода (+ снимок `draft`) |
| `code_run` | Запуск программы (+ снимок `run`) |
| `code_run_result` | Что программа вывела при запуске |
| `code_run_denied` | Отказ в запуске: кончились 4 запуска у программы с ошибкой (`limit`) или в редакторе алгоритма (3.1–3.2) запускают код, похожий на программу с ошибкой из другого задания, чтобы обойти лимит запусков (`bug_program`) |
| `code_check` | Проверка тестами: сколько тестов пройдено, найдены ли запрещённые конструкции, решено ли (+ снимок `check`) |
| `code_reset` | Сброс кода к исходному |
| `bug_submit` | Отправка программы с ошибкой (+ снимок `submit`) |
| `sql_run`, `sql_check` | SQL: запрос и результат, проверка ответа |
| `report_save`, `report_submit` | Сохранение и отправка отчёта об инциденте |
| `blocked_action` | Попытка действия после закрытия контрольной или по закрытому заданию |

### 2. Браузер

Это то, что видно только на странице студента (`public/js/exam.js`). Браузер собирает события в
очередь и отправляет на `POST /exam/<id>/log`:

- раз в 10 секунд;
- когда в очереди набралось 20 событий;
- при уходе со страницы или скрытии вкладки (через `navigator.sendBeacon`).

| Тип | Что значит |
|---|---|
| `visibility` | Вкладка скрыта или снова видна (`state: hidden / visible`) |
| `blur`, `focus` | Ушёл в другое окно, вернулся. Щелчок по окну терминала уходом не считается |
| `page_leave` | Закрыл или покинул страницу |
| `paste` | Вставка из буфера на странице: число символов и строк, куда вставлено, сам текст (до 2000 символов) |
| `terminal_paste` | То же, но вставка в терминал |
| `copy` | Копирование: сколько символов и откуда |
| `idle` | Бездействие дольше 3 минут; записывается, когда студент снова начал работать (клавиатура, мышь, прокрутка) |
| `timer_end` | Время на странице закончилось |
| `device_info` | Экран, платформа и т. п., один раз за вкладку |

Сервер принимает только типы из этого списка (`CLIENT_EVENTS` в `src/routes/exam.js`), не больше
50 событий за раз, и проверяет `stage` (1–6) и `task` (вид `N.N`). Остальное отбрасывается.

## Что видно в админке

Страница студента: `/admin/exam/ib-final-1/students/<id>`.

- **Карта действий** — полоса по времени. Цвет показывает этап, метки — ответы (верно / неверно),
  запуски, вставки (больше 200 символов выделены), уходы со страницы, команды терминала, отказы.
  При наведении видны время и действие.
- **Путь по заданиям** — порядок заданий, время и число действий на каждом, частые переходы
  между заданиями.
- **Устройства** — с каких компьютеров и IP работал студент, были ли отказы и несовпадение MAC.
- **Журнал действий** — все события по порядку `seq`: у команды можно раскрыть вывод, у вставки —
  вставленный текст, снимок кода открывается по ссылке
  (`…/students/<id>/snapshot/<имя>`).
- **Счётчики** — число событий, команд, вставок, уходов и общее время бездействия.
- Журнал скачивается целиком: `…/students/<id>/log.jsonl`.

В общей таблице результатов (`/admin/exam`) есть столбец «ПК» и предупреждения об устройствах,
а экспорт `…/export.csv` содержит число событий у каждого студента.

## Обработка после контрольной

| Скрипт | Что делает |
|---|---|
| `node scripts/exam/recheck.js` | Заново запускает сохранённый код на тестах. Находит случаи «сервер записал решено, а код тесты не проходит» (подмена вывода) и заполняет результаты программ, отправленных без прогона. Выполняет код студентов на этом компьютере |
| `python3 scripts/exam/analyze.py` | По журналам считает время на заданиях и ищет подозрительное: большие вставки, решение без запусков, частые уходы, одинаковый код, одинаковые последовательности команд, ответы почти одновременно. Пишет `summary.csv`, `students.csv`, `flags.txt`, `tasks.txt` |
| `node scripts/exam/report.js` | Собирает отчёты по группе и по каждому студенту в `results_exam/` |
| `node scripts/exam/merge-archive.js` | Объединяет журналы двух серверов: события по времени, `seq` заново 1..N, снимки переименовываются, `exam_events` строится заново |

## Слабые места

1. **События из браузера можно подделать или потерять.** Студент, который разбирается в
   браузере, может их не отправлять или отправить ложные. Если вкладку закрыли до отправки
   очереди, последние события могут пропасть. Ответы, команды, запуски и отправки пишет сервер,
   и им можно доверять.
2. **Бездействие без возвращения не записывается.** Если студент перестал работать и больше
   ничего не трогал, события `idle` не будет. Пауза видна только как промежуток на карте.
3. **Номера `seq` хранятся в памяти одного процесса.** Если запустить два экземпляра сервера на
   одни и те же данные, номера пересекутся. Сейчас работает один процесс, так что это не мешает.
4. **В журналах лежат личные данные:** IP, вставленный текст, вывод терминала. Папка `data/` в
   git не попадает, но копии журналов, например в архиве, нужно хранить так же осторожно.
