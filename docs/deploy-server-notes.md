Эти условия задал пользователь 28.10.2026. Держать в силе.

## Как устроен прод

- Проект развёрнут на **стороннем сервере**, к которому **нет доступа по SSH** из этой среды.
  Любой скрипт обновления пользователь запускает **сам, на сервере**.
- Новую версию пользователь **заливает на сервер архивом** (`.tar.gz`, верхняя папка `mdtask`,
  собирается здесь) и **сам его распаковывает** на сервере.
- Проект работает как **systemd-демон**, имя службы — **`mdtask`**.
- Путь к проекту на сервере — **`/root/mdtask`**.
- Порт по умолчанию `42521` (`/health`). Реальный порт/окружение заданы в unit-файле службы.

## Триггер «дай скрипт обновы»

Когда пользователь пишет **«дай скрипт обновы»** (или по смыслу то же) — выдать **bash-скрипт,
который выполняется на сервере** и обновляет `/root/mdtask` из распакованного архива новой версии:

1. Принимает путь к **распакованной** папке новой версии (или к архиву — тогда сам распаковывает
   во временный каталог). Верхняя папка архива — `mdtask`.
2. **Заменяет только код** новой версии поверх старого `/root/mdtask`:
   обновляет `src/`, `ib/`, `public/`, `content/`, `scripts/`, `views`, `index.js`, `package.json`
   и прочие файлы кода.
3. **НЕ трогает данные и локальное окружение сервера**: `data/`, `uploads/`, `backups/`,
   `results_exam/`, `archive/`, `node_modules/`, `.env`, `data/session-secret`.
4. Перед заменой — **резервная копия заменяемых файлов** в
   `/root/mdtask/backups/code-before-update-<дата-время>.tar.gz` (для отката).
5. Копирует только изменившиеся/новые файлы (сравнение по содержимому), показывает список.
6. Если менялись зависимости (`package.json`) — подсказать `npm ci`/`npm install` при необходимости.
7. **Перезапуск демона**: `systemctl restart mdtask`, затем проверка `curl -fsS localhost:42521/health`.
8. Безопасность: **не обновлять во время идущей контрольной** (как `scripts/deploy/update-server.sh`:
   проверка окна экзамена в `data/mdtask.db`, флаг `--force` для обхода); флаг `--dry-run` для показа
   изменений без применения.

За основу брать `scripts/deploy/update-server.sh`, но адаптировать: **без ssh/rsync** (всё локально
на сервере), служба через `systemctl`, путь `/root/mdtask`, источник — распакованный архив рядом.

**Скрипт уже написан: `scripts/deploy/update-mdtask.sh`** (создан и проверен 28.10.2026). Он входит
в архив кода и сам попадает на сервер в `/root/mdtask/scripts/deploy/update-mdtask.sh`. Запуск на
сервере: `bash update-mdtask.sh ИСТОЧНИК [ЦЕЛЬ] [--dry-run] [--yes] [--no-restart] [--force]`.
По триггеру «дай скрипт обновы» править/обновлять именно этот файл.

Скрипт **сохранять сразу в файл** (`scripts/deploy/update-mdtask.sh`), а не выдавать текстом —
так просил пользователь 28.10.2026.

## Сборка архива новой версии (на этой машине)

Архив **без данных** (для обновления кода):
```bash
cd /home/thinklinux/Projects
tar czf mdtask-$(date +%Y-%m-%d-%H%M).tar.gz \
  --exclude='node_modules' --exclude='.git' \
  --exclude='mdtask/data' --exclude='mdtask/uploads' --exclude='mdtask/backups' \
  --exclude='mdtask/results_exam' --exclude='mdtask/archive' \
  mdtask
```

Полный снимок **с данными** (бэкап/перенос всей системы) — дополнительно включить `data/`,
`uploads/`; исключать только `archive/`, `node_modules`, `backups/`, `.git`. Содержит реальные
персональные данные студентов — только локально и по защищённому каналу.
