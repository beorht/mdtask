# Итоговая контрольная работа группы IB — план

**Статус:** план, не утверждён. Код не писался, реализация начнётся после команды «давай».

**История правок:**
- 2026-10-19 — первая версия.
- 2026-10-19 — правки по ответам преподавателя:
  - 3 темы вариантов;
  - алгоритмы: линейный поиск, сортировка выбором, пузырьковая сортировка;
  - 5 программ с ошибками на 30–70 строк;
  - этап SSH убран;
  - шифр Цезаря вернулся отдельным этапом;
  - баллы объявляются после проверки преподавателем.
- 2026-10-19 — программы с ошибками:
  - не больше 4 запусков;
  - одна отправка на проверку;
  - после отправки или после 4-го запуска задание блокируется.

## 1. Цель и формат

Контрольная проверяет, как студенты группы IB применяют на практике то, что прошли:

| Навык | Что уже было |
|---|---|
| Linux | задания ИБ №3 «Цезарь», №4 «конфиги», №5 «терминал», №6 «инцидент» |
| Программирование на Python | задачи на словари, «Учёт библиотеки» |
| Базы данных | SQL-тренажёр, практикум «Ключи и JOIN» |

- **Формат:** одно многоэтапное практическое задание со сквозным сценарием.
- **Кто пишет:** вся группа IB (18 студентов).
- **Длительность:** 2 пары подряд, около 160 минут. Окно открытия и закрытия задаёт преподаватель в админке.
- **Язык:** весь интерфейс и тексты на русском.

## 2. Сценарий и темы вариантов

Студент — новый администратор фирмы. На сервере фирмы сбой и следы взлома, прежний администратор уволился. Нужно:
- разобраться в сервере и журналах;
- обработать данные программами и исправить сломанные программы;
- оценить ущерб в базе и восстановить её;
- открыть зашифрованный файл;
- написать отчёт.

Три темы, у каждой своя база, журналы, данные и программы:

| Тема | Сервер | Данные в журналах, БД и программах |
|---|---|---|
| **Магазин** | интернет-магазин | заказы, товары, клиенты, суммы |
| **Библиотека** | электронный каталог | книги, читатели, выдачи, сроки возврата |
| **Поликлиника** | запись к врачу | пациенты, врачи, приёмы, время |

## 3. Как распределяются варианты

Цель — чтобы соседи и вообще любые два студента не получили одинаковое задание.

**Алгоритмы (этап 3.1–3.2).** Каждый студент получает 2 алгоритма из 3, то есть одну из трёх пар:
- линейный поиск + сортировка выбором;
- линейный поиск + пузырьковая сортировка;
- сортировка выбором + пузырьковая сортировка.

**Формулировки.** У каждого алгоритма в каждой теме 2 формулировки (а, б): ищут или сортируют по разным полям. Вместе с темами и парами это 3 × 3 × 2 = **18 уникальных сочетаний**, ровно по одному на студента.

**Программы с ошибками (этап 3.3–3.7).**
- 5 типов ошибок, на каждый тип в каждой теме по 2 версии программы.
- Всего 3 × 5 × 2 = **30 программ**. Одну программу получают не больше 3 студентов, и рассаживаются они не рядом.

**Данные.** Генерируются под каждого студента:
- журналы;
- база;
- файлы для алгоритмов (числа, имена, время);
- сдвиг Цезаря.

Даже при одинаковой формулировке ответы у всех разные.

Распределение задаётся по списку студентов скриптом `scripts/exam/assign-variants.js`. Перед контрольной его можно посмотреть и поправить в админке.

| 3 | Программирование: 2 алгоритма + 5 программ с ошибками | 7 заданий | автоматически, скрытые тесты | 35 (2 × 7.5 + 5 × 4) |
| 4 | SQL: ущерб и восстановление | 3–4 запроса | автоматически | 20 |

**Всего 100 баллов.** Оценка: 86+ «5», 71–85 «4», 56–70 «3», меньше 56 «2».

### Этап 1. Разведка в Linux
Терминал-песочница, как в заданиях №4–№6. Студент находит в `/srv` и `/etc`:
- конфиг приложения;
- путь к базе данных;
- порт сервиса;
- владельца и права ключевых файлов.

Команды: `ls -la`, `cd`, `find`, `grep`, `cat`.

### Этап 2. Поиск проблемы в журналах сервера (упрощённый)
Журналы короткие (100–200 строк) и в одном простом формате, одна запись — одна строка:

```
2026-10-28 02:14:07 192.168.4.17 LOGIN_FAIL admin
2026-10-28 02:14:09 192.168.4.17 LOGIN_OK admin
2026-10-28 02:15:30 192.168.4.17 DELETE order=1043
```

Вопросы:
1. С какого IP перебирали пароли?
2. Во сколько злоумышленник вошёл и под какой учёткой?
3. Сколько записей он изменил или удалил?

Команды: `grep`, `wc -l`, `sort`, `uniq -c`, `head`, `tail`.

### Этап 3. Программирование
Редактор Python на странице, как в курсе pybasics. Код выполняется в браузере студента (Pyodide), сервер сравнивает только вывод. Задания внутри этапа решаются в любом порядке.

#### 3.1–3.2. Алгоритмы (2 из 3)

**Общие правила для всех алгоритмов:**
- **Данные.** Записи в простом формате, как в журнале этапа 2, только короче: одна запись — одна строка из 2–3 полей через пробел. Первая строка — число записей N (50–500), дальше N строк, для поиска ещё строка запроса. Данные читаются через `input()`.
- **Только своя реализация.** Алгоритм пишется вручную. Встроенные `sorted()`, `.sort()`, `min()`, `max()`, `.index()`, `.find()`, `.count()` и проверка `x in список` запрещены.
  - Сервер проверяет это по коду: разбирает его модулем `ast` и не выполняет.
  - Если запрещённое найдено, задание не засчитывается, а студент видит, какая функция запрещена.
- **Подтверждение алгоритма.** Кроме результата программа выводит счётчик: число сравнений, обменов или проходов. Такой счётчик совпадает с ожидаемым только у нужного алгоритма. Значит, вместо сортировки выбором нельзя сдать пузырьковую, и наоборот.
- **Условие** — 3–5 предложений: что делает алгоритм, что на входе, что вывести, плюс таблица примеров «ввод → вывод». Без кода, как во всех заданиях.

**Линейный поиск** (формулировки а/б по темам):

| Тема | а | б |
|---|---|---|
| Магазин | первый заказ клиента X: номер строки и число сравнений, либо «не найдено» | все заказы дороже суммы S: номера строк и их количество |
| Библиотека | первая выдача книги X: номер строки и число сравнений | все выдачи читателю X: номера строк и количество |
| Поликлиника | первый приём у врача X после времени T | все приёмы пациента X: номера строк и количество |

*Как объяснено студенту:* «Линейный поиск просматривает записи по очереди, с первой до последней, и сравнивает каждую с искомым значением. Он останавливается, когда нашёл (если нужна первая), или доходит до конца (если нужны все)».

**Сортировка выбором:**

| Тема | а | б |
|---|---|---|
| Магазин | заказы по сумме по убыванию | товары по цене по возрастанию |
| Библиотека | книги по числу выдач по убыванию | читатели по фамилии по алфавиту |
| Поликлиника | приёмы по времени по возрастанию | врачи по числу пациентов по убыванию |

Вывод: отсортированные записи и число обменов.

*Как объяснено студенту:* «На каждом шаге находим наименьший (или наибольший) элемент среди ещё не отсортированных и меняем его местами с первым неотсортированным. После шага i первые i элементов стоят на своих местах».

**Пузырьковая сортировка:** те же пары тем, но поля отличаются от сортировки выбором, например магазин: а — клиенты по числу заказов, б — заказы по дате.

Вывод: отсортированные записи и число проходов. Если за проход не было обменов, сортировка останавливается раньше.

*Как объяснено студенту:* «Идём по списку и сравниваем соседние элементы. Если они стоят в неправильном порядке, меняем их местами. За один проход самый большой элемент „всплывает“ в конец. Проходы повторяются, пока за проход нет ни одного обмена».

**Проверка:** 6 тестов, 2 из них открытые (видно ожидаемый вывод). Среди тестов есть пустой поиск, одинаковые значения (порядок должен сохраняться — нужно для пузырьковой и для счётчиков), уже отсортированные данные и данные в обратном порядке. Ограничение — 10 секунд на тест.

#### 3.3–3.7. Пять программ с ошибками

**Что получает студент:**
- Программу на 30–70 строк: простой код без классов, на функциях, циклах, условиях, списках и словарях.
- Над редактором короткое описание, 2–4 предложения: что программа должна делать, что на входе и что выводит. Плюс один пример «ввод → правильный вывод».
- Программа запускается, но на примере выдаёт неверный результат или падает с ошибкой.

**Что делает студент:** находит ошибку, исправляет, запускает программу на своём вводе и отправляет на проверку.
- **Запуск ограничен: не больше 4 раз на задание.**
  - Счётчик ведёт сервер. Перед каждым запуском браузер запрашивает разрешение (`POST …/run`), сервер уменьшает остаток и разрешает или отказывает.
  - Над редактором видно «Осталось запусков: N из 4».
  - **После 4-го запуска задание блокируется полностью:** запускать, править и отправлять код больше нельзя.
  - Код, который был в 4-м запуске, становится окончательным ответом и автоматически уходит на проверку (в журнале и админке с пометкой «авто: запуски закончились»). Иначе за задание всегда был бы 0, даже если ошибка исправлена.
  - Перед 4-м запуском показывается предупреждение: «Это последний запуск. После него код будет заблокирован и отправлен на проверку».
- **На проверку — только один раз.**
  - Перед отправкой показывается подтверждение: «Отправить? Изменить решение после отправки будет нельзя».
  - Отправка возможна и без единого запуска.
- **После отправки (или после 4-го запуска) задание блокируется.** Это касается только того задания, которое отправлено, остальные задания работают как прежде.
  - Редактор только для чтения, кнопки «Запустить», «Отправить» и «Вернуть исходный код» исчезают.
  - Стоит пометка «Отправлено», показывается отправленный код.
  - Сервер отклоняет повторную отправку и запуск этого задания, даже если запрос пришёл в обход страницы.
- **Результат проверки студенту не показывается**, только «Отправлено, результат объявит преподаватель» (см. п. 5). Тесты сервер прогоняет и сохраняет сразу, баллы видны в админке.
- **Что ограничение не охватывает.** Запуск идёт в браузере студента, поэтому код можно скопировать и запустить вне сайта (например, в своём Python). Полностью это не запретить, но вставка, копирование и уход со вкладки пишутся в журнал.
- **Сбросы.** Кнопка «Вернуть исходный код» восстанавливает программу, но **не возвращает запуски**.
- **Если время вышло до отправки.** В момент закрытия окна последний сохранённый черновик отправляется на проверку автоматически, с пометкой «авто» в журнале и в админке.
- Объём изменений не ограничен. В журнал записывается, сколько строк изменено, это нужно только для анализа.

**Типы ошибок** (у каждого студента по одной программе каждого типа, из своей темы):

| Тип | Ошибка | Пример программы (магазин / библиотека / поликлиника) |
|---|---|---|
| 1 | Граница цикла: `range(1, n)` или `range(n - 1)`, теряется первая или последняя запись | итог по чеку / число книг на руках / число приёмов за день |
| 2 | Неверное условие: `>` вместо `>=`, `and` вместо `or` | скидка от суммы / штраф за просрочку от N дней / запись только в рабочие часы |
| 3 | Тип данных: строка из `input()` не приведена к числу, сравниваются строки (`"9" > "10"`) | самый дорогой товар / самая старая книга по году / самый ранний приём |
| 4 | Накопитель обнуляется внутри цикла или `return` стоит внутри цикла | выручка по категориям / средний срок выдачи / нагрузка на врача |
| 5 | Ошибка со словарём: `KeyError` для нового ключа, перезапись вместо накопления, сортировка не по тому ключу | заказы по клиентам / выдачи по читателям / приёмы по врачам |

Версии 1 и 2 одного типа в одной теме отличаются полями, данными и местом ошибки.

**Проверка:**
- 5 тестов, первый открытый (это пример из описания). Открытый тест студент видит в условии, но не прогоняет автоматически: запускает сам, расходуя запуск.
- Засчитывается, когда при единственной отправке проходят все тесты.
- Отдельный скрипт перед контрольной проверяет, что исходная программа с ошибкой проходит не все тесты, а исправленный эталон проходит все.

**Исключение из правила «задания без кода»:** в этих пяти заданиях студент видит готовый код, потому что найти в нём ошибку и есть задание.

### Этап 4. SQL: ущерб и восстановление
Студент работает в личной копии базы своей темы через `sql-sandbox`. Время атаки и учётка злоумышленника даны в условии, поэтому этап не зависит от этапа 2.

Задания:
- SELECT с JOIN: какие записи изменила учётка злоумышленника после времени T;
- подсчёт ущерба через `COUNT`/`SUM` с `GROUP BY`;
- восстановление по резервной таблице через UPDATE/DELETE (проверяется состояние таблиц);
- заблокировать учётку злоумышленника (UPDATE поля `active`).

### Этап 5. Шифр Цезаря
В песочнице этапа 1 лежит скрытый файл с зашифрованным паролем администратора. Сдвиг у каждого студента свой. Студент находит файл (`ls -a`, `find`), подбирает сдвиг и расшифровывает. Флаги:
1. Найденный путь к файлу.
2. Пароль.

Расшифровывать можно вручную или программой в редакторе этапа 3 (свободное поле «Черновик», без проверки).

### Этап 6. Отчёт об инциденте
Форма из четырёх полей: хронология, причина, что сделано, рекомендации (5–10 предложений). Черновик сохраняется автоматически. Баллы ставит преподаватель.

## 5. Правила проведения

**Этапы:**
- Переход не ограничен: все этапы и задания открыты с начала, порядок любой, можно возвращаться.
- Невыполненное задание не засчитывается (0 баллов), частичных баллов за задание нет.

**Что видит студент:**
- Подсказки и теория выключены.
- **Алгоритмы (3.1–3.2):** запуск и проверка не ограничены. Проверка отвечает «тест N пройден / не пройден / ошибка выполнения». Ожидаемый вывод закрытых тестов не показывается.
- **Программы с ошибками (3.3–3.7):** 4 запуска и одна отправка; после отправки или 4-го запуска задание заблокировано, результат не показывается (см. 3.3–3.7).
- **Баллов студент не видит** ни во время контрольной, ни сразу после. Видно только, какие задания решены.
- Итог появляется у студента, когда преподаватель проверит отчёты и нажмёт «Опубликовать результаты» в админке.

**Окно времени:**
- До начала контрольную не видно.
- После окончания сдать ничего нельзя, а действия «Проверить» и «Отправить» отклоняются сервером.

**Обычные задания на время контрольной:**
- Задания ИБ №3–№7 и SQL-тренажёр у группы IB остаются в списке, но заблокированы с пометкой «Закрыто на время контрольной».
- Прямые ссылки и API этих заданий в это время отвечают отказом.
- После закрытия окна всё открывается автоматически.

## 6. Журнал действий студента

**Требование:** каждое действие студента сохраняется, у каждого студента отдельный файл журнала. Действия разных студентов не смешиваются. По журналу строится карта действий, анализ проводится после всех контрольных.

### Где хранится
- **`data/exam/<exam-id>/logs/<studentId>.jsonl`** — один файл на студента, одна строка — одно событие в JSON. Файл только дописывается и никогда не перезаписывается.
- **`data/exam/<exam-id>/snapshots/<studentId>/`** — полные версии кода при каждом запуске и проверке.
- **Таблица `exam_events`** в БД — краткая копия событий только для быстрых таблиц в админке. Основной источник — файлы.

### Формат события
```json
{"ts":"2026-10-28T09:14:03.512Z","seq":184,"student":"st-ib-125","exam":"ib-final-1","stage":3,"task":"3.4","type":"code_check","data":{"passed":3,"total":5,"changedLines":2},"session":"s-7f3a","ip":"10.0.0.21"}
```
`seq` — сквозной номер события у студента, по нему видно, если событие потерялось или повторилось.

### Какие события пишутся
| Группа | События |
|---|---|
| Сессия | вход, выход, открытие контрольной, перезагрузка страницы, смена IP/браузера, окончание времени |
| Навигация | открытие этапа и задания, переход между заданиями, время на каждом |
| Терминал (этапы 1, 2, 5) | каждая команда, её вывод (обрезанный), код возврата, текущий каталог |
| Флаги | каждый ответ, верный или нет |
| Код (этап 3) | снимок правок раз в 10–15 с при изменениях, запуск (с вводом и выводом, номер запуска из 4), отказ в запуске сверх лимита, отправка программы с ошибкой (ручная или авто) и попытки после блокировки, проверка с результатом по тестам, найденные запрещённые функции, сброс к исходному, вставка из буфера (размер) |
| SQL (этап 4) | каждый запрос, ошибка или результат, верно ли |
| Отчёт (этап 6) | сохранения черновика, отправка |
| Внимание | уход со вкладки и возврат, длинные паузы без действий |

### Карта действий и анализ
**В админке** (`/admin/exam/<exam-id>/student/<id>`):
- лента событий с фильтрами по этапу и типу;
- временная шкала на всё время контрольной: цвет — этап, отметки — решения, ошибки, уходы со вкладки;
- граф переходов между заданиями: порядок, возвраты, брошенные задания;
- по каждому заданию: время, число попыток до верного, изменения кода между запусками, для SQL — классификатор ошибок `sql-mistakes.js`.

**Скрипт `scripts/exam/analyze.py`** после всех контрольных:
- сводная таблица «студент × задание»: время, попытки, итог; выгрузка в CSV;
- совпадения между студентами: одинаковый код, одинаковые последовательности команд, ответы в одно время;
- подозрительное: большая вставка с первой попытки, решение без единого запуска, частые уходы со вкладки;
- общая картина: самые трудные задания и типы ошибок для группы.

## 7. Что сделать в коде (после «давай»)

1. **Модуль контрольной** `src/lib/exam.js`: этапы, баллы, окно времени, варианты. Новые таблицы:
   - `exams` — окно времени и флаг «результаты опубликованы»;
   - `exam_variants` — студент → тема, пара алгоритмов, формулировки, версии программ;
   - `exam_results` — задание → решено, баллы, оценка преподавателя;
   - `exam_events`.
2. **Журнал** `src/lib/exam-log.js`: дописывание в файл студента и в сводку БД, сквозной `seq`, очередь записи на студента. Маршрут `POST /exam/log` для событий из браузера.
3. **Блокировка обычных заданий:** проверка «идёт контрольная у группы» в карточках и маршрутах ИБ (`src/routes/ib.js`) и тренажёра (`src/routes/trainer.js`), пометка «Закрыто на время контрольной».
4. **Песочница Linux** (этапы 1, 2, 5): новое задание на движке `ib/server/lab_task.py`, генератор под вариант (дерево файлов, короткие журналы с атакой, скрытый файл Цезаря). Команды пишутся в журнал контрольной.
5. **Этап 3:**
   - **Контент** в `content/exam/`:
     - 18 условий алгоритмов, `algorithms/<тема>/<алгоритм>-<а|б>.md`;
     - 30 программ с ошибками, `bugs/<тема>/<тип>-<версия>.py` + `.md` с описанием;
     - генераторы тестовых данных.
   - **Код:** редактор и проверка на основе `python-basics-check.js`, кнопка «Вернуть исходный код», для программ с ошибками счётчик запусков на сервере (таблица `exam_runs`), одна отправка и блокировка задания, автоотправка при закрытии окна, проверка запрещённых функций через `ast` (код только разбирается, не выполняется).
6. **Этап 4:** схемы и данные трёх тем, упражнения через `sql-sandbox` под вариант. В общем тренажёре их не видно.
7. **Страница контрольной** `/exam/<exam-id>`: этапы с отметкой «решено / не решено» (без баллов), таймер, свободный переход, форма отчёта.
8. **Админка** `/admin/exam`:
   - окно времени;
   - распределение вариантов;
   - таблица «студент × задание × баллы»;
   - карта действий;
   - баллы за отчёт;
   - «Опубликовать результаты»;
   - выгрузка CSV.
9. **Эталоны и проверка вариантов** (`scripts/exam/`): эталоны всех 18 алгоритмов и 30 исправленных программ. Скрипт проверяет каждый вариант:
   - эталон проходит;
   - программа с ошибкой не проходит;
   - чужой алгоритм не даёт верный счётчик;
   - запрещённые функции ловятся.
10. **Тесты:**
    - отдельный файл журнала на студента и `seq` без пропусков;
    - свободный переход между этапами;
    - блокировка заданий ИБ и тренажёра в окне и снятие после;
    - закрытие по окончании окна;
    - баллы скрыты до публикации;
    - закрытые тесты не попадают на страницу;
    - программа с ошибками: 5-й запуск отклоняется, после 4-го запуска правка, запуск и отправка отклоняются, а код 4-го запуска отправлен автоматически, вторая отправка отклоняется, после отправки задание только для чтения, результат не отдаётся студенту, автоотправка черновика по окончании окна;
    - уникальность вариантов.
11. **Пробный прогон** на `st-test-001` и копии базы на втором порту: по одному варианту каждой темы, просмотр карты действий в админке.

Перед изменениями базы — резервная копия в `backups/`. Существующие данные и задания студентов не трогаются.

**Дата контрольной: 20-е число** (по ответу преподавателя 2026-10-19; если это 2026-10-20, на подготовку остаётся один день).
