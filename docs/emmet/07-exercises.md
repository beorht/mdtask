## Теория «id, class и контейнеры» (`LessonView.js`)

Основана на презентации «HTML id, class и контейнеры». Структура статьи:

1. **id и class — имена для элементов.** Сравнения: «id — как номер паспорта», «class — как форма команды». Примеры: `h1#logo`, три `p.card`, кнопки `.btn` с `#buy`. Таблица отличий (как пишется, как найти в CSS, сколько на странице, сколько у элемента). Совет: для оформления почти всегда берите class.
2. **div — универсальная коробка.** Пример карточки котика. Зачем нужен div: сгруппировать, оформить разом, расположить. Вложенность «как матрёшка».
3. **Специальные контейнеры.** 4 цветные карточки: `header` — шапка, `nav` — навигация, `main` — главное (один на странице), `footer` — подвал. Пример страницы блога. «Почему не просто div?»: понятнее людям, поисковикам и программам чтения с экрана.
4. **Как устроены задания.** Где писать код, что показывают верхнее и нижнее окно, переключатель «Схема», `Ctrl+Enter`. Кнопка «К заданиям».

Каждый пример показан как код с подсветкой и рядом схема коробок, нарисованная из того же HTML
(`sanitize(..., { stripNames: true })` внутри `.lesson-render.boxes`).

## Как добавить задание

```json
{
  "id": "practice-31",
  "title": "Название",
  "description": "Условие для ученика без тегов и сокращения.",
  "emmetExpression": "section>h2+p",
  "mode": "emmet",
  "validationMode": "structure",
  "difficulty": 1
}
```

- **Задание на контейнеры:** добавить в `containers.json` с `"mode": "html"` и `"section": "containers"`. Оно появится у всех в конце плана.
- После правки запустить `npm test`. Тесты проверяют, что каждый эталон разворачивается, берётся из строки по Tab целиком и проходит собственную проверку. Тест на количество работ по уровням (7 / 4 / 19) нужно обновить.
- Если банк изменился, сервер сам перевыдаст наборы, которые перестали быть валидными.
