# Итоговая контрольная группы WEB — варианты устройства (на будущее)

Предложены 24.10.2026. Сделан вариант **В** «Мини-приложение по техническому заданию» (план и реализация —
`docs/web-exam-plan.md`). Остальные сохранены здесь, чтобы добавить их позже: каждый ложится на ту же
основу — окно контрольной, варианты, журнал действий, вход только с ПК аудитории, редактор HTML/CSS/JS с
изолированным предпросмотром (`public/js/web-runner.js`).

Темы группы: объекты и словари, «DOM: работа с document» (12 задач), «DOM: подробная теория» (8 частей:
поиск элементов, содержимое и классы, создание элементов, события, формы, профессиональные приёмы, ES-модули).

## А. Набор задач с автотестами

6–8 задач по DOM: счётчик, список с удалением, поиск по таблице, сортировка, форма с проверкой, вкладки,
делегирование событий. У каждого студента свои данные и формулировки; у каждой задачи открытые и закрытые тесты.

- Тесты — сценарии на странице студента: «ввести в поле…», «нажать…», «в списке должно стать 3 пункта».
  Во время контрольной выполняются в браузере студента (видны результаты открытых тестов).
- Итог — **перепроверка после контрольной** скриптом на компьютере преподавателя в настоящем браузере
  (Playwright + Chromium, как уже установлены для проверок): все тесты, включая закрытые; подделать результат в
  своём браузере бесполезно.
- \+ автоматическая проверка, понятные баллы; − задачи похожи на домашние, их легче «переписать».

## Б. Найди и исправь ошибку

Готовые страницы с ошибкой: неверный селектор, обработчик вешается до появления элемента, нет `preventDefault`,
ошибка с `this` / стрелочной функцией, данные вставляются через `innerHTML`, `querySelector` вместо
`querySelectorAll`. 4 запуска и одна отправка, как программы с ошибкой в контрольной IB (`src/lib/exam/bugs.js`).

- \+ проверяет понимание, а не заучивание; механизм уже проверен на IB.
- − нужно готовить страницы с ошибкой (это единственное исключение из правила «без кода в заданиях», как в IB).

## Г. «Что выведет код» на время

10 коротких фрагментов по 60 секунд: порядок событий, всплытие и погружение, `textContent` против `innerHTML`,
`querySelectorAll` против `children`, `this` в обработчике, `defer`/`DOMContentLoaded`, ключи `localStorage`.
Варианты ответа перемешаны, фрагменты из банка — у каждого свой набор.

- \+ нейросеть почти не помогает (времени нет); проверяется автоматически.
- − только теория, писать код не нужно.

## Д. Вёрстка по макету

Повторить страницу по картинке (шапка, карточки, форма, адаптив).

- − автоматически проверяется плохо (сравнение картинок ненадёжно) — только ручная оценка.

## Защита от решения через нейросеть (для любого варианта)

Личные данные, тексты и тестовые значения у каждого; вставка в редактор отключена, набор без клавиш записывается;
закрытые тесты и перепроверка после контрольной; 2 контрольных вопроса по коду студента после задачи
(«что изменится, если убрать `preventDefault`?»); ловушка при копировании; вход только с ПК аудитории без
интернета; сигналы и «Выбрать 4 студентов» для устной проверки в админке.
