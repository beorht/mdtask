## Сюжет

Студент — администратор учебного сервера небольшой организации (тема по зерну: интернет-магазин,
библиотека, клиника). На сервере работает веб-приложение `/srv/<app>`, есть сотрудники,
уволенный сотрудник и стажёр. Прошлый администратор оставил ошибки в правах. Нужно провести аудит
и привести сервер к политике, не сломав приложение и не потеряв свой доступ.

## Модель прав в эмуляторе

Сейчас владелец файла определяется местом (домашний каталог — студент, остальное — root). Для
задания нужна настоящая модель:

- `vfs.Sandbox`: необязательный файл владельцев `/var/lib/seclab/owners.json` (путь → `user:group`,
  числовой UID для файлов без владельца). Если файла нет — всё как раньше (другие задания не меняются).
- `owner()/group()/uid()/gid()` по этому файлу и `/etc/passwd`, `/etc/group`; `can()` учитывает
  биты группы, если студент в группе файла.
- Новые команды `chown [-R] user[:group]` и `chgrp [-R]` (только с sudo); `chown` снимает SUID/SGID,
  как в Linux. Перемещение и удаление переносят и удаляют записи владельцев.
- `ls -l`, `stat`, `find -user/-group/-nouser/-nogroup/-uid/-gid` показывают и находят настоящих
  владельцев; `ls -l` показывает биты `s/S/t/T`.

## Этапы (личные значения у каждого)

1. **Учётные записи** — `getent passwd`, `getent group`, `id`: сколько участников в группе sudo,
   какая лишняя учётная запись с UID 0 (ответы с доказательством выводом команд).
2. **Чтение прав** — `ls -l`, `stat -c`: восьмеричные права и владелец личного файла конфигурации.
3. **Файлы, доступные на запись всем** — `find / -xdev -type f -perm -o+w`: сколько их; убрать
   запись для всех. Критично: `/tmp` остаётся `1777`.
4. **Секреты** — `/etc/shadow`, `.env` приложения, закрытый ключ сотрудника, резервная копия базы:
   их не читают посторонние; приложение (`www-data`) по-прежнему читает свой `.env`.
5. **Нестандартные SUID-программы** — `find / -perm -4000`: какая программа не из стандартного
   набора; снять бит. Критично: `passwd` и `sudo` сохраняют SUID.
6. **Владельцы каталога приложения** — файлы без владельца (`find -nouser`) передать владельцу
   приложения, код не доступен на запись стажёру, `uploads` доступен на запись только приложению.
7. **Пользователи и sudo** — стажёр не в группе sudo, уволенный сотрудник заблокирован,
   лишняя учётная запись с UID 0 заблокирована. Критично: студент остаётся в sudo.
8. **Повторный аудит** — те же `find` после исправлений (команды после открытия этапа).

Проверки этапов 3–7 — по итоговому состоянию песочницы через ту же модель прав («может ли
пользователь X прочитать или записать файл Y»), а не по точным числам, поэтому подходят разные
правильные решения.
