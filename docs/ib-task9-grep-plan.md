Запрошено 2026-10-21. Применяется после «давай».

Документ из двух частей:

2. Общий набор мер против «переписывания ответа из ИИ»: он внедряется в №9, переносится в уже выданные

## 1. Как устроено задание №9

- Ключ `grep`, номер 9, движок этапов `ib/server/lab_task.py` (как №6–8). Этап = одна задача, 13 этапов,
  открываются по порядку.
- Песочница у каждого студента своя (`data/ctf/grep/<id>/`), тема — одна из трёх (магазин / библиотека /
  клиника, как в №8). Имена, адреса, домены, учётные записи, числа — свои у каждого.
- Студент пишет команду прямо в терминале. После каждой команды система проверяет:
  1. **команда разрешена** — в конвейере только `grep` (и `grep | grep`, где это сказано в условии),
     без `cat`, `awk`, `sed`, `sort`, `head`, `echo`, перенаправлений и `answer`;
  2. **вывод совпадает** с выводом эталонной команды на данных студента (строка в строку, порядок важен —
     grep не меняет порядок);
  3. **команда верна в общем случае** — та же команда выполняется ещё на двух скрытых наборах данных
     с теми же путями файлов, но другим содержимым и крайними случаями (см. меры, п. А).

  Если всё совпало — задача засчитана, затем 2 контрольных вопроса (п. Г).
- Условие описывает результат словами и показывает «контрольную точку»: сколько строк должно выйти
  и первые 1–2 из них. По этому студент сам видит, что попал. Полный ожидаемый вывод не показывается.
- Команды `task`, `check`, `hint N` (подсказка — какой раздел теории читать, без готового ключа;
  использование подсказки записывается).
- Теория `ib/ctf/grep/THEORY.md`: BRE/ERE/PCRE, классы символов, якоря, `\b` и `-w`, квантификаторы,
  группы и обратные ссылки, просмотр вперёд/назад (`-P`), `-o -c -n -v -l -L -m`, контекст `-A/-B/-C`,
  `-r --include --exclude`, `-f` и `-F`, почему точка в IP-адресе должна быть экранирована.
  Теория не содержит ни одной команды из эталонных решений (тест проверяет).

### Задачи

Файлы песочницы: `/var/log/auth.log`, `/var/log/nginx/access.log`, `/var/log/<служба>/app.log`,
`/etc/passwd`, `/etc/<служба>/*.conf` (+ `*.bak`, `*.example`), `~/contacts.txt`, `~/notes.txt`,
`~/payments.txt`, `~/blocklist.txt`.

| № | Что получить | Что проверяют скрытые наборы |
|---|---|---|
| 1 | Все строки `auth.log` с учётной записью студента, в любом регистре | имя в другом регистре, имя как часть более длинного имени |
| 2 | Число строк `auth.log` с неудачным вводом пароля | одно число; в скрытых наборах другое количество |
| 3 | Конфигурация службы без комментариев и пустых строк (включая строки из одних пробелов и комментарии с отступом) | `#` внутри значения не должен выкидывать строку |
| 4 | Только корректные IPv4-адреса из `notes.txt`, по одному в строке | `300.1.2.3`, `1.2.3.4.5`, версии `v2.10.3.1`, адрес в конце строки, ведущие нули |
| 5 | Строки `access.log`, где **код ответа** 5xx | 500 в размере ответа, в URL, во времени запроса |
| 6 | Логины из `/etc/passwd` с UID ≥ 1000 и настоящей оболочкой (не `nologin`/`false`), только логины | UID 100 и 10000, `nologin` в поле комментария, оболочка `/bin/false` |
| 7 | Имена файлов конфигурации (рекурсивно, только `*.conf`), где задан непустой пароль, без закомментированных | `#password=…`, `password=` пустой, `.bak` и `.example` с паролем |
| 8 | Каждый успешный вход root и 2 строки перед ним, без разделителей групп | соседние входы с перекрытием контекста |
| 9 | Адреса почты только домена организации, без поддоменов-подделок | `user@corp.uz.evil.com`, `user@sub.corp.uz`, регистр, точка в конце предложения |
| 10 | Строки `notes.txt`, где одно и то же слово повторено два раза подряд | «на на», «Нет нет» (регистр), «ab abc» — не повтор |
| 11 | Записи `app.log` за 18.11 с 21:00 до 23:59 включительно | 20:59, 00:00 следующего дня, другой день с тем же временем |
| 12 | Строки `access.log` с адресами из `blocklist.txt` (шаблоны из файла) | `10.0.0.1` против `10.0.0.15`, точка как «любой символ» (`10a0b0c1`) |
| 13 | Номера карт из `payments.txt`: 16 цифр, группы по 4 через один и тот же разделитель или без, только номера | 20-значный номер заказа, смешанные разделители `1234-5678 9012-3456`, номер внутри длинного числа |

Эталонные команды — в `scripts/ib/solutions/grep.json` (ключ задачи → команда). Генератор проверяет на
12 сидах, что эталон даёт непустой и однозначный результат, а «типичные почти верные» команды (без `-w`,
без экранирования точки, без якоря и т. п., список в генераторе) на скрытых наборах дают другой вывод.
Иначе задача не ловила бы ошибку, ради которой она придумана.

Баллы: 1–2 — по 3, 3 — 4, 4–13 — по 9 (всего 100). Неверный или просроченный контрольный вопрос —
половина баллов задачи. Студенту показывается «задач N из 13», баллы — в админке.

## 2. Меры против решения через нейросеть

Принцип: ответ, который можно получить от чата, не приняв участия в работе, не засчитывается или
оставляет след. Меры А–Е новые, Ж–Л уже есть в №8 и становятся общими.

**А. Скрытые проверочные данные (новое).** Команда студента повторно выполняется на скрытых наборах с теми же
путями. «Подогнанная» команда (`grep -x 'готовая строка'`, `grep -n '' | grep -E '^(3|7|9):'`) и
«почти верная» команда, которую чаще всего предлагает чат, на них не проходят. Студент видит только
«на ваших данных верно, на проверочных — нет», без содержимого скрытых наборов.

**Б. Только grep (новое).** Конвейер разбирается до выполнения; запрещённая команда — отказ с объяснением.
Значения, набранные в самой команде, не могут дать ответ: если результат содержит строку, целиком
набранную в командной строке, задача не засчитывается (защита от `grep -F 'скопированный ответ'`).

**В. Мутационные контрольные вопросы (новое).** После решения задачи система меняет команду студента
(убирает `-w`, ключ `-o`, якорь `^`, экранирование точки…), сама выполняет изменённую команду и
спрашивает: «Сколько строк выведет ваша команда без `-w`?» — 4 варианта, 60 секунд. Ответ знает тот,
кто понимает свою команду, а не тот, кто её переписал. Второй вопрос — про смысл части шаблона
(«что совпадает с `[0-9]{1,3}` в вашей команде»), варианты из реального вывода.

**Г. Контрольные вопросы этапов** (есть в №8): 2 вопроса по 60 с, `answer q N`.

**Д. Ритм набора (новое, для всех заданий).** `ib-guard.js` для каждой отправленной строки терминала
сообщает число символов, время от первой клавиши до Enter и число исправлений (Backspace). Длинная
команда, набранная без единой паузы и исправления за доли секунды, — признак автонабора или вставки в
обход запрета; это сигнал в админке, а не отказ.

**Е. Время до решения (новое, для всех заданий).** От открытия задачи до первой верной команды и число
неверных попыток перед ней. «Сразу верная сложная команда за 20 секунд после открытия, без попыток» —
сигнал. Попытки студента в админке видны целиком (все команды задачи по порядку).

**Ж. Доказательство из вывода** (есть в №8, `ib_lab_seen`): ответ `answer` засчитывается, только если
значение было в выводе команд студента. Для №9 не нужно — там проверяется сама команда.

**З. Ловушки** (есть в №8): скрытый абзац в условии и текст, добавляемый к скопированному, подсказывают
команду, которая проходит видимые данные и не проходит скрытые (например, `-P` с `\d` вместо проверки
диапазона). Срабатывание записывается в `progress.traps`, баллы автоматически не снимаются.

**И. Запрет вставки** (есть в №8): вставка и перетаскивание в терминал и редактор отклоняются и
записываются, копирование и уход со страницы — тоже.

**К. Большие персональные данные** (есть в №8): у каждого свои данные, целиком в чат их не вставить;
ответ одного студента другому не подходит.

**Л. Админка и устная проверка** (есть в №8): баллы, сигналы с весами, «Выбрать 4 студентов» —
студенты с большим числом сигналов выпадают чаще.

Правила переноса, чтобы не навредить тем, кто уже работает:

- **Пройденное остаётся пройденным.** Новые проверки действуют только на этапы, открытые после
  обновления; уже решённые этапы и задания не пересчитываются.
- Доказательство из вывода включается с момента обновления: «следы» до него не собирались, поэтому для
  текущего этапа студенту, возможно, придётся заново выполнить команду, которая показала значение.
  В сообщении отказа это сказано прямо.
- №6 и №7 уже на движке `lab_task.py` — у них меры включаются флагами `Lab` и полями пунктов.
  №5 (`terminal_task.py`), №4 (`config_task.py`) и №3 (Цезарь) на своих движках: для них выносятся общие
  функции «следов», контрольных вопросов и событий в `lab_task.py` и вызываются оттуда, без переписывания
  заданий целиком.
- Баллы для №3–7 не вводятся: в админке появляются только сигналы, ответы на контрольные вопросы и
  ловушки.
