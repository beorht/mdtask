# План разработки интерактивной учебной платформы

## 1. Цель проекта

Развить существующую mdBook-подобную документацию в полноценную интерактивную учебную платформу.

Основная концепция:

> **Учебная IDE + документация**

Платформа должна объединять:

* теоретические материалы;
* практические задания;
* SQL-редактор;
* выполнение SQL;
* автоматическую проверку;
* структуру базы данных;
* историю попыток;
* автосохранение;
* загрузку файлов;
* прогресс обучения;
* интерфейс преподавателя;
* тесты.

Главный учебный цикл:

```text
Теория
   ↓
Попробовать пример
   ↓
SQL Editor
   ↓
Выполнить
   ↓
Результат
   ↓
Проверить
   ↓
Разбор ошибок
   ↓
Повторить
   ↓
Готово
```

# 10. Этап 6. Подсказки

Не показывать решение сразу.

Пример:

```text
💡 Подсказка №1

В таблице необходимо определить три столбца.
```

Следующая:

```text
💡 Подсказка №2

Для уникального идентификатора используется PRIMARY KEY.
```

Последняя:

```text
💡 Подсказка №3

Используйте CREATE TABLE products (...).
```

В дальнейшем можно добавить стоимость использования подсказок.

# 11. Этап 7. Объяснение ошибок

Не показывать только технический текст ошибки.

Вместо:

```text
ERROR
```

показывать:

```text
Ошибка

В запросе обнаружена синтаксическая ошибка возле TABLE.

Проверьте:

• CREATE TABLE;
• скобки;
• запятые между столбцами.
```

Нужно создать слой преобразования технических ошибок SQLite в понятные учебные сообщения.

# 12. Этап 8. Автосохранение

Разделить:

```text
Draft
```

и

```text
Submission
```

Draft — текущая работа.

Submission — отправленная попытка.

Пример:

```text
Автосохранение...
```

затем:

```text
Сохранено ✓
```

При повторном открытии:

```text

[Восстановить] [Начать заново]
```

# 23. Универсальный Validator

Не сравнивать SQL как строки.

Плохо:

```text
answer == "CREATE TABLE products (...)"
```

Правильно:

```text
Есть таблица products?
        ↓
Есть id?
        ↓
INTEGER?
        ↓
PRIMARY KEY?
        ↓
Есть name?
        ↓
TEXT?
        ↓
NOT NULL?
        ↓
Есть price?
        ↓
REAL?
        ↓
NOT NULL?
```

Проверять итоговое состояние БД.

# 50. Главный UX-принцип

Студент в любой момент должен понимать:

```text
1. Что нужно сделать?
2. Где это сделать?
3. Что произошло?
4. Что правильно?
5. Что неправильно?
6. Что делать дальше?
```

Поэтому основной экран должен строиться вокруг:

```text
ЗАДАНИЕ
   ↓
РЕДАКТОР
   ↓
ВЫПОЛНИТЬ
   ↓
РЕЗУЛЬТАТ
   ↓
ПРОВЕРИТЬ
   ↓
ОШИБКИ / ОБЪЯСНЕНИЕ
   ↓
ПОВТОРИТЬ
   ↓
ГОТОВО
```

# 51. Рекомендуемый первый релиз

Для первой рабочей версии достаточно реализовать:

```text
Dashboard
    ↓
Курс
    ↓
Раздел
    ↓
Теория
    ↓
Практика
    ↓
SQL Editor
    ↓
Execute
    ↓
Database Explorer
    ↓
Check
    ↓
Validation Result
    ↓
Progress
```

Не следует начинать разработку одновременно с тестов, достижений, сложной аналитики и полноценной геймификации.

Главный продуктовый фокус первой версии:

> **Студент прочитал → написал SQL → выполнил → получил результат → проверил → понял ошибку → исправил → завершил задание.**
