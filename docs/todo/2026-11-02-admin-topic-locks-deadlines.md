# Админ: блокировка и дедлайны тем по группам

**Запрошено:** 2026-11-02. **Статус:** план, не применялось.

## Задача

Со стороны преподавателя (`/admin`) нужно для **конкретной темы предмета** уметь:
- **заблокировать** её для группы (студенты видят 🔒, зайти нельзя);
- **поставить дедлайн** — после него тема автоматически закрывается так же, как ручная блокировка.

## Решения (согласованы с пользователем 2026-11-02)

1. **Два уровня области — группа и студент:**
   - **по группе** — настройка на `(предмет, тема, группа)`, действует на всех студентов группы;
   - **по студенту** — настройка на `(предмет, тема, студент)`, и в двух смыслах:
     - **закрыть** тему только одному студенту (даже если группе открыто);
     - **открыть доступ** только одному студенту — форс-открытие в обход группового замка/дедлайна.
   - **Приоритет: студент > группа > обычная логика.** Запись по студенту всегда перебивает групповую.
2. **Предметы — все, у кого есть темы/модули:** HTML, CSS, Emmet, курс Python, курс JavaScript, Linux, SQL-тренажёр.
3. **Дедлайн — жёсткий:** после срока тема закрывается (🔒 + 423), как ручная блокировка. (Мягкий режим «просрочено, но можно решать» не делаем.) Дедлайн можно ставить и на группу, и на студента.

Группа `TEST` / `hasFullAccess` **никогда не блокируется** (как и везде). Экзаменационная блокировка (`examLockFor`) действует независимо и имеет приоритет (закрывает весь предмет).

## Модель данных

Новая таблица (в `src/db/schema.sql`, `CREATE TABLE IF NOT EXISTS`, миграции не нужны):

```sql
CREATE TABLE IF NOT EXISTS topic_overrides (
  subject     TEXT NOT NULL,            -- 'html','css','emmet','python','javascript','linux','sql'
  topic_key   TEXT NOT NULL,            -- ключ темы/модуля/секции в рамках предмета
  scope       TEXT NOT NULL,            -- 'group' | 'student'
  target      TEXT NOT NULL,            -- имя группы (scope='group') ИЛИ id студента (scope='student')
  mode        TEXT NOT NULL,            -- 'lock' | 'deadline' | 'allow'
  deadline    TEXT,                     -- ISO-дата для mode='deadline' (закрыть после неё)
  note        TEXT,                     -- необязательная причина, показывается студенту
  updated_at  TEXT,
  updated_by  TEXT,                     -- id преподавателя
  PRIMARY KEY (subject, topic_key, scope, target)
);
```

Смысл `mode`:
- `lock` — закрыто сразу (🔒);
- `deadline` — открыто до `deadline`, после — закрыто (жёстко);
- `allow` — **только для `scope='student'`**: форс-открыть тему этому студенту в обход группового замка/дедлайна.

Групповые записи используют `lock`/`deadline`. Студенческие — любой из трёх (`allow` = «открыть одному»).

Доступ в БД: `makeTopicLocksDb(...)` в `src/db/topic-locks.js` (`getOverride(subject,topicKey,scope,target)`, `listOverrides(subject?)`, `overridesForStudent(subject,user)` — групповые по `user.group` + студенческие по `user.id`, `setOverride`, `clearOverride`), подключить в `src/db/index.js` и добавить `DELETE FROM topic_overrides` в `__resetForTests`.

## Общий слой `src/lib/topic-locks.js`

- `lockState(subject, topicKey, user)` → `{ locked, deadline, overdue, forcedOpen, reason }`. Приоритет **студент > группа > открыто**:
  1. `hasFullAccess(user)` → `{ locked:false }` (TEST никогда не закрыт);
  2. запись студента (`scope='student'`, `target=user.id`), если есть, **решает всё**:
     - `allow` → `{ locked:false, forcedOpen:true }` (в обход группы);
     - `lock` → закрыто; `deadline` → закрыто при `now ≥ deadline`, иначе открыто + бейдж;
  3. иначе запись группы (`target=user.group`): `lock` → закрыто; `deadline` → закрыто при `now ≥ deadline`, иначе открыто + бейдж;
  4. иначе не закрыто.
  - `reason`: «Закрыто преподавателем» / «Срок прошёл: <дата +05>» (+ `note`, если задан).
- `requireTopicOpen(subject, getTopicKey)` — middleware для роутов практики/теории/API: если `locked` → страница `423 render('topic-locked', { reason, deadline })`, API → `423 json`. По образцу `blockDuringExam` (`src/middleware/exam-lock.js`).
- `SUBJECT_TOPICS` — реестр: предмет → `{ title, groups, topics:[{key,title}] }`, собирается из модулей предметов (чтобы админка перечисляла темы и группы).
- `deadlineBadge(state)` — текст «до 10.11 18:00» для открытых тем с будущим дедлайном.

Формат даты/таймзона — как у экзаменов (+05), общий хелпер форматирования.

## Интерфейс админа

Новая страница **`/admin/locks`** (роут `src/routes/admin-locks.js`, данные `src/lib/admin-locks.js`, вид `src/views/admin/locks.ejs`), ссылка в топбаре админки (`src/lib/admin-view.js` / `src/views/admin/partials`).

UI: выбор **предмета**, затем переключатель области — **группа** или **студент**:
- **Группа:** выбрать группу (из `SUBJECT_TOPICS[subject].groups`) → таблица тем, в строке: **🔒 Заблокировать** / **Дедлайн** (`datetime-local`, +05) / **заметка** / **Сохранить** / **Снять**.
- **Студент:** выбрать студента (поиск по ФИО/логину среди студентов групп предмета) → таблица тем, в строке дополнительно к тем же полям — **«Открыть доступ»** (`mode='allow'`, перебивает групповой замок). Рядом показывается **эффективный статус** студента (что сейчас действует: групповой замок / дедлайн / индивидуально).
- Сверху — сводка: «по группе X закрыто N тем; индивидуально: закрыто K, открыто M».
- POST `/admin/locks/set` (поля `subject, topic_key, scope, target, mode, deadline, note`) и `/admin/locks/clear` (`subject, topic_key, scope, target`), сохраняют `updated_by = req.session.user.id`.

Дополнительно (необязательно, 2-й заход): на уже существующих админ-страницах предметов (`/admin/html`, `/admin/css`, …) показывать плашку «для группы X закрыты темы: …».

## Тесты

- `tests/lib/topic-locks.test.js`: `setOverride`/`lockState` —
  - групповой `lock` закрывает для студента группы и не закрывает TEST; `deadline` в прошлом → `locked`, в будущем → открыто + `deadline`; `clearOverride` открывает;
