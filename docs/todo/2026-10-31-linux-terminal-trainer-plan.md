# Новый предмет «Linux Terminal Trainer» (тренажёр командной строки)

Запрошено 31.10.2026. По спецификации `docs/console_emulator/Linux_Terminal_Trainer_Project_Specification.docx`.

## Что в документе

Веб-тренажёр для начального изучения Linux: ученик вводит команду → интерпретатор выполняет её над
**виртуальной файловой системой** → **дерево файлов** обновляется → система проверяет **итоговое
состояние ФС** (а не последовательность команд). Многие верные пути решения засчитываются.

- **Интерфейс — 3 панели + шапка + нижняя панель** (табл. 1): слева панель задания (теория, цель,
  шаги, подсказки, кнопка проверки), в центре терминал (ввод, вывод, история ↑, очистка), справа
  дерево файлов (раскрытие, подсветка текущего каталога, иконки, сведения об объекте, авто-обновление).
  Тёмная тема в стиле Linux IDE (графит/тёмно-синий, зелёный для успеха, фиолетовый для подсказок).
- **Команды:** `pwd whoami clear ls (-l -a -la, путь) tree (-L, путь) cd (.. ../.. / ~ - абс/отн)
  mkdir (-p) rmdir rm (-r -i -f) cat echo (> >>) cp (-r) mv` (табл. 3, 5–10).
- **5 модулей / 15 миссий** (табл. 4): 1 знакомство (pwd/whoami/clear/ls/tree), 2 навигация (cd, абс/отн
  пути), 3 создание/удаление (mkdir/rmdir/rm), 4 файлы (cat/echo/cp/mv), 5 комплексная практика.
- **Миссия =** исходное состояние ФС, формулировка, 3 уровня подсказок, критерии проверки, ожидаемое
  состояние, возможность сброса. Проверка (табл. 11): результат 40 / расположение 25 / навигация 15 /
  содержимое 10 / нет лишнего 10 = 100.
- **Visual Learning Mode** — показывать ФС «до/после» команды (ключевая фишка; по реальному состоянию
  виртуальной ФС, не декоративная анимация).
- **Архитектура (табл. 13):** свой парсер, исполнитель, реестр команд, виртуальная ФС, path-resolver,
  task-engine, история, прогресс. Запрещено подключать настоящий shell/ФС сервера.

## Что уже есть в mdtask (переиспользуем)

- **Эмулятор команд Linux** в IB — `ib/server/shell.py` + `ib/server/vfs.py` (ls/cd/mkdir/rmdir/rm/cp/mv/
  cat/echo/tree/…, виртуальная песочница, разрешение путей, ошибки как в coreutils). Это **эталон
  семантики команд** (но он на Python и работает по сети через bridge — тяжело для «живого» 3-панельного
  UI с мгновенным обновлением дерева и визуальным режимом; плюс один общий процесс на всех).
- **Паттерн «предмет-курс»** (python/js/html/css): контент в `content/<key>/` (JSON), логика в
  `src/lib/<key>-course/index.js`, маршруты `src/routes/<key>-course.js`, прогресс в своей таблице,
  админка `/admin/<key>`, перепроверка попытки на сервере (как html/css/emmet/python).
- **Паттерн «движок в браузере + серверная перепроверка»**: `public/js/js-runner.js` (UMD, работает и в
  браузере, и в Node на сборке/в тестах), `src/lib/emmet/validate.js` (клиент+сервер сверяют дерево).

## Предлагаемая архитектура (на обсуждение)

Новый предмет **`/subjects/linux`** «Linux Terminal Trainer», по паттерну курсов, но с собственным
3-панельным UI:

1. **Движок — клиентский JS** (виртуальная ФС + интерпретатор ~13 команд) в `public/js/linux-fs.js`
   (UMD, как `js-runner.js`): мгновенное дерево и визуальный режим без round-trip, полный сброс миссии,
   нет нагрузки на сервер. Семантику команд портируем из `ib/server/vfs.py`/`shell.py` (эталон).
   - **Против списывания — серверная перепроверка:** тот же UMD-движок подключается в Node, сервер
     **повторяет журнал команд студента** на исходном состоянии миссии и проверяет итоговую ФС по
     правилам миссии (как html/css сверяют результат). Клиентский вердикт — только подсказка.
2. **UI (новые компоненты, тёмная Linux-тема):** `TaskPanel` (слева), `Terminal` (центр), `FileTree`
   (справа), нижняя панель (запуск/сброс/подсказка/история/проверка/полный экран), Visual diff до/после.
   Тема отдельная (в спецификации — графит/синий/зелёный/фиолетовый), не общая Marple/«Тетрадь».
3. **Контент** `content/linux/`: `modules.json` (5 модулей/15 миссий) + на миссию `mission.json`
   (исходная ФС, текст, синтаксис, 3 подсказки, правила проверки, ожидаемое состояние). Правила проверки:
   существование каталога/файла по пути, содержимое файла, текущий каталог (если условие), отсутствие
   лишних объектов — всё по итоговому состоянию ФС, несколько решений засчитываются.
4. **Логика** `src/lib/linux-course/index.js` (миссии, статусы, порядок открытия), `validate.js`
   (серверная перепроверка через UMD-движок), маршруты `src/routes/linux-course.js`, страница-практика
   `src/views/linux-course/…`, прогресс в таблице `linux_progress` (+ `linux_events`), админка `/admin/linux`.
5. **Проверка/оценка:** статус миссии (решена/нет), подсказки трёх уровней, журнал команд и сигналы для
   преподавателя; баллы по таблице 11 — опционально.

## Альтернатива движка (если не JS)

Переиспользовать Python-эмулятор IB через bridge. Плюс: готовая зрелая семантика. Минусы: round-trip на
каждую команду, один общий процесс (контеншн), сложнее «живое» дерево и визуальный режим, завязка на
дисковую песочницу. **Рекомендация — клиентский JS-движок** (команд мало, UI требует мгновенности).

## Решения (31.10.2026)

1. **Движок:** клиентский JS (виртуальная ФС + интерпретатор в браузере), серверная перепроверка тем же
   UMD-движком; семантику команд портируем из `ib/server/vfs.py`/`shell.py`.
2. **Объём v1:** модуль за модулем — сначала движок + 3-панельный UI + модуль 1 (миссии 1–3), показать,
   затем модули 2–5.
3. **Группа:** **web-1** (+ TEST). Нюанс: web-1 ограничена набором предметов (`GROUP_SUBJECTS['web-1'] =
   ['html','css','emmet']`), поэтому новый предмет нужно добавить в её список (`'linux'`), иначе
   `subjectGuard` отдаст 404. Видимость: `LINUX_GROUPS = ['web-1']` + TEST (`hasFullAccess`).
4. **Тема:** своя тёмная «Linux IDE» тема предмета (графит/тёмно-синий, зелёный — успех, фиолетовый —
   подсказки), отдельный CSS; не общая Marple/«Тетрадь».
5. **Соотношение с ИБ:** IB-терминал (№5) остаётся как есть; это отдельный наглядный предмет для начинающих.
6. **Оценки:** в v1 — «решена/не решена» + подсказки трёх уровней + журнал/сигналы; баллы (табл. 11) —
   позже, по желанию.
