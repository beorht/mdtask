# Входы (сессии) хранить в базе, а не в памяти сервера

Запрошено 26.10.2026. Пункт в `TODO.md`. **Применено 26.10.2026** (см. раздел «Выполнено» в `TODO.md`). **Выкладывать на рабочий сервер только после контрольной**:
само изменение требует одного перезапуска.

## Проблема

`src/server.js` подключает `express-session` без хранилища — используется `MemoryStore`:

- каждый перезапуск выкидывает всех на страницу входа (во время контрольной — посреди работы);
- `MemoryStore` по документации не для рабочего сервера: память растёт, просроченные сессии не чистятся;
- секрет `'prototype-secret'` зашит в код.

## Что сделать

1. Своё небольшое хранилище сессий на `better-sqlite3` (`src/lib/session-store.js`, класс от `session.Store`):
   таблица `sessions (sid TEXT PRIMARY KEY, sess TEXT NOT NULL, expires_at INTEGER NOT NULL)` в `schema.sql`,
   методы `get`, `set`, `destroy`, `touch`; раз в час удалять просроченные.
   **Без новых пакетов из npm** (`connect-sqlite3` и т. п.): на сервере нет интернета, `npm ci` не запускать.
2. Срок сессии — `cookie.maxAge` 12 часов (сейчас cookie живёт до закрытия браузера); `rolling: true`, чтобы
   активный студент не вылетал.
3. Секрет: из переменной `SESSION_SECRET`, иначе — случайный, сохранённый в `data/session-secret` (создаётся при
   первом запуске). Если взять новый случайный при каждом запуске, сессии снова будут теряться.
4. Тесты (`DB_PATH=:memory:`): вход сохраняется в таблице; после `createApp()` заново (имитация перезапуска)
   тот же cookie остаётся входом; выход удаляет строку; просроченная сессия не принимается.
5. Не затронуть: проверку пароля и `must_change_password`, вход в терминал ИБ (у Python свой вход по паролю).

## Что не решает

- Сессии терминала ИБ живут в Python-процессе — после перезапуска студент ИБ вводит пароль терминала заново
  (работа в песочнице сохранена на диске).

## Выкладка

После контрольной: архив + `update-server.sh` (один перезапуск — все входят заново последний раз).
После этого перезапуски больше не выкидывают студентов.
