## Цель и формат

Промежуточная контрольная средней сложности для группы ИБ. Четыре блока:
- **A. Единое задание по терминалу/серверу** — поиск и изменение (find/grep/sed), настройка
  SSH-конфига, выдача прав доступа — в одной песочнице-сервере.
- **B. Две практические задачи «Python + sqlite3»** — по готовой структуре таблицы написать
  терминальную программу анализа и вывода (средняя сложность).
- **D. Анализ журналов** — по лог-файлам найти и вывести нежелательные входы и «засветившиеся»
  в журналах пароли/секреты (программа анализа; авто-проверка по выводу).
- **C. Поиск и исправление ошибок в коде** — сложные программы 50–60 строк с ловушками,
  **4 запуска**, после 4-го — авто-отправка (или кнопка «Отправить»); ошибки разных видов,
  особенно в работе с данными.

Окно: **2026-11-03 09:00–14:00 (+05)** (см. решение 1), 5 часов. Экзамен id `ib-mid-1`.

Варианты: тема/порядок/значения из позиции студента в группе (как у финала — seed), чтобы у
соседей не совпадали данные и программы.

## Блок A — «Операции на сервере» (единая терминальная задача)

Одна персональная песочница Debian (объединяет навыки заданий №4 configs, №7 ssh, №10 perms).
Генератор `ib/ctf/mid/generate_mid.py` на базе `ctf/configs` + `ctf/ssh` + `ctf/perms`
(переиспользует `templates.py`, `sshd_sim`, модель владельцев `vfs` + `owners.json`). Этапы:

- **A1. Поиск (find/grep).** Найти и назвать: порт SSH, `bind-address` MariaDB, `Listen`
  Apache, путь к `.env` приложения, лишнюю SUID-программу, файлы world-writable. Ответы
  (числа/пути) принимаются **только если были в выводе команд** (`track_output`/`proof`).
- **A2. Изменение (sed, без редактора).** Привести к политике: сменить SSH-порт, отключить
  `PasswordAuthentication`/`PermitRootLogin` (sshd_config + drop-in), `bind-address` БД →
  `127.0.0.1`. Проверка — по эффективному значению (`config_task`-логика).
- **A3. SSH по ключу.** Добавить свой открытый ключ в `authorized_keys`, `sshd -t`, применить
  (reload). Проверка — `sshd_sim.login()` (вход по ключу работает, пароль/без root — нет).
- **A4. Права доступа.** Снять world-write и лишний SUID, вернуть владельца каталога
  приложения (`www-data`), сохранить `/tmp` 1777 и себя в `sudo`, заблокировать лишнюю UID-0
  учётку (`passwd -l`/`usermod`). Проверка — модель `_perm` + critical-пункты «не сломать
  доступ/приложение».

Анти-ИИ: доказательство из вывода, 2 контрольных вопроса на этап (банк по образцу
`defense_banks`), ловушка-файл «инструкция для ИИ», `guard` (блок вставки). Критические пункты
проверяются после каждой изменяющей команды.

Движок: общий `lab_task.py` (этапы, critical, proof, defense) — как у №6–11.

## Блок B — две задачи «Python + sqlite3: анализ готовой таблицы»

Онлайн-редактор + Pyodide (`sqlite3` уже загружается, `public/js/python-worker.js`). Студенту
даётся **готовая БД** (seed-скрипт персонализирован, та же схема и у сервера для перепроверки).
Программа читает БД, считает аналитику, печатает в заданном формате. Проверка — сверка stdout
на основном и **скрытом** наборе (нормализация вывода, как `python-basics-check`); правила кода
(`forbid`/`require`) по образцу python-course.

- **B1. «Отчёт по продажам».** Таблица `sales(id, day TEXT, product TEXT, qty INT, price
  REAL)`. Вывести: выручку по дням (сорт.), топ-N товаров по выручке, средний чек. N — из seed.
- **B2. «Журнал входов».** Таблица `logins(ts TEXT, user TEXT, ok INT, ip TEXT)`. Вывести: по
  пользователю число входов/неудач и долю успеха; IP с ≥K неудачами за ≤M минут (брутфорс),
  сорт. K, M — из seed.

Средняя сложность: группировка, сортировка, временное окно, форматирование. Генерация эталонов
и данных — скриптом (как python-course/build.py): пишем решение + входные наборы, получаем
ожидаемый вывод.

## Блок D — анализ журналов: нежелательные входы и утечки паролей

Студенту даётся набор **лог-файлов** в песочнице (как в №8): `auth.log` (SSH — входы и
неудачи, время в UTC), `access.log` (nginx, `+0500`, прокси и `X-Forwarded-For` — реальный
клиент последний), `app.log` (журнал приложения). Нужно написать **терминальную программу на
Python** (онлайн-редактор + Pyodide; файлы лежат в рабочем каталоге запуска), которая читает
журналы, анализирует и печатает в заданном формате:

- **D1. Нежелательные входы.** Выявить и вывести: успешные SSH-входы, которых быть не должно —
  вход **root**, входы **заблокированных/уволенных** учёток (список из варианта), входы с
  **IP из чёрного списка** и источники **брутфорса** (≥ K неудач за ≤ M минут). Для каждого —
  «кто · откуда (реальный IP с учётом XFF) · когда · признак». Сортировка задана.
- **D2. Утечки паролей/секретов в журналах.** Найти строки, где в открытом виде оказались
  пароль/токен — напр. `?password=…`, `pwd=…`, `token=…`, `Authorization: Basic …` в URL
  `access.log` или в `app.log`. Вывести учётку и засветившийся секрет (учебно; при желании —
  маскировать всё, кроме первых символов). Это демонстрирует, почему секреты не должны
  попадать в журналы.

Персональные значения из seed: чёрный список IP, список заблокированных/уволенных учёток,
пороги K/M, набор «засветившихся» строк. Ловушки как в №8: подставные строки без корректных
полей, прокси/XFF (реальный клиент — последний адрес), строка-«инструкция для ИИ».

Проверка — авто: сверка вывода на основном и **скрытом** наборе журналов (нормализация
вывода); правила кода (`forbid`/`require`). Генерация журналов и эталонов — скриптом
(переиспользует идеи генератора №8 `ctf/logs/generate_logs.py`).

> Вариант: тот же анализ можно оформить как **терминальное** задание (grep/zgrep/awk в
> эмуляторе, ответы с доказательством из вывода — как №8/№9) вместо Python-программы. По
> умолчанию в плане — Python-программа (единообразно с блоком B, проще авто-проверка по выводу).

## Блок C — поиск и исправление ошибок (4 запуска → авто-сдача)

**Переиспользуем ровно механику баг-программ финала** (`src/lib/exam/bugs.js`,
`scripts/exam/build-bugs.py`, контент `content/exam/bugs/`): N запусков, одна сдача, 4-й запуск
блокирует задание и сдаёт его код, вердикт студенту не показывается; кнопка «Отправить» тоже
есть. По запросу: **лимит = 4 запуска**.

- Программы **50–60 строк** каждая, 4–5 штук в банке; студенту — подмножество (напр. 3) по
  варианту. Эталоны (исправленные) — `scripts/exam/solutions/bugs/`, собираются
  `build-bugs.py`.
- **Виды ошибок (с упором на работу с данными), ловушки — чтобы не бросались в глаза:**
  1. агрегация по неверному ключу (группировка не по тому полю);
  2. off-by-one в срезах/диапазонах дат (`<=` vs `<`, индекс);
  3. mutable default argument (накопление между вызовами);
  4. целочисленное деление / потеря дробной части / деление на ноль на пустых данных;
  5. перезапись в dict (`=` вместо `+=` — затирает сумму);
  6. неверный компаратор сортировки (строка вместо числа);
  7. сравнение разных типов (строка из БД vs число);
  8. граница окна фильтра (пропускает/лишнее);
  9. парсинг строки (split по не тому разделителю, неверный индекс);
  10. накопление float / округление денег.
- Ловушки: программа выглядит рабочей, падает/врёт только на части данных или на краях;
  тесты скрытые; verdict скрыт; автозапуск Pyodide до `/run`, чтобы сбой загрузки не тратил
  запуск.
