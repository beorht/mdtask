# Админ-панель: системная причёска интерфейса (UI-рефакторинг)

*Запрошено 2026-11-02. Основано на `docs/admin_panel_update/mdtask-admin-frontend-architecture.md`
(разбор в чате) и на фактическом коде. Применяется поэтапно по «давай». Ничего не
деплоится, пока идут занятия/контрольные.*

## Цель

Не переписывать админку (остаётся Express + EJS + vanilla JS, server-rendered), а системно
причесать оболочку, навигацию и повторно используемые UI-паттерны. Сохранить все URL,
серверные контракты, правила статусов (в `admin-data.js`) и границу «админка не тянет
студенческие стили».

## Поправки к исходному документу (сверено с кодом 2026-11-02)

Документ местами описывает как «цель» то, что уже сделано, и наоборот:

1. **Токены уже есть.** `public/css/admin.css` — зрелая дизайн-система на `:root` (цвета,
   тени `--a-shadow-*`, радиусы `--a-radius*`, 8px-сетка отступов, шрифты, `--a-ease`) с
   полным override под `:root[data-theme="dark"]`. Отдельный «tokens.css» (§10.3 документа)
   создавать **не нужно** — этап «определить токены» считать выполненным.
2. **`admin.js` богаче, чем в документе.** Кроме перечисленного там, он уже обслуживает:
   `data-theme-choice` (радиокнопки выбора темы), `tr[data-href]` (кликабельные строки),
   loading-state на `form[method="post"]` с кнопкой `.a-btn`, `data-review-form` (подсказки
   по вердикту + Ctrl/⌘+Enter = сохранить), `data-assignment-form` (переключение
   групповое/индивидуальное), фокус поиска по `/`, навигацию стрелками в живом поиске.
   **Дробить `admin.js` на модули (§10.2) — отложить:** сборки нет, выгода мала, риск для
   рабочего кода реальный.
3. **CSS/JS не дробить на файлы (§10.2–10.3).** Нет бандлера → это даёт лишние HTTP-запросы
   (или цепочку `@import`) и риск двойной инициализации. Держать единые `admin.css`/`admin.js`,
   наводить порядок **внутри** (секции-баннеры).
4. **Навигация в документе (§5) идеализирована.** В реальном `sidebar.ejs` группа тренажёров
   **без подписи**, а контрольные (`exam`, `web-exam`) лежат в той же группе. Это и есть
   предмет улучшения, а не текущее состояние.
5. Таблица URL в документе не включает вложенные маршруты, которые тоже рендерят страницы:
   `/admin/trainer/:studentId/:exerciseId`, `/admin/ib/terminal/:id`, `/admin/ib/lab/:task/:id`,
   `/admin/html|css|python-course|js-course|emmet/students/:id` (+ `.../reset`). Учитывать.
6. `views/admin/error.ejs` (404/500 внутри админки) — часть «состояний», в документе не назван.

## Контракт `data-*` (трогать разметку — сохранять эти атрибуты)

`admin.js` завязан на: `data-sidebar-toggle`, `data-sidebar-close`, `data-theme-toggle`,
`data-theme-choice`, `data-dropdown` / `data-dropdown-toggle` / `data-dropdown-menu`,
`data-flash` / `data-flash-close`, `data-confirm` / `data-confirm-dialog` /
`data-confirm-title` / `data-confirm-text` / `data-confirm-ok`, `data-autosubmit`,
`data-live-search` / `data-search-results`, `data-review-form` / `data-verdict-hint` /
`data-primary-submit` / `data-checked` / `data-current-verdict`, `data-assignment-form` /
`data-target-type` / `data-target-group` / `data-target-individual`, `tr[data-href]`.
Любая переразметка обязана их сохранить.

## Ограничения (из CLAUDE.md и проекта)

- Все URL и серверные контракты неизменны без отдельного согласования.
- Правила статусов/дедлайнов остаются в `admin-data.js` и сервисах, не в браузере.
- Статус — всегда иконка + текст (не только цвет).
- Без внешних CDN/шрифтов (аудитории без интернета; есть тест, проверяющий это).
- Реальные данные (`data/`, `uploads/`, `backups/`) не трогать.
- После **каждого** этапа — полный `npm test` (маршрутные тесты проверяют текст/разметку и
  коды 200/423, напр. `/Доступ к темам/`, `/Алиса/`).
- Предметная специфика (сигналы ИБ, матрицы) не стирается общим UI.

  - **Исправлен латентный баг `admin.js`:** обработчик `form[data-confirm]` отправлял через
    `form.submit()`, который **терял** `formaction` и нажатую кнопку — для формы замков с
    двумя кнопками (`Сохранить`→`/set`, `Снять`→`/clear`) это сломало бы отправку. Теперь
    через `form.requestSubmit(submitter)` (как у формы проверки), с откатом на `form.submit()`.
    Существующие одно-кнопочные `data-confirm` формы (занятия Emmet, «Сбросить» у предметов)
    не затронуты.

    (`a-stats`, `a-table`, `partials/*`).
  - **Регрессия:** полный JS-набор `node --test tests/` — **343/343** зелёные.

## Критерии готовности (на весь рефакторинг)
- Все разделы и действия доступны; URL и серверные контракты целы.
- Одинаковые элементы выглядят и ведут себя одинаково; навигация понятна без знания имён файлов.
- Фильтры сохраняют значения и не обходят серверную валидацию.
- Пустые состояния, ошибки, подтверждения — единообразны.
- Работает на десктопе/планшете/телефоне; без внешних CDN.
- `npm test` зелёный после каждого этапа.
