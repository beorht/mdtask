# Курс «JavaScript: от синтаксиса до DOM» — план

Запрошено 27.10.2026: «составь полный образовательный план начиная с синтаксиса до взаимодействия с веб-сайтом через
DOM, составь практический и теоретический материал по данной тематике». Это план; применяется после «давай».

## Что уже есть в предмете JavaScript

- **Банк задач** — 12 задач без проверки (переменные, арифметика, условия, циклы, функции, «модули»).
- **Задания со сдачей группы web-2** (архивом, проверяет преподаватель): «Теория: DOM и объект document»,
  «Теория DOM» части 1–8, задачи 1–12 по DOM (приветствие, счётчик кликов, переключатель темы, список покупок, отметка
  и удаление пунктов, счётчик символов, таблица из массива, поиск и сортировка таблицы, форма регистрации, вкладки и
  аккордеон, список дел). По задачам уже 9–10 сдач — **их не трогаем**, сданные работы остаются.
- **Общие задания «Объекты и словари»** (15 задач) — сейчас видны и в JavaScript.

## Идея курса

Курс устроен как «Начальный Python» и предметы HTML/CSS: **модули → уроки**, в уроке **теория** (с примерами, которые
запускаются прямо на странице, «▶ Запустить») и **практика** (задачи с автопроверкой, кнопки «Теория / Практика» —
общие `.topic-btn`). Уроки открываются по порядку. Язык — русский, без уровней сложности в текстах. Практика с упором на
алгоритмы в начале и на работу со страницей в конце; задачи от урока к уроку сложнее.

Два вида практики:

| Модули | Что пишет студент | Как проверяется |
| --- | --- | --- |
| 1–5 (язык) | программу, которая читает ввод и выводит ответ в консоль | как в курсе Python: код выполняется **в браузере студента** (Web Worker, без доступа к странице, лимит времени), ввод — функция `input()` (строки теста), вывод — `console.log`; сервер сравнивает вывод с эталоном на открытых и **скрытых** тестах; правила кода (`forbid` / `require`: например, нельзя `.sort(`, `Math.max`, обязательно `function`, `=>`, `class`) сервер проверяет по тексту без выполнения |
| 6 (DOM) | `script.js` к **готовой разметке** (HTML видно во вкладке «Разметка», как в CSS) | разметка + скрипт студента и разметка + эталонный скрипт выполняются в двух изолированных iframe; к обоим применяется один **сценарий** (нажать кнопку, ввести текст, нажать Enter, отметить флажок, подождать таймер…), после каждого шага сравнивается состояние страницы: элементы, текст, атрибуты, классы, значения полей, видимость, `localStorage`. Есть **скрытые сценарии** с другими данными — «зашить» ответ под образец не выйдет. Слева «Ваша страница» и «Как должно работать» — с обоими можно взаимодействовать руками |

Защита (как в HTML/CSS/Emmet): вставка в редактор запрещена и записывается, учёт «набрано руками» (готовые куски,
автонабор, копия эталона), уходы со страницы, одинаковые решения у разных студентов, «Выбрать 4 студентов» в админке
`/admin/javascript-course`.

## Как будет устроено (кратко)

- Содержание генерируется скриптом, как в курсе Python: урок — файл с теорией, задачами, **эталонным решением** и
  тестами (`scripts/js-course/lessons/*.js`); сборка запускает эталон и записывает ожидаемый вывод и сценарии; тест
  проверяет, что каждый эталон проходит свои тесты и соблюдает правила, а теория не содержит строки эталона.
- Модули 1–5: запуск в Web Worker браузера, `input()` / `console.log`, лимит времени; сервер сравнивает вывод.
- Модуль 6: проверка сценариями в двух iframe (страница студента и эталон) — по образцу `public/js/css-check.js`.
  Сервер без браузера страницу не выполнит: он проверяет правила по тексту (например, «обязательно
  `addEventListener`», «нельзя `innerHTML`» в задаче про безопасный вывод) и записывает попытку; признаки «не руками» —
  сигналы преподавателю.
- Админка `/admin/javascript-course`: матрица «студент × урок», код попыток, журнал, сигналы, «Выбрать 4 студентов».
- Предмет JavaScript: курс — основное содержимое (как Python); банк задач — переносится в уроки по теме (как в Python).
