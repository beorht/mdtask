## Что это

Тренажёр урока вёрстки (группа WEB). Две части:

1. **Emmet** — у каждого студента свой случайный набор из 10 работ из банка в 30. Слева образец (HTML и его вид в
   браузере), справа редактор «в клетку»: нужно подобрать сокращение Emmet и развернуть его `Tab`. HTML, набранный
   руками, не засчитывается.
2. **Контейнеры** — теория «id, class и контейнеры», затем 10 одинаковых для всех заданий на HTML; образец не код, а
   вид («Браузер» / «Схема» коробками).

Панель преподавателя: матрица «студент × работа», попытки, время, ручной ввод/вставки/уходы, код решений, CSV,
«Завершить / Открыть занятие».

## Чем отличается от mdtask (главное для переноса)

| | EmmetEmulator | mdtask |
|---|---|---|
| Сборка | Vite 8, ES-модули, `?raw`, импорт JSON | без сборки, CommonJS, файлы из `public/` |
| Редактор | CodeMirror 6 (+ `emmet` 2.4) | CodeMirror 5.65.16 из `public/vendor/` |
| Сервер | `node:http`, JSON-файлы, статистика в памяти | Express 5 + SQLite (`better-sqlite3`) |
| Вход | личный ключ `stWeb-###`, Bearer | аккаунты mdtask, сессия |
| Проверка | на клиенте, сервер верит статусу | ответы перепроверяет сервер (SQL, Python-тесты, IB) |
| Интернет | шрифты из `@fontsource` в сборке | ничего внешнего, всё в `public/vendor/` (тест) |

## План (вариант D из `docs/emmet/08-porting-guide.md`: клиент целиком, сервер — под mdtask)

1. **Клиент — заранее собранный бандл.** В EmmetEmulator собрать клиент студента одним файлом (Vite, `base`
   под `/subjects/emmet/`), положить в `public/vendor/emmet/<версия>/` (JS + CSS + шрифты), как Pyodide и CodeMirror:
   без сборки в mdtask и без интернета. CodeMirror 6 и `HandwrittenTracker` (защита от ручного ввода) остаются как
   есть — переписывать на CodeMirror 5 нельзя без потери защиты. Скрипт сборки — `scripts/vendor/emmet.sh`
   (EmmetEmulator → `public/vendor/emmet/`).
2. **Вход.** Убрать экран ввода ключа и `SavedKey`: страница mdtask `/subjects/emmet` (`requireAuth`), клиент берёт
   студента из сессии (cookie, тот же адрес). `Api.js` — без Bearer, адреса `/subjects/emmet/api/*`.
3. **Сервер** (`src/routes/emmet.js`, `src/lib/emmet/`, монтировать до `student`):
   - `GET /api/me` — студент, план (10 личных + 10 общих), решённые;
   - `POST /api/events` — `open`, `attempt`, `paste`, `away` (тот же контракт, `docs/emmet/03-api.md`);
   - `GET /api/session` — открыто ли занятие для группы.
   Хранение в SQLite вместо `stats.json`: `emmet_assignments (student_id, ids JSON, created_at)`,
   `emmet_progress (student_id, exercise_id, … поля из docs/emmet/04-data-model.md)`, `emmet_events` (журнал).
   Набор: `createAssignment` (3/2/5 по уровням, `crypto.randomInt`) переносится в `src/lib/emmet/assignment.js`.
4. **Перепроверка на сервере.** Сейчас статус присылает браузер. В mdtask: на сервере развернуть эталон
   (`emmet` — нужен как зависимость, ставится вместе с проектом заранее, без `npm ci` на сервере) и сравнить
   структуру кода попытки с эталоном. Для разбора HTML на сервере нужен DOM-парсер — выбрать без новых пакетов
   (простой токенайзер тегов/атрибутов по правилам `ValidationService`) или добавить пакет и положить в
   `node_modules` заранее. Засчитывать по серверной проверке; признак «ручной ввод» — по событию клиента.
5. **Данные заданий** (`exercises.json`, `containers.json`) — в `content/emmet/`. Эталоны (`emmetExpression`) не
   отдавать в браузер целиком, если возможно: клиенту нужен `expectedHtml` для образца — это и есть то, что видит
   студент, а сокращение — нет.
6. **Уровни трудности не показывать** (правило mdtask): убрать бейдж уровня («ПРОСТАЯ» и т. п.) из условия у
   студента; в админке — только черта сложности в шапке матрицы без слов. Тексты заданий проверить.
7. **Меры против нейросети** (как в IB и контрольной WEB): уже есть — запрет вставки и перетаскивания, «набор
   куском» (`bulk`), учёт ручного HTML, уходы со страницы, запрет копирования образца. Добавить: события в журнал
   mdtask, сигналы и «Выбрать 4 студентов» для устной проверки в админке.
8. **Админка** `/admin/emmet` (в стиле `admin.css`, не отдельная страница Emmet): сводка, матрица с вкладками
   «Emmet / Контейнеры», карточка студента (код решений, «Новый набор», «Сбросить»), CSV, «Завершить / Открыть
   занятие» для группы. Ключи и печать карточек не нужны — вход по аккаунтам mdtask.
9. **Видимость:** группа WEB и TEST (`hasFullAccess`); карточка на главной и пункт в меню; блокировка контрольной
   (`examLockFor`) закрывает и Emmet.
10. **Дизайн.** Страница тренажёра — в стиле «Тетради» (`docs/emmet/design/`), согласовать со светлой темой сайта
    (`docs/todo/2026-10-26-light-theme-tetrad.md`). Тёмной темы у тренажёра нет — решить: тренажёр всегда светлый
    или сделать тёмный вариант.
11. **Тесты** (`node:test`, `DB_PATH=:memory:`): выдача набора, события, чужая работа → 400, закрытое занятие,
    серверная перепроверка на эталонах всех 40 заданий (каждый эталон проходит, «почти верные» — нет), нет внешних
    адресов (`tests/routes/vendor.test.js`). Тесты валидатора из EmmetEmulator (`tests/validation.test.js`, Vitest
    + happy-dom) — перенести логику или запускать отдельно.
12. **Документация:** `CLAUDE.md` (раздел о тренажёре), `docs/STRUCTURE.md`.
