# IBEmulator

> **Встроено в mdtask** как раздел «Информационная безопасность» (`/subjects/ib`). Код перенесён один в один из отдельного репозитория IBEmulator; внутри mdtask терминал открывается на странице задания, а backend (`server/app.py`) запускается мостом `server/bridge.py` из Node (см. `src/lib/ib-bridge.js` и `src/routes/ib.js` в корне mdtask). Пути по умолчанию считаются от корня mdtask (`data/mdtask.db`, `data/ctf/caesar/`). Автономный запуск (`python3 ib/server/app.py`) по-прежнему работает.

Платформа-эмулятор терминала для практических работ студентов направления «Информационная Безопасность»: веб-терминал в браузере, настоящий backend на реальных данных студентов, лабораторные задания с автоматической проверкой.

## Быстрый старт

```bash
python3 ib/server/app.py
```

Backend поднимается на `http://localhost:8088` (без сторонних зависимостей — только стандартная библиотека Python 3).

Открыть терминал: **http://localhost:8088/prototype/terminal-lab.html**

По умолчанию backend читает реальную базу `mdtask` (`/home/thinklinux/Projects/mdtask/data/mdtask.db`) и песочницы студентов (`/home/thinklinux/Projects/mdtask/data/ctf/caesar/`). Переопределить пути можно переменными окружения:

```bash
MDTASK_DB=/path/to/mdtask.db CTF_CAESAR_DIR=/path/to/sandboxes PORT=8088 python3 server/app.py
```

## Терминал (`prototype/terminal-lab.html` + `server/app.py`)

Реальный веб-терминал: вход по логину/паролю (та же БД, что использует mdtask), после входа — полноценный шелл с историей команд.

**Поддерживаемые команды:** `ls [-a] [путь]`, `cd [путь]`, `pwd`, `cat <файл>`, `find [путь]`, `whoami`, `id`, `date`, `echo`, `sqlite3 [файл] [SQL]`, `clear`, `help`, `logout`.

**`sqlite3`** (`server/sqlite_shell.py`) — упрощённая эмуляция одноимённой утилиты. SQL выполняет настоящий движок SQLite, так что язык поддерживается полностью (JOIN, CTE, транзакции, триггеры и т.д.). Результаты выводятся таблицами в терминале (`.mode box` по умолчанию, также `table`, `column`, `markdown`, `list`, `csv`, `tabs`, `line`, `json`). Dot-команды: `.help`, `.tables`, `.schema`, `.indexes`, `.dump`, `.mode`, `.headers`, `.nullvalue`, `.open`, `.read`, `.timer`, `.show`, `.databases`, `.version`, `.quit`. Без SQL-аргумента включается интерактивный режим с приглашением `sqlite>` (многострочный ввод до `;`, `Ctrl+C` сбрасывает недописанное выражение), с аргументом — запрос выполняется один раз. Ограничения песочницы: файлы БД только внутри домашнего каталога, `ATTACH`/`VACUUM INTO` запрещены, лимиты на размер БД (~10 МБ), время запроса (3 с) и вывод (1000 строк). У каждого студента есть учебная база `~/Documents/inventory.db`.

**Удобства ввода:** история команд (↑/↓, как в bash), `Ctrl+L` — очистка экрана, `Ctrl+C` — отмена введённой строки, блокировка повторного ввода во время выполнения команды.

**Авторизация** — основной пароль студента (`users.password_hash/salt`, scrypt — совместимо 1-в-1 с хешированием в mdtask, `src/lib/password.js`). Пароль задания №3 для входа не подходит — он открывает защищённую базу.

**Песочница студента** — реальные файлы на диске, строго ограниченные домашним каталогом (защита от path traversal проверена на `cat ../../../etc/passwd` и аналогах).

## Задание №3: пароль от защищённой базы, зашифрованный Цезарем

Цель студента: найти пароль от защищённой базы данных `~/Documents/backup/company_data.db` (вымышленные «секретные» данные компании: сотрудники, учётные записи, документы) и открыть её командой `sqlite3`. Терминал запрашивает пароль (`Password:`, ввод скрыт и не попадает в историю); при верном пароле база расшифровывается в память и задание отмечается решённым (`ctf_caesar_secrets.solved=1`). Без пароля содержимое недоступно: файл зашифрован (`server/protected_db.py` — учебный формат: scrypt + XOR с потоком SHAKE-256), `cat` показывает «двоичный файл».

Генератор: `ctf/caesar-secret/generate_challenge.py`.

```bash
python3 ctf/caesar-secret/generate_challenge.py --group IB
python3 ctf/caesar-secret/generate_challenge.py --group IB --force   # перегенерировать все пароли/пути
python3 ctf/caesar-secret/generate_challenge.py --group IB --variant path --force   # усложнённый вариант
```

**Варианты задания** (`--variant`):
- `password` (по умолчанию) — в скрытом файле зашифрован сам пароль
- `path` — усложнённый: в скрытом файле зашифрован **путь** к другому файлу (например, `~/.mkmro/.pyxdmyxpsq/.myxp-mkmro` → `~/.cache/.fontconfig/.conf-cache`), а уже в нём пароль открытым текстом. Файл с паролем тоже выбирается из пула и спрятан среди обманок; на студента занимается два уникальных пути. Вариант хранится в `ctf_caesar_secrets.variant`, путь к файлу с паролем — в `password_file_path` (колонки добавляются в существующую БД автоматически)

Сменить вариант уже сгенерированной группе можно только с `--force` (пароли и пути будут выданы заново, старые файлы превратятся в обманки).

Для каждого студента группы создаётся:
- случайный пароль + случайный сдвиг шифра Цезаря (2–25)
- уникальный путь к скрытому файлу (без повторов среди студентов группы — путь назначается `random.sample` по пулу из 116 правдоподобных системных путей в 30 каталогах, `HIDDEN_DIRS`; занятые ранее пути исключаются)
- `.bash_history` с подсказкой: в истории есть переход в каталог со скрытым файлом (`cd ~/<каталог>`, `sudo cp /var/backups/admin-pass.bak .`), но имя файла не названо — в каталоге несколько обманок. История перезаписывается при каждом запуске генератора (детерминированно от студента и пути)
- защищённая база `Documents/backup/company_data.db`, зашифрованная паролем студента (перешифровывается при `--force`; студентам, сгенерированным до её появления, создаётся с уже выданным паролем)
- учебная SQLite-база `Documents/inventory.db` (без пароля) для практики с `sqlite3`
- `TASK.md` — условие задания, единственный файл с описанием в песочнице (студенческая часть `TASK.md` из корня репозитория, без раздела для преподавателя). После правки `TASK.md` перезапустите генератор, чтобы обновить копии у студентов
- стандартный скелет домашнего каталога Linux (`Desktop/`, `Documents/`, `.bashrc`, `.bash_history` и т.п.) + обманки на всех НЕ выбранных путях пула, чтобы реальный файл не выделялся по имени

Подробности и формат данных — в `task/№3.Caesar-hidden-password.md`.

## Чекеры и отчёты (`checks/`)

- `task1_check.sh <student_id> <host> <user> <identity_file>` — проверяет настройку SSH «только по ключу» на удалённом хосте студента
- `task2_check.sh <student_id> <container_name>` — проверяет изоляцию Docker-контейнера (лимиты ресурсов, cap-drop, read-only rootfs, сетевая изоляция)
- `run_all.py students.json` — прогоняет оба чекера по списку студентов, печатает прогресс и выгружает JSON-отчёт

Пример входных данных — `checks/students.example.json`, пример отчёта — `checks/reports/sample_report.json`.

## Админ-панель (`admin-panel/index.html`)

Визуальный дашборд с результатами по заданиям №1/№2: сводная статистика, таблица студент × задание, разворачивающаяся детализация по этапам. Сейчас отображает встроенные демо-данные — для реальных данных нужно подключить к выводу `checks/run_all.py`.

Доступна по адресу `/admin-panel/index.html` на том же backend (`server/app.py`).

## Задания (`task/`)

Пошаговые инфраструктурные инструкции, каждая — отдельный файл `№<номер>.<Название>.md`:

- **№1** — настройка SSH с входом только по ключу
- **№2** — контейнерная изоляция студенческих сессий (Docker/Firecracker, лимиты, снижение привилегий)
- **№3** — пароль от защищённой базы данных, зашифрованный Цезарем (полностью реализовано и протестировано end-to-end)

## Стек

- Backend: Python 3 (стандартная библиотека — `http.server`, `sqlite3`, `hashlib.scrypt`), без внешних зависимостей
- Frontend: чистый HTML/CSS/JS, без фреймворков и сборки
- Данные: читается реальная SQLite-база проекта `mdtask` (`better-sqlite3` на стороне mdtask, `sqlite3` на стороне IBEmulator)
- Чекеры: Bash + Python

## Связанные проекты

- **mdtask** (`/home/thinklinux/Projects/mdtask`) — отдельная учебная платформа (markdown-задания, SQL-тренажёр), владеет основной базой данных студентов (`users`, `ctf_caesar_secrets`). IBEmulator читает и дополняет эту базу, но не является её частью.
