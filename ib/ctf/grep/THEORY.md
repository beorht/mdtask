# Тренажёр grep

`grep` ищет в тексте строки, подходящие под шаблон, и выводит их. Это главный инструмент для работы с журналами
и конфигурацией: за одну команду из тысяч строк остаются нужные. В тренажёре 13 задач; в каждой вы пишете
команду сами, и она проверяется не только на ваших файлах, но и на двух скрытых наборах с тем же устройством.
Поэтому команда должна описывать **правило**, а не перечислять найденные строки.

Примеры ниже — на других файлах и с другими значениями: готовых ответов к задачам здесь нет.

## Как устроена команда

```
grep [КЛЮЧИ] 'ШАБЛОН' ФАЙЛ...
команда | grep 'ШАБЛОН'          # искать в выводе другой команды
```

Шаблон почти всегда берите в **одинарные кавычки**: тогда шелл не трогает `*`, `$`, `\`, `|` и пробелы
внутри него. Несколько `grep` можно соединить конвейером: каждый следующий отбирает строки из вывода
предыдущего (`grep A файл | grep B` — строки, где есть и A, и B).

## Ключи -i и -w

| Ключ | Что делает | Пример |
|---|---|---|
| `-i` | не различать регистр | `grep -i error app.log` найдёт ERROR, Error, error |
| `-w` | совпадение — только отдельное слово | `grep -w cat` найдёт «cat», но не «category» |
| `-x` | совпадение — вся строка целиком | `grep -x 'yes'` |
| `-v` | вывести строки, где совпадения **нет** | `grep -v DEBUG` |
| `-o` | вывести только совпавшие части, каждую с новой строки | `grep -o '[0-9]*'` |
| `-n` | номер строки перед строкой | `grep -n TODO main.py` |

Ключи можно склеивать: `-iw` — то же, что `-i -w`.

## Где кончается слово

Для `-w` и `\b` «слово» — это буквы, цифры и подчёркивание. Значит, `alex` с `-w` не найдётся в `alex2`
и `alex_old` (там слово продолжается), но найдётся в `alex.bak` и `alex:` — точка и двоеточие слово
заканчивают. Если запись может стоять в другом регистре, `-w` нужно сочетать с `-i`.

## Подсчёт: -c

`grep -c 'шаблон' файл` выводит одно число — **сколько строк** подходят (не сколько раз встретился
шаблон: строка с двумя совпадениями считается один раз). Без `-i` регистр важен: `Error` и `error` —
разные шаблоны.

## Инверсия: -v

`-v` переворачивает отбор: остаются строки **без** совпадения. Удобно для «убрать лишнее»:

```
grep -v '^;' php.ini          # без строк, начинающихся с ;
```

## Якоря ^ и $

- `^` — начало строки: `grep '^ERROR'` — строки, которые **начинаются** с ERROR;
- `$` — конец строки: `grep 'sh$'` — строки, которые заканчиваются на sh;
- `^$` — пустая строка.

Без якоря шаблон ищется в любом месте строки — в том числе внутри текста сообщения. Если поле (дата,
ключ) должно стоять в начале, ставьте `^`.

## Классы символов

| Запись | Что совпадает |
|---|---|
| `[abc]` | один из символов a, b, c |
| `[^abc]` | любой символ, кроме a, b, c |
| `[0-9]`, `[a-z]` | диапазон |
| `[[:digit:]]` | цифра |
| `[[:alpha:]]` | буква (и русская, и латинская) |
| `[[:alnum:]]` | буква или цифра |
| `[[:space:]]` | пробел или табуляция |
| `.` | **любой** один символ |

Чтобы найти саму точку, её экранируют: `\.` (или `[.]`). Шаблон `1.2` найдёт и «1.2», и «172», и «1x2».

## Квантификаторы

Квантификатор пишется **после** символа или группы и говорит, сколько раз ему повторяться:

| Запись | Сколько раз | Где работает |
|---|---|---|
| `*` | 0 и больше | везде |
| `+` | 1 и больше | `-E`, `-P` |
| `?` | 0 или 1 | `-E`, `-P` |
| `{3}` | ровно 3 | `-E`, `-P` |
| `{2,4}` | от 2 до 4 | `-E`, `-P` |
| `{3,}` | 3 и больше | `-E`, `-P` |

Ключ `-E` включает «расширенные» шаблоны (ERE): `+ ? { } | ( )` работают без обратной косой черты.
Пример: `grep -E 'id=[0-9]{5}'` — «id=» и ровно пять цифр… или больше: после пяти цифр могут идти ещё
цифры. Если важно, что число кончилось, это надо проверить отдельно (см. «Просмотр вперёд и назад»).

## Диапазоны в квадратных скобках

`[0-9]` — **одна** цифра, а не число. Число из диапазона собирают по разрядам:

```
grep -E ' (1[0-2]|0[1-9]) '      # месяц 01–12
grep -E '^(0[89]|1[0-7]):'        # часы с 08 до 17 в начале строки
```

## Группы и альтернатива

- `(abc)` — группа: к ней применяется квантификатор, `(ab)+` — ab, abab …;
- `a|b` — «или»: `grep -E 'WARN|ERROR'`;
- группы можно вкладывать: `grep -E '^(GET|POST) /api/'`.

Пример — число от 0 до 99 без ведущего нуля: `([1-9]?[0-9])`. Обратите внимание, что такое правило
не запрещает цифрам стоять **вокруг** найденного числа — об этом следующий раздел.

## Просмотр вперёд и назад (-P)

Ключ `-P` включает шаблоны Perl: в них есть `\d` (цифра), `\w` (буква, цифра или _), `\s` (пробел) и
**проверки окружения**, которые смотрят на соседние символы, не включая их в совпадение:

| Запись | Смысл |
|---|---|
| `(?=X)` | дальше идёт X |
| `(?!X)` | дальше **не** идёт X |
| `(?<=X)` | перед этим местом стоит X |
| `(?<!X)` | перед этим местом **не** стоит X |

```
grep -oP '(?<![\d.])\d{3}(?![\d.])' f       # трёхзначные числа, не входящие в более длинные числа или версии
grep -oP 'port=\K\d+' f                      # \K — «всё, что левее, не выводить»
```

С `-o` проверки особенно полезны: выводится только найденное, а окружение лишь проверяется.

## Формат access.log

Строка журнала nginx в формате combined:

```
203.0.113.9 - - [18/Nov/2026:10:15:02 +0500] "GET /index.html HTTP/1.1" 404 512 "-" "curl/8.5.0"
адрес клиента        время запроса          запрос (в кавычках)         код  размер  откуда  программа
```

Числа встречаются в нескольких полях: в запросе, в размере, во времени. Чтобы найти **поле**, опирайтесь
на то, что стоит рядом с ним — кавычки, пробелы, скобки.

## Поля через двоеточие

`/etc/passwd` — одна учётная запись на строку, 7 полей через `:`:

```
имя:x:UID:GID:комментарий:домашний_каталог:оболочка
alice:x:1000:1000:Alice:/home/alice:/bin/bash
```

Поле «что угодно, кроме двоеточия» — `[^:]*`. Например, третье поле — это `^[^:]*:[^:]*:` и затем
само значение. Последнее поле — то, что перед концом строки `$`.

## Конвейер из grep

Сложное условие часто проще записать несколькими `grep` подряд:

```
grep 'Accepted' auth.log | grep -v '10\.0\.' | grep -o 'for [a-z]*'
```

Первый отбирает строки, второй выкидывает лишние, третий вырезает нужную часть (`-o`).

## Рекурсивный поиск: -r, -l, --include

| Ключ | Что делает |
|---|---|
| `-r` | искать во всех файлах каталога и подкаталогов |
| `-l` | вывести только **имена** файлов, где есть совпадение |
| `-L` | имена файлов, где совпадения нет |
| `--include='*.ini'` | искать только в файлах с таким именем |
| `--exclude='*.bak'` | пропустить такие файлы |

```
grep -rl 'listen' --include='*.yml' /etc/myapp
```

Маску в `--include` берите в кавычки, иначе шелл раскроет её сам.

## Контекст: -A, -B, -C

- `-A N` — ещё N строк **после** найденной;
- `-B N` — N строк **перед** ней;
- `-C N` — по N строк с обеих сторон.

Если группы контекста не соприкасаются, grep разделяет их строкой `--`. Убрать разделитель —
`--no-group-separator`. Если две найденные строки близко, их контексты сливаются в одну группу.

## Почтовые адреса

Адрес — `имя@домен`. В имени бывают буквы, цифры и `. _ % + -`; домен — части через точку. Подвохи:

- `user@example.com.evil.net` — домен на самом деле `evil.net`, хотя в начале написано «example.com»;
- `user@mail.example.com` — это поддомен, не сам `example.com`;
- в конце предложения после адреса бывает точка — она не часть адреса.

Поэтому после домена надо проверить, что он действительно кончился: дальше нет буквы, цифры, дефиса и нет
«точки с продолжением» (см. проверки `(?!…)`).

## Обратные ссылки

`\1` — «то же самое, что совпало с первой группой в скобках», `\2` — со второй:

```
grep -E '(ab)-\1'          # ab-ab
grep -E '^(.)(.).?\2\1$'   # палиндромы из 4–5 символов
```

С `-i` обратная ссылка тоже сравнивается без учёта регистра. Обратной ссылкой удобно требовать, чтобы
**одинаковым** было что-то, что заранее неизвестно: одно и то же слово, один и тот же разделитель.

## Шаблоны из файла: -f и -F

- `-f ФАЙЛ` — взять шаблоны из файла, по одному в строке; строка подходит, если подходит **любой** шаблон;
- `-F` — шаблоны — это просто строки, без специальных символов: точка — это точка;
- `-w` и `-x` работают и вместе с ними.

```
grep -Ff stopwords.txt text.txt
```

Внимание: пустая строка в файле шаблонов совпадает с **любой** строкой.

## Как проверять себя

1. Посмотрите на данные: `head`, `grep -n` по ключевому слову, `wc -l`.
2. Напишите шаблон и сравните с контрольной точкой в условии (число строк и первая строка).
3. Подумайте, на каких строках шаблон ошибётся: другое число в том же месте, то же слово в другом поле,
   другой регистр, соседние символы. Проверочные наборы как раз из таких строк.
