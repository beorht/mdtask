# Поиск и правка конфигурационных файлов: find, grep, sed

Администратор сервера постоянно делает одно и то же: **находит** файл с настройкой, **смотрит**
текущее значение и **меняет** его. На серверах часто нет графического интерфейса, а иногда нет
и привычного редактора. Поэтому важно уметь менять файл одной командой, не открывая его. Это
быстрее, легко повторяется на десятке серверов и подходит для скриптов автоматизации.

В этом материале разбираются три инструмента:

| Команда | Что делает | Вопрос, на который отвечает |
|---|---|---|
| `find` | ищет **файлы** по имени, типу, размеру, дате, правам | «Где лежит файл?» |
| `grep` | ищет **строки** внутри файлов | «В каком файле и в какой строке параметр?» |
| `sed` | **изменяет** строки в потоке или прямо в файле | «Как поменять значение, не открывая файл?» |

## 1. Где живут настройки в Linux

Почти все настройки системы и сервисов лежат в каталоге **`/etc`**. Обычно у каждого сервиса
свой подкаталог:

| Сервис | Каталог | Главный файл |
|---|---|---|
| SSH-сервер | `/etc/ssh/` | `sshd_config` (буква **d** — daemon, сервер) |
| SSH-клиент | `/etc/ssh/` | `ssh_config` — настройки команды `ssh`, а не сервера! |
| Apache | `/etc/apache2/` | `apache2.conf`, порты — `ports.conf` |
| MariaDB/MySQL | `/etc/mysql/` | `my.cnf` и файлы в `mariadb.conf.d/` |
| PHP | `/etc/php/<версия>/<режим>/` | `php.ini`, отдельный для `apache2` и `cli` |

Что ещё важно знать о структуре:

- **Каталоги `*.d`** (`sshd_config.d/`, `conf.d/`, `mariadb.conf.d/`). Главный файл подключает
  все файлы из такого каталога (директивы `Include`, `IncludeOptional`, `!includedir`).
  Значит, параметр может быть задан **не в главном файле**.
- **`*-available` и `*-enabled`** (Apache). В `sites-available/` лежат все сайты, в
  `sites-enabled/` — **символические ссылки** на включённые. Apache читает только `*-enabled`.
- **Кто побеждает при повторе.** У разных программ по-разному. `sshd` берёт **первое**
  встреченное значение. Apache, MariaDB и PHP — **последнее**.
- **Не рабочие копии.** Шаблоны (`/usr/share/...`), примеры (`/usr/share/doc/...`) и
  резервные копии (`*.bak`, `*.old`, `/var/backups/`) — тоже конфиги, но сервис их не читает.
  Менять нужно рабочий файл.

## 2. Права доступа и sudo

Файлы в `/etc` принадлежат пользователю **root**. Права видно в `ls -l`:

```
-rw-r--r-- 1 root root 3267 ноя  2  2025 /etc/ssh/sshd_config
 │  │  │
 │  │  └── остальные (вы): r-- — только чтение
 │  └───── группа root: r--
 └──────── владелец root: rw- — чтение и запись
```

- Прочитать такой файл может любой пользователь, а **изменить — только root**. Поэтому
  команды, которые пишут в `/etc`, запускают через **`sudo`**: `sudo sed -i ...`.
- Некоторые файлы закрыты даже для чтения (`-rw-------`, например ключи и пароли). Чтобы
  прочитать или найти внутри них что-то, тоже нужен `sudo`.
- **Ловушка с перенаправлением.** Знак `>` обрабатывает ваш шелл, а не `sudo`:

  ```bash
  sudo echo "Port 2222" >> /etc/ssh/sshd_config      # Отказано в доступе
  echo "Port 2222" | sudo tee -a /etc/ssh/sshd_config  # правильно: пишет tee от имени root
  ```

## 3. find — поиск файлов

```
find [где искать] [условия] [действие]
```

- **Где искать** — один или несколько каталогов. Без указания — текущий каталог (`.`).
- **Условия** (тесты) проверяются для каждого файла слева направо.
- **Действие** — что сделать с найденным. По умолчанию `-print`, то есть вывести путь.

### Проверки по имени и пути

| Ключ | Что проверяет | Пример |
|---|---|---|
| `-name 'шаблон'` | имя файла (без каталогов) по маске | `find /etc -name 'sshd_config'` |
| `-iname 'шаблон'` | то же без учёта регистра | `find / -iname 'readme*'` |
| `-path 'шаблон'` | полный путь по маске (`*` захватывает и `/`) | `find /etc -path '*apache2*/*.conf'` |
| `-regex 'выражение'` | полный путь по регулярному выражению | `find /etc -regex '.*\.\(conf\|cnf\)'` |

Маски: `*` — любые символы, `?` — один символ, `[abc]` — один из перечисленных.
**Шаблон всегда берите в кавычки**: `-name '*.conf'`. Без кавычек шелл может сам подставить
файлы из текущего каталога, и `find` получит совсем не тот шаблон.

### Проверки по типу, размеру, времени и правам

| Ключ | Что проверяет | Пример |
|---|---|---|
| `-type f` / `d` / `l` | обычный файл / каталог / символическая ссылка | `find /etc/apache2 -type l` |
| `-size +N` / `-N` | размер больше / меньше N (единицы: `c` байты, `k`, `M`, `G`) | `find /var/log -size +1M` |
| `-empty` | пустой файл или каталог | `find /tmp -empty` |
| `-mtime -N` / `+N` | изменён меньше / больше N дней назад | `find /etc -mtime -7` |
| `-mmin -N` | изменён меньше N минут назад | `find /etc -mmin -30` |
| `-newer файл` | изменён позже указанного файла | `find /etc -newer /etc/hostname` |
| `-user имя` | владелец файла | `find /home -user student` |
| `-perm 600` | права ровно 600 | `find /etc -perm 600` |
| `-perm -4000` | установлены **все** указанные биты (здесь SUID) | `find /usr/bin -perm -4000` |
| `-perm /022` | установлен **хотя бы один** из битов | `find /etc -perm /022` |

### Глубина поиска

| Ключ | Что делает |
|---|---|
| `-maxdepth N` | не спускаться глубже N уровней (`1` — только содержимое самого каталога) |
| `-mindepth N` | не показывать то, что ближе N уровней |

Эти ключи пишут **сразу после каталога**, до остальных условий: `find /etc -maxdepth 2 -name '*.conf'`.

### Логика: И, ИЛИ, НЕ

| Запись | Значение |
|---|---|
| `усл1 усл2` или `усл1 -a усл2` | И — оба условия |
| `усл1 -o усл2` | ИЛИ |
| `! усл` или `-not усл` | НЕ |
| `\( ... \)` | скобки для группировки (экранируются от шелла) |

```bash
find /etc \( -name '*.conf' -o -name '*.cnf' \) -type f    # файлы .conf или .cnf
find /etc -name '*.conf' ! -path '*/ssl/*'                  # все .conf, кроме тех, что в ssl
```

### Действия

| Ключ | Что делает |
|---|---|
| `-print` | вывести путь (по умолчанию) |
| `-ls` | подробная строка, как у `ls -l` |
| `-printf 'формат'` | свой формат: `%p` путь, `%f` имя, `%s` размер, `%m` права, `%u` владелец, `%l` цель ссылки, `\n` перевод строки |
| `-exec команда {} \;` | выполнить команду **для каждого** файла, `{}` заменяется путём |
| `-exec команда {} +` | выполнить команду **один раз** для всех найденных файлов сразу |
| `-delete` | удалить найденное (будьте осторожны!) |
| `-quit` | остановиться на первом найденном |

```bash
find /etc -type l -printf '%p -> %l\n'               # ссылки и куда они ведут
find /etc -name '*.conf' -exec grep -l 'Listen' {} +  # в каких .conf есть Listen
```

### Сообщения «Отказано в доступе»

При поиске по всей системе `find` заходит в закрытые каталоги и пишет ошибки. Ошибки идут в
поток **stderr** (номер 2), и их можно скрыть:

```bash
find / -name 'php.ini' 2>/dev/null     # /dev/null — «чёрная дыра», ошибки исчезают
sudo find / -name 'php.ini'            # или искать с правами root
```

## 4. grep — поиск строк в файлах

```
grep [ключи] 'шаблон' файл...
```

| Ключ | Что делает |
|---|---|
| `-n` | показать номер строки |
| `-i` | без учёта регистра |
| `-v` | показать строки, **не** подходящие под шаблон |
| `-w` | только целые слова (`Port`, но не `Ports`) |
| `-x` | строка целиком совпадает с шаблоном |
| `-c` | только количество совпавших строк |
| `-o` | вывести только совпавшую часть |
| `-r` | искать рекурсивно во всех файлах каталога |
| `-l` / `-L` | только имена файлов с совпадениями / без них |
| `-h` / `-H` | не показывать / показывать имя файла |
| `-E` | расширенные регулярные выражения: `+ ? \| ( )` без обратной косой |
| `-F` | искать строку как есть, без спецсимволов |
| `-A N` / `-B N` / `-C N` | N строк после / до / вокруг совпадения |
| `--include='*.conf'` | при `-r` искать только в файлах по маске |
| `-q` | ничего не выводить, только код возврата (для скриптов) |

### Регулярные выражения: минимум для конфигов

| Запись | Значение | Пример |
|---|---|---|
| `^` | начало строки | `^Port` — строка начинается с Port |
| `$` | конец строки | `yes$` — строка заканчивается на yes |
| `.` | любой один символ | `Listen .0` |
| `*` | предыдущий символ 0 или больше раз | `^ *Listen` — с пробелами в начале или без |
| `[0-9]` | один символ из диапазона | `Port [0-9]*` |
| `[^#]` | любой символ, **кроме** `#` | `^[^#]` — строка не начинается с `#` |
| `[[:space:]]` | пробел или табуляция | `^bind-address[[:space:]]*=` |
| `\` | экранирование: `\.` — именно точка | `php\.ini` |

### Типичные приёмы

```bash
grep -n 'Port' /etc/ssh/sshd_config                  # где упоминается Port
grep -n '^Port' /etc/ssh/sshd_config                 # только активная строка (без #)
grep -v '^#' /etc/ssh/sshd_config | grep -v '^$'     # все активные настройки файла
grep -rn 'PasswordAuthentication' /etc/ssh/          # параметр во всех файлах каталога
grep -rl 'Listen' /etc/apache2 --include='*.conf'    # в каких файлах есть Listen
grep -E '^(Port|PermitRootLogin)' /etc/ssh/sshd_config
```

Строка, начинающаяся с `#` (в php.ini — с `;`), — это **комментарий**, сервис её не читает.
`#Port 22` — это подсказка «по умолчанию 22», а не настройка.

## 5. sed — изменение текста без редактора

`sed` (stream editor) читает файл построчно, применяет к каждой строке команды и выводит
результат. **Без ключа `-i` файл не меняется**: вы видите, что получилось бы. Это удобно для
проверки.

```
sed [ключи] 'команды' файл
```

### Ключи

| Ключ | Что делает |
|---|---|
| `-i` | изменить файл на месте (in-place) |
| `-i.bak` | изменить на месте, а исходный файл сохранить как `файл.bak` |
| `-n` | не выводить строки автоматически (вывод только командой `p`) |
| `-e 'команда'` | добавить команду, можно несколько: `-e '...' -e '...'` |
| `-E` | расширенные регулярные выражения: группы `( )` без `\` |
| `--follow-symlinks` | при `-i` менять файл, на который указывает ссылка, а не саму ссылку |

### Главная команда: замена s

```
s/что_найти/на_что_заменить/флаги
```

| Флаг | Значение |
|---|---|
| (нет) | заменить первое вхождение в каждой строке |
| `g` | заменить все вхождения в строке |
| `2` | заменить только второе вхождение |
| `i` | без учёта регистра |
| `p` | вывести строку, если замена была (вместе с `-n`) |

В замене `&` означает весь найденный текст, а `\1`, `\2` — части, взятые в скобки `\( \)` (или
`( )` с ключом `-E`). Разделитель не обязан быть `/`: если в тексте есть косые черты, удобнее
`s|/var/www|/srv/www|`.

### Адреса: к каким строкам применять

| Адрес | Строки |
|---|---|
| `5` | пятая строка |
| `$` | последняя |
| `/шаблон/` | строки, где есть совпадение |
| `10,20` | с 10-й по 20-ю |
| `/начало/,/конец/` | от строки с «начало» до строки с «конец» |
| `адрес!` | все строки, **кроме** адреса |

Адрес ставится перед командой: `sed '/^Listen/s/80/8080/'` — заменить 80 на 8080 только в
строках, начинающихся с Listen.

### Другие команды

| Команда | Что делает | Пример |
|---|---|---|
| `p` | вывести строку | `sed -n '/^Port/p' файл` — как grep |
| `d` | удалить строку | `sed '/^#/d' файл` — убрать комментарии |
| `c текст` | заменить строку целиком | `sed '/^PermitRootLogin/c PermitRootLogin no'` |
| `a текст` | добавить строку **после** | `sed '/^Port/a ListenAddress 0.0.0.0'` |
| `i текст` | вставить строку **перед** | `sed '1i # managed by admin'` |
| `=` | вывести номер строки | `sed -n '/Listen/=' ports.conf` |

### Рецепты для конфигов

```bash
# 1. Посмотреть, что получится (файл не меняется)
sed 's/^ServerTokens OS/ServerTokens Prod/' security.conf | grep -n '^ServerTokens'

# 2. Раскомментировать и задать значение
sudo sed -i 's/^#Port 22$/Port 2222/' /etc/ssh/sshd_config

# 3. Заменить значение, каким бы оно ни было сейчас
sudo sed -i 's/^PermitRootLogin .*/PermitRootLogin no/' /etc/ssh/sshd_config

# 4. Параметр вида «имя = значение» с любым количеством пробелов
sudo sed -i -E 's/^(memory_limit\s*=\s*).*/\1256M/' /etc/php/8.2/apache2/php.ini

# 5. Закомментировать строку
sudo sed -i 's/^X11Forwarding/#X11Forwarding/' /etc/ssh/sshd_config

# 6. Несколько замен за раз и резервная копия
sudo sed -i.bak -e 's/^A on/A off/' -e 's/^B 1/B 0/' файл
```

Якоря `^` и `$` в шаблоне — главная защита от случайной правки. `s/22/2222/` изменит **любое**
«22» в файле, а `s/^#Port 22$/Port 2222/` — только нужную строку.

### Символические ссылки

`sed -i` записывает результат в новый файл. Если указать **ссылку** (например,
`sites-enabled/000-default.conf`), то вместо ссылки появится обычный файл, а оригинал в
`sites-available/` останется прежним. Чтобы изменить сам оригинал, правьте файл в
`*-available/` или добавьте `--follow-symlinks`. Проверить, ссылка ли это: `ls -l` (стрелка `->`)
или `find ... -type l`.

## 6. Связки команд

Конвейер `|` передаёт вывод одной команды на вход другой:

```bash
find /etc -name '*.conf' | xargs grep -l 'Listen'          # xargs превращает строки в аргументы
find /etc -name '*.conf' -exec grep -Hn 'Listen' {} \;     # то же через -exec
grep -rl 'ServerTokens' /etc/apache2 | xargs ls -l         # подробности о найденных файлах
grep -c '^#' /etc/ssh/sshd_config                          # сколько строк закомментировано
```

Проверка после правки:

```bash
grep -n '^Port' /etc/ssh/sshd_config            # значение изменилось?
diff /etc/apache2/ports.conf.bak /etc/apache2/ports.conf    # что именно поменялось
```

## 7. Порядок работы

1. **Найти файл**: `find /etc -name '...'` или `grep -rl 'параметр' /etc/сервис/`.
2. **Убедиться, что файл рабочий**, а не копия, шаблон или конфиг клиента. Включён ли он
   (`*-enabled`, `Include`)? Нет ли параметра ещё где-то: `grep -rn 'параметр' /etc/сервис/`.
3. **Посмотреть текущую строку**: `grep -n 'параметр' файл`.
4. **Проверить замену без `-i`**: `sed 's/.../.../' файл | grep -n 'параметр'`.
5. **Применить**: `sudo sed -i 's/.../.../' файл`.
6. **Проверить результат**: `grep -n 'параметр' файл`.

## 8. Частые ошибки

- **`ssh_config` вместо `sshd_config`.** Первый — настройки клиента. Сервер их не читает.
- **Правка закомментированной строки** без удаления `#`: `#Port 2222` — всё ещё комментарий.
- **Параметр задан в нескольких местах.** Вы поменяли главный файл, а действует значение из
  `*.d/`. Ищите `grep -rn` по всему каталогу сервиса.
- **Не тот php.ini.** У PHP для веб-сервера (`apache2/php.ini`) и для командной строки
  (`cli/php.ini`) разные настройки.
- **`sudo` и `>`.** Перенаправление работает без прав root. Используйте `sudo tee` или `sudo sed -i`.
- **Шаблон без кавычек** в `find -name *.conf`. Шелл может подставить файлы из текущего каталога.
- **`sed` без якорей** меняет больше, чем нужно, в том числе комментарии и другие параметры.
- **Сразу `-i` без проверки.** Сначала посмотрите вывод без `-i` или делайте `-i.bak`.
- **Правка резервных копий** через `find ... -exec sed -i` по всем найденным файлам сразу.
  Сначала посмотрите список файлов, потом меняйте только нужный.

## 9. Шпаргалка

```bash
find /etc -name 'имя'                        # найти файл по имени
find /etc -type f -name '*.conf' 2>/dev/null # все .conf, без ошибок доступа
find /etc -maxdepth 1 -type d                # подкаталоги первого уровня
find /etc -mtime -7                          # что меняли за неделю
grep -rn 'параметр' /etc/сервис/             # где задан параметр
grep -v '^#' файл | grep -v '^$'             # активные настройки
sed -n '/шаблон/p' файл                      # показать строки
sed 's/было/стало/' файл                     # предпросмотр замены
sudo sed -i 's/^было$/стало/' файл           # заменить в файле
sudo sed -i.bak 's/.../.../' файл            # заменить и сохранить копию
echo 'строка' | sudo tee -a файл             # дописать строку в файл root
```
