# Задание №5. Основы работы в терминале Linux

Терминал (командная строка) — главный инструмент администратора и специалиста по
информационной безопасности. На серверах обычно нет графического интерфейса: файлы
ищут, читают, копируют и защищают командами. Этот тренажёр шаг за шагом учит
основным командам. В нём **14 этапов**, и проходить их нужно **строго по порядку**.

## Как устроен тренажёр

1. Прочитайте этот материал: здесь описаны все команды, их ключи и порядок этапов.
2. Откройте «Практику в терминале» и войдите под своим логином и паролем от платформы.
3. Наберите `task`: появится описание **текущего** этапа с вашими личными значениями.
   Все этапы сразу есть в файле `~/TASK.md` (`cat TASK.md`).
4. Выполняйте пункты этапа. Проверка запускается автоматически после каждой команды.
   Когда все пункты выполнены, терминал сообщит «Этап N пройден» и откроет следующий.
5. `check` показывает прогресс по всем этапам и что осталось сделать в текущем.

В этапах встречаются пункты трёх видов:

| Вид | Как проверяется | Пример |
|---|---|---|
| **Команда** | по журналу команд: команда выполнена без ошибки **после открытия этапа** | «выведите подробный список: `ls -l`» |
| **Файлы** | по состоянию файлов: каталог создан, файл перемещён, права выставлены | «создайте каталог `~/proj-falcon`» |
| **Вопрос** | ответ командой `answer НОМЕР ОТВЕТ` | «сколько строк в журнале?» → `answer 4.1 57` |

> Значения (имя проекта, кодовое слово, IP-адрес и т.д.) у каждого студента свои,
> поэтому чужие ответы не подойдут. Все ваши действия записываются в журнал, который
> видит преподаватель.

Пример ответа на вопрос:

```bash
wc -l ~/logs/app.log        # 57 /home/st-ib-001/logs/app.log
answer 4.1 57               # ✔ Вопрос 4.1: верно!
```

## Основы: команда, ключи, пути

Команда состоит из **имени**, **ключей** (опций) и **аргументов**:

```text
ls  -l  -a  /etc
│   └─┬──┘  └─ аргумент: с чем работать
│     └ ключи: как работать (-l подробно, -a со скрытыми)
└ имя команды
```

- Короткие ключи можно объединять: `ls -l -a` = `ls -la`. Длинные пишутся через два дефиса:
  `rm --recursive`.
- Регистр важен: `ls -r` и `ls -R` — разные ключи, а `File.txt` и `file.txt` — разные файлы.
- Имена с пробелами берите в кавычки: `cat 'мой файл.txt'`.

**Одна строка — одна команда.** Всё, что написано в строке, команда считает своими аргументами.
Если написать две команды подряд, вторая станет аргументами первой:

```bash
mkdir -p proj/data mv downloads/data.csv proj/data/      # ОШИБКА: mkdir создаст каталоги mv, downloads/data.csv ...
mkdir -p proj/data && mv downloads/data.csv proj/data/   # верно: mv выполнится, если mkdir прошёл успешно
mkdir -p proj/data ; mv downloads/data.csv proj/data/    # тоже можно: команды выполнятся по очереди
```

Проще всего набирать команды по одной. Если копируете команды из подсказки, проверяйте, что
в строку не попало лишнее.

**Файловая система** — одно дерево каталогов, начиная с корня `/`:

```text
/
├── etc/          настройки системы (hostname, passwd, motd ...)
├── home/
│   └── st-ib-001/   ваш домашний каталог (~)
├── root/         домашний каталог администратора root
├── tmp/          временные файлы
├── usr/bin/      программы (команды)
└── var/log/      журналы (логи)
```

| Запись | Значение | Пример |
|---|---|---|
| `/` | корень файловой системы | `cd /` |
| `~` | ваш домашний каталог (`/home/ваш_логин`) | `cd ~/documents` |
| `.` | текущий каталог | `./backup.sh` |
| `..` | родительский каталог (на уровень выше) | `cd ..` |
| **абсолютный путь** | начинается с `/`, указывает путь от корня | `/var/log/syslog` |
| **относительный путь** | указывает путь от текущего каталога | `documents/notes.txt` |

**Клавиши**, которые экономят время:

| Клавиша | Что делает |
|---|---|
| `Tab` | дописывает имя команды, файла или каталога; если вариантов несколько — показывает их |
| `↑` / `↓` | листают историю команд |
| `Ctrl+C` | отменяет набранную команду |
| `Ctrl+L` | очищает экран (то же, что `clear`) |

## Этап 2. Просмотр каталогов: ls

`ls` (list) показывает содержимое каталога. Без аргумента — текущего каталога.

| Ключ | Что делает |
|---|---|
| `-l` | подробный список: тип и права, владелец, размер, дата изменения |
| `-a` | показывает скрытые файлы (имя начинается с точки), включая `.` и `..` |
| `-A` | показывает скрытые файлы без `.` и `..` |
| `-h` | показывает размеры в K/M/G (вместе с `-l`) |
| `-t` / `-S` / `-r` | сортируют по времени / по размеру / в обратном порядке |
| `-R` | показывает содержимое всех подкаталогов |
| `-d` | показывает сам каталог, а не его содержимое |

Как читать строку `ls -l`:

```text
-rw-r--r--  1  st-ib-001  st-ib-001   223  сен  1 10:00  README.txt
│└───┬───┘     └─владелец─┘ └группа┘  └размер └─дата изменения─┘ └имя
│    └ права: владелец rw-, группа r--, остальные r--
└ тип: - обычный файл, d каталог, l символическая ссылка
```

**Скрытые файлы** — файлы, имя которых начинается с точки (`.bashrc`, `.profile`). Это
обычно настройки программ. `ls` без `-a` их не показывает.

**Что сделать:** выполните `ls -l` и `ls -la` в домашнем каталоге и `ls -l /etc`. Затем
посчитайте скрытые файлы и каталоги дома (без `.` и `..`) и отправьте ответ `answer 2.1 ЧИСЛО`.

## Этап 4. Чтение файлов: cat, head, tail, wc

| Команда | Что делает |
|---|---|
| `cat ФАЙЛ` | выводит файл целиком; `cat -n` — с номерами строк |

## Этап 7. Удаление: rm, rmdir

| Команда | Что делает |
|---|---|
| `rm ФАЙЛ` | удаляет файл |
| `rm *.tmp` | удаляет все файлы, имя которых заканчивается на `.tmp` (маска) |
| `rmdir КАТАЛОГ` | удаляет **пустой** каталог |
| `rm -r КАТАЛОГ` | удаляет каталог со всем содержимым |
| `rm -f` | не спрашивает и не сообщает о несуществующих файлах |
| `rm -v` | сообщает о каждом удалённом файле |

**Маски** (шаблоны имён) раскрывает сам шелл:

| Маска | Подходят имена |
|---|---|
| `*` | любые символы: `*.tmp` → `a.tmp`, `cache_1.tmp` |
| `?` | ровно один символ: `file?.txt` → `file1.txt`, `fileA.txt` |
| `[abc]` | один символ из списка: `report[12].txt` → `report1.txt`, `report2.txt` |

> **Корзины нет: удалённое не вернуть.** Перед `rm` с маской проверьте, что она находит:
> сначала `ls *.tmp`, потом `rm *.tmp`. `rm -rf` удаляет всё без вопросов, поэтому
> внимательно проверяйте путь.

**Что сделать** (в каталоге `~/trash`):
1. Удалите все файлы `*.tmp` одной командой. Файл `keep.txt` удалять не нужно.
2. Удалите пустой каталог `empty_dir` командой `rmdir`.
3. Удалите каталог `old_project` вместе с содержимым командой `rm -r`.

## Этап 8. Права доступа: chmod и запуск скриптов

У каждого файла три набора прав: для **владельца** (u), **группы** (g) и **остальных** (o).
Каждый набор содержит три права:

| Право | Для файла | Для каталога | Число |
|---|---|---|---|
| `r` (read) | читать | смотреть список файлов | 4 |
| `w` (write) | изменять | создавать и удалять файлы внутри | 2 |
| `x` (execute) | запускать как программу | входить в каталог (`cd`) | 1 |

Числовая запись — сумма прав в каждом наборе:

| Права | Число | Типичный случай |
|---|---|---|
| `rwxr-xr-x` | 755 | скрипты и программы, каталоги |
| `rw-r--r--` | 644 | обычные файлы |
| `rw-------` | 600 | личные и секретные файлы (ключи, пароли) |
| `rwxr-x---` | 750 | скрипт, доступный только владельцу и группе |
| `r--r--r--` | 444 | файл только для чтения |

Как перевести права в число: `rw-r-----` = (4+2+0)(4+0+0)(0+0+0) = **640**.

| Команда | Что делает |
|---|---|
| `chmod 600 ФАЙЛ` | задаёт права числом |
| `chmod u+x ФАЙЛ` | добавляет владельцу право выполнения |
| `chmod go-rwx ФАЙЛ` | убирает все права у группы и остальных |
| `chmod +x ФАЙЛ` | добавляет право выполнения всем |
| `chmod -R 755 КАТАЛОГ` | меняет права рекурсивно |

**Скрипт** — текстовый файл с командами. Запустить его по пути (`./backup.sh`) можно,
только если у файла есть право `x`. Иначе будет ошибка «Отказано в доступе». Через
`bash backup.sh` скрипт запускается и без права `x`, но в этапе нужен именно запуск по пути.

```bash
cd ~/scripts
ls -l backup.sh        # -rw-r--r--  — права x нет
./backup.sh            # bash: ./backup.sh: Отказано в доступе
chmod +x backup.sh
./backup.sh            # скрипт выполнился
```

**Что сделать:**
1. Сделайте `~/scripts/backup.sh` исполняемым и запустите его по пути `./backup.sh`.
2. Закройте `~/documents/private.txt` от всех, кроме себя: права 600.
3. Посмотрите `ls -l ~/documents/mystery.txt`, переведите права в число и отправьте
   ответ `answer 8.1`.

## Этап 9. Ссылки: ln -s, readlink

**Символическая ссылка** — это ярлык: отдельный файл, который указывает на другой файл или
каталог. Через ссылку можно работать с целью, но если цель удалить, ссылка «повиснет».

| Команда | Что делает |
|---|---|
| `ln -s ЦЕЛЬ ИМЯ_ССЫЛКИ` | создаёт символическую ссылку: **сначала цель, потом имя ссылки** |
| `ls -l` | показывает ссылку так: `latest.log -> /home/.../logs/app.log` |
| `readlink ССЫЛКА` | показывает, куда ведёт ссылка (как она записана) |
| `readlink -f ССЫЛКА` | показывает полный путь к конечному файлу |
| `ln -sf ...` | заменяет существующую ссылку |

```bash
ln -s ~/logs/app.log proj-falcon/latest.log
ls -l proj-falcon/latest.log
cat proj-falcon/latest.log     # читается файл app.log
```

> Указывайте цель абсолютным путём (`~/logs/app.log`). Относительная цель отсчитывается
> от каталога, **где лежит ссылка**, а не от текущего каталога.

**Что сделать:**
1. Создайте ссылку `latest.log` в проекте, ведущую на `~/logs/app.log`.
2. Создайте ссылку `~/docs`, ведущую на каталог `~/documents`.
3. Узнайте командой `readlink`, куда ведёт `~/downloads/current`, и отправьте ответ
   `answer 9.1 ИМЯ_ФАЙЛА`.

## Этап 10. Поиск: find и grep

`find` ищет **файлы** по имени, типу, размеру и дате. `grep` ищет **строки** внутри файлов.

| Команда | Что делает |
|---|---|
| `find ~/archive -name '*.pdf'` | ищет файлы по маске имени (маску берите в кавычки!) |
| `find ~ -iname '*report*'` | ищет по имени без учёта регистра |
| `find ~ -type f` / `-type d` | ищет только файлы / только каталоги |
| `find ~ -name '*.log' -size +1k` | ищет по имени и размеру сразу |
| `grep СЛОВО ФАЙЛ` | выводит строки, в которых есть слово |
| `grep -c СЛОВО ФАЙЛ` | считает строки со словом |
| `grep -i` / `grep -v` / `grep -n` | ищет без учёта регистра / выводит строки **без** слова / показывает номера строк |
| `grep -r СЛОВО КАТАЛОГ` | ищет во всех файлах каталога и подкаталогов |
| `grep -rl СЛОВО КАТАЛОГ` | выводит только имена файлов, где нашлось слово |

```bash
find ~/archive -name '*.pdf'
grep -c ERROR ~/logs/app.log
grep -rl KESTREL-123 ~/documents
```

Подробно `find` и `grep` разбираются в задании №4.

**Что сделать:**
1. Найдите командой `find` единственный PDF в `~/archive` и отправьте его путь: `answer 10.1`.
2. Посчитайте строки с ERROR в журнале: `answer 10.2`.
3. Найдите файл в `~/documents`, где упоминается ваше слово (оно указано в `task`), и
   отправьте ответ `answer 10.3`.

## Этап 11. Конвейеры и перенаправления

**Конвейер** `|` передаёт вывод одной команды на вход следующей. Так из простых команд
собирают сложную обработку:

```bash
cat ~/logs/access.log | cut -d' ' -f1 | sort | uniq -c | sort -rn | head -1
#        строки лога    первое поле (IP)  сорт.  счёт   по убыванию  первая
```

| Команда | Что делает |
|---|---|
| `cut -d' ' -f1` | вырезает первое поле строки (разделитель — пробел); `-d:` — двоеточие |
| `sort` | сортирует строки; `-n` — как числа, `-r` — в обратном порядке, `-u` — без повторов |
| `uniq` | убирает **соседние** повторы, поэтому сначала нужен `sort`; `-c` — пишет число повторов |
| `head -1` | оставляет первую строку |
| `wc -l` | считает строки результата |

**Перенаправления** управляют тем, куда идёт вывод:

| Запись | Что делает |
|---|---|
| `команда > файл` | записывает вывод в файл (файл перезаписывается) |
| `команда >> файл` | дописывает вывод в конец файла |
| `команда < файл` | берёт ввод из файла |
| `команда 2> файл` | записывает в файл сообщения об **ошибках** (поток 2) |
| `команда 2>/dev/null` | скрывает сообщения об ошибках (`/dev/null` — «чёрная дыра») |
| `команда > файл 2>&1` | записывает в файл и вывод, и ошибки |

```bash
grep ERROR ~/logs/app.log > errors.txt
find / -name '*.log' 2>/dev/null          # без «Отказано в доступе»
```

**Что сделать:**
1. Найдите IP, с которого больше всего запросов в `~/logs/access.log`, и отправьте ответ
   `answer 11.1`.
2. Запишите в `ips.txt` проекта все IP без повторов, по алфавиту: `cut ... | sort -u > ...`.
3. Запишите в `errors.txt` проекта только строки с ERROR из `app.log`.
4. Выполните поиск по всей системе со скрытием ошибок: `find / -name '*.log' 2>/dev/null`.

## Этап 12. Права администратора: sudo

Системные файлы принадлежат администратору **root**. Обычный пользователь не может
читать некоторые из них (например, `/var/log/auth.log` или `/etc/shadow`) и не может
изменять ни один. `sudo` выполняет **одну** команду с правами root.

| Команда | Что делает |
|---|---|
| `sudo КОМАНДА` | выполняет команду от имени root |
| `sudo whoami` | выведет `root` |
| `sudo !!` | повторяет предыдущую команду с `sudo` |
| `sudo -l` | показывает, что вам разрешено |
| `echo 'текст' \| sudo tee -a ФАЙЛ` | дописывает строку в системный файл |

> **Ловушка:** `sudo echo 'x' >> /etc/motd` не сработает. Перенаправление `>>` выполняет ваш
> шелл без прав root, а `sudo` получает только `echo`. Правильно — через конвейер и `tee`:
> `echo 'x' | sudo tee -a /etc/motd`. Ключ `-a` означает «дописать». Без него `tee`
> перезапишет файл.

**Что сделать:**
1. Выполните `sudo whoami`.
2. Прочитайте `/var/log/auth.log` через `sudo`. Найдите имя пользователя, под которым были
   неудачные попытки входа (`Failed password`), и отправьте ответ `answer 12.1`.
3. Допишите в `/etc/motd` строку `Сервер обслуживает: ВАШ_ЛОГИН`.

## Этап 13. История команд

| Команда | Что делает |
|---|---|
| `history` | выводит пронумерованный список выполненных команд |
| `history 10` | выводит последние 10 команд |
| `!!` | повторяет последнюю команду |
| `!N` | повторяет команду номер N из `history` |
| `!-2` | повторяет предпоследнюю команду |
| `!ls` | повторяет последнюю команду, начинающуюся с `ls` |
| `history \| grep cd` | находит в истории все команды с `cd` |

Перед выполнением bash показывает, во что превратилась команда с `!`.

**Что сделать:**
1. Выполните `history`.
2. Повторите какую-нибудь команду через `!!`.
3. Найдите в истории все команды `cd`: `history | grep cd`.

## Частые ошибки

| Ошибка | Причина и что делать |
|---|---|
| `команда не найдена` | опечатка в имени команды; проверьте, есть ли она в `help` |
| `Нет такого файла или каталога` | неверный путь: проверьте `pwd` и `ls`, пользуйтесь Tab |
| `Отказано в доступе` | нет прав: посмотрите `ls -l`; системный файл — через `sudo`, свой скрипт — `chmod +x` |
| `Это каталог` | `rm` и `cp` без `-r` не работают с каталогами |
| Появились лишние каталоги (`mv`, `cp` ...) | две команды в одной строке: вторая стала аргументами первой. Пишите по одной команде в строке или соединяйте их `&&` |
| `Каталог не пуст` | `rmdir` удаляет только пустые каталоги, для остальных нужен `rm -r` |
| Файл пропал после `echo >` | `>` перезаписывает файл, для дописывания нужен `>>` |
| Пункт-команда не засчитывается | команду нужно выполнить **после** открытия этапа (`task`) и без ошибки |
| Маска не сработала (`*.tmp` осталось буквально) | файлов по маске нет: проверьте каталог и имя (`ls`) |
