# Межсетевой экран: аудит и настройка iptables

**Межсетевой экран** (пакетный фильтр) решает, какие сетевые пакеты пропускать, а какие
отбрасывать. В Linux это `iptables` (или `nftables`). Правильно настроенный фильтр оставляет
открытыми только те порты, которые действительно должны быть доступны, и закрывает остальное.

## Цепочки и политика по умолчанию

Правила сгруппированы в **цепочки**. Для защиты сервера важна цепочка **INPUT** — входящие
подключения. У каждой цепочки есть **политика по умолчанию** — что делать с пакетом, если ни одно
правило не подошло:

- `policy ACCEPT` — «разрешено всё, что явно не запрещено». Небезопасно: любой новый сервис
  оказывается доступен из интернета.
- `policy DROP` — «запрещено по умолчанию». Доступны только порты с явным правилом `ACCEPT`. Это
  безопасная настройка.

## Как читать правила

```
sudo iptables -L -n --line-numbers    # правила с номерами (prot, source, dpt — порт назначения)
sudo iptables -S                       # правила и политики в виде команд (-P ... — политика)
```

Правило `-A INPUT -p tcp --dport 22 -j ACCEPT` означает: разрешить входящие TCP-подключения на
порт 22 (SSH). Поле `--dport` — порт назначения, `-j` — что сделать (`ACCEPT`, `DROP`, `REJECT`).

**Срабатывает первое подходящее правило** сверху вниз; если ни одно не подошло — применяется
политика цепочки.

## Какие порты открывать

Наружу (в интернет) открывают только то, что должно быть доступно всем:

| порт | служба | открывать наружу |
|---|---|---|
| 22 | SSH | да (лучше — не всем) |
| 80, 443 | сайт (HTTP/HTTPS) | да |
| 3306 | MySQL / MariaDB | **нет** |
| 5432 | PostgreSQL | **нет** |
| 6379 | Redis | **нет** |
| 27017 | MongoDB | **нет** |

Порт базы данных, открытый в интернет, — частая и опасная ошибка: к базе получают доступ
посторонние.

## Настройка

```
sudo iptables -D INPUT -p tcp --dport 3306 -j ACCEPT   # удалить правило, открывающее порт БД
sudo iptables -A INPUT -p tcp --dport 3306 -j DROP     # запретить порт БД для входящих
sudo iptables -P INPUT DROP                             # политика по умолчанию — «запрещено»
sudo iptables -I INPUT -s 203.0.113.5 -j DROP          # заблокировать адрес (в начало цепочки!)
```

- **Порядок важен.** Блокирующее правило добавляют в **начало** цепочки (`-I`), иначе разрешающее
  правило сработает раньше и запрет не подействует.
- **Сначала разрешите SSH, потом ставьте `DROP`.** Если включить политику `DROP`, не оставив
  правила `ACCEPT` для порта 22, вы потеряете доступ к серверу.
- **Сохранение.** Правила в памяти теряются при перезагрузке. Их сохраняют:
  `sudo iptables-save > /etc/iptables/rules.v4` (в учебном терминале это делается автоматически).

## Поиск атакующего

Перебор паролей по SSH виден в журнале входов `/var/log/auth.log` — много строк
`Failed password ... from АДРЕС` с одного адреса:

```
grep 'Failed password' /var/log/auth.log | grep -oE '([0-9]+\.){3}[0-9]+' | sort | uniq -c | sort -rn
```

Такой адрес блокируют правилом в начало цепочки INPUT.
