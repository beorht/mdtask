# №3. Пароль от защищённой базы, спрятанный и зашифрованный Цезарем

> **Актуальная постановка (обновлено):** найденный пароль больше не используется для входа на платформу. Он открывает защищённую базу данных `~/Documents/backup/company_data.db` с вымышленными учебными данными (сотрудники, учётные записи, документы). Студент выполняет `sqlite3 Documents/backup/company_data.db`, вводит пароль на запрос `Password:` — база расшифровывается в память, задание отмечается решённым (`solved=1`). Формат шифрования файла — `server/protected_db.py`. Описание ниже (про вход вторым паролем и mdtask-интерфейс) — история первой версии задания; генерация, пул путей и варианты `password`/`path` по-прежнему актуальны.

Цель: студент находит скрытый в системе файл, расшифровывает Цезаря вручную, получает второй пароль от **своего же** аккаунта и заново входит на платформу под своим логином с этим паролем. Первый (обычный) пароль в `users.password_hash` не трогается и не участвует в проверке — это отдельный, независимый механизм.

**Статус: реализовано полностью и протестировано end-to-end на реальном студенте (st-ib-688).**

## Что сделано

### 1. Данные (реальная БД `mdtask/data/mdtask.db`)

- Таблица `ctf_caesar_secrets` — отдельно от `users`, не пересекается с обычным логином
- Для всех 18 студентов группы **IB**: случайный сдвиг Цезаря (2–25), случайный пароль, шифротекст — всё уникальное на каждого (проверено — совпадений нет ни по паролю, ни по сдвигу)
- Схема также добавлена в `mdtask/src/db/schema.sql`, чтобы применялась на свежих БД автоматически

Генератор: `ctf/caesar-secret/generate_challenge.py --group IB`. Идемпотентен — повторный запуск не трогает уже сгенерированных студентов и не перезаписывает то, что уже лежит на диске; донести новые обманки старым студентам можно без `--force`.

### 2. Песочница на диске (`mdtask/data/ctf/caesar/<student_id>/`)

По аналогии с уже существующим паттерном SQL-тренажёра (`data/trainer/<studentId>/`). У каждого студента:

- Стандартный "скелет" домашней директории Linux: `Desktop/`, `Documents/`, `Downloads/`, `Music/`, `Pictures/`, `Public/`, `Templates/`, `Videos/`, `.bashrc`, `.bash_profile`, `.profile`, `.bash_logout`, `.bash_history` (с правдоподобной историей команд)
- 7 путей-кандидатов для скрытого файла (`.cache/.fontconfig/.uuid.bak`, `.config/.dconf/.user-cache`, `.config/.pulse/.cookie-old`, `.ssh/.known_hosts.old`, `.bash_sessions/.meta`, `.local/share/.recently-used.bak`, `.local/state/.wal.bak`) — **у каждого студента путь к настоящему файлу выбирается случайно из этого пула**, остальные шесть заполнены правдоподобным мусором без подсказок (валидные на вид UUID, hex-строки, XML, ssh-ключи), так что нельзя понять по имени файла, какой из них настоящий
- Реальный файл отличается только содержимым — комментарий-намёк + шифротекст:
  ```
  # резервная копия :: доступ уровня администратора
  # восстановлено из старого бэкапа системы
  <шифротекст>
  ```
- `TASK.md` — условие задания (копия студенческой части `TASK.md` из корня репозитория); список команд — команда `help`

### 3. Приём второго пароля при логине (`mdtask/src/routes/auth.js`)

`POST /login` теперь: сначала проверяет обычный `password_hash` как раньше; при неудаче — fallback на `ctf_caesar_secrets.plain_password` для того же `student_id`; при совпадении логинит и помечает `solved=1, solved_at=now()`. Основной пароль и обычный флоу входа не затронуты.

### 4. Интерфейс терминала (`mdtask/src/routes/ctf.js` + `views/ctf-caesar.ejs`)

Новая страница `/ctf/caesar` (кнопка «Терминал» в шапке — видна только студентам), реализована как псевдо-shell поверх реальных файлов студента на сервере:

- `ls [-a] [путь]`, `cd [путь]` (с реальным состоянием текущей директории в сессии и живым промптом `~/...`), `pwd`, `cat <файл>`, `find [путь]` (рекурсивный листинг), `whoami`, `id`, `date`, `echo`, `clear`, `help`
- Песочница жёстко ограничена домашним каталогом студента — попытки выйти за пределы (`cd ..` из корня, `cat ../../../etc/passwd`) блокируются проверенным путём (протестировано вручную)

## Усложнённый вариант: зашифрован путь к файлу с паролем

`generate_challenge.py --group IB --variant path --force` — в скрытом файле вместо пароля лежит зашифрованный Цезарем путь ко второму файлу, где пароль хранится открытым текстом:

```
# резервная копия :: доступ уровня администратора
# расположение файла с паролем (восстановлено из старого бэкапа)
~/.mkmro/.pyxdmyxpsq/.myxp-mkmro        ← сдвиг 10 → ~/.cache/.fontconfig/.conf-cache
```

Сдвиг подбирается перебором: правильный даёт осмысленный путь, который существует в песочнице. Файл с паролем выбирается из того же пула и спрятан среди обманок. Условие в `TASK.md` общее для обоих вариантов.

## Формат данных

```sql
CREATE TABLE ctf_caesar_secrets (
  id TEXT PRIMARY KEY,
  student_id TEXT NOT NULL REFERENCES users(id),
  caesar_shift INTEGER NOT NULL,
  plain_password TEXT NOT NULL,
  cipher_text TEXT NOT NULL,
  hidden_file_path TEXT NOT NULL,
  solved INTEGER NOT NULL DEFAULT 0,
  solved_at TEXT,
  created_at TEXT NOT NULL,
  variant TEXT NOT NULL DEFAULT 'password',   -- 'password' | 'path'
  password_file_path TEXT                      -- только для variant='path'
);
```

## Как проверить прогресс группы

```sql
SELECT student_id, solved, solved_at FROM ctf_caesar_secrets WHERE solved = 1;
```
