# №1. Настройка SSH: вход только по ключу

Цель: настроить сервер так, чтобы вход по SSH был возможен только по публичному ключу, без пароля. Это базовый бэкенд-этап платформы — прежде чем подключать реальные лабораторные контейнеры к веб-терминалу, доступ к ним должен быть защищён ключами.

## Этап 1. Генерация ключа (клиент)

```bash
ssh-keygen -t ed25519 -C "student@seclab"
```
- `id_ed25519` — приватный ключ, остаётся только у студента
- `id_ed25519.pub` — публичный ключ, уходит на сервер

## Этап 2. Установка публичного ключа на сервере

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
echo "ssh-ed25519 AAAA... student@seclab" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```
Права `700`/`600` обязательны — иначе sshd молча откажет в ключевой аутентификации.

## Этап 3. Правка `/etc/ssh/sshd_config`

```
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitEmptyPasswords no

PubkeyAuthentication yes
AuthenticationMethods publickey

PermitRootLogin no

AuthorizedKeysFile .ssh/authorized_keys

ChallengeResponseAuthentication no
UsePAM no
```

## Этап 4. Проверка конфига перед перезапуском

```bash
sudo sshd -t
```
Если ошибка — sshd не перезапустится, конфиг не поломает текущий доступ.

## Этап 5. Перезапуск службы

```bash
sudo systemctl restart sshd
```

## Этап 6. Проверка доступа без разрыва текущей сессии

Открыть **новое** подключение в отдельном терминале, не закрывая старое:
```bash
ssh -i ~/.ssh/id_ed25519 user@host
```
Если новое подключение работает без запроса пароля — можно закрывать старую сессию. Если нет — чинить через ещё открытую старую.

## Задел на будущее (для платформы с множеством студентов)

- `Match User` / `Match Group` — разные ограничения для разных групп
- `ChrootDirectory` — изоляция студента в его домашней песочнице
- `AllowTcpForwarding no`, `X11Forwarding no` — отключить, если не нужно
- `AuthorizedKeysCommand` — динамическая подгрузка ключа из БД/API платформы вместо статичных файлов на диске (актуально при десятках/сотнях студентов)
- Отдельный контейнер/namespace на студента со своим sshd-портом, либо единый sshd-хост с выдачей ключей через API платформы
