# Обработка ошибок

Когда что-то идёт не так, JavaScript **бросает** ошибку: выполнение прерывается, и если её никто не поймал, программа
падает. Поймать можно конструкцией `try / catch`:

```js run
try {
  const data = JSON.parse('{ сломано }');
  console.log(data);
} catch (e) {
  console.log('Не получилось разобрать данные:', e.name);
}
console.log('Программа продолжает работу');
```

- `try` — код, где может случиться ошибка;
- `catch (e)` — что делать, если случилась; `e` — объект ошибки (`e.name`, `e.message`);
- `finally` — выполняется **всегда**: и после успеха, и после ошибки (закрыть, убрать, посчитать).

## Свои ошибки

Функция может сама сообщить о неправильных данных — бросить ошибку `throw`:

```js run
function parseAge(text) {
  const age = Number(text);
  if (!Number.isInteger(age)) throw new Error('возраст должен быть целым числом');
  if (age < 0 || age > 150) throw new RangeError('возраст вне диапазона');
  return age;
}
for (const t of ['17', 'abc', '200']) {
  try {
    console.log(parseAge(t));
  } catch (e) {
    console.log(e.name + ': ' + e.message);
  }
}
```

Встроенные виды: `Error` (общая), `TypeError`, `RangeError`, `SyntaxError`, `ReferenceError`. Вид ошибки помогает
в `catch` решить, что делать: `if (e instanceof RangeError) …`.

## Когда ловить

- **ловите** там, где знаете, что делать с ошибкой: показать сообщение, взять значение по умолчанию, пропустить запись;
- **не глотайте** ошибки молча (`catch {}`) — так прячутся настоящие баги;
- проверка `if` дешевле и понятнее, чем `try`, если ошибку можно предвидеть (деление на ноль, пустой массив).

## Ошибка «пробрасывается» вверх

Если внутри функции ошибку не поймали, она уходит к тому, кто функцию вызвал, и дальше — пока не найдётся `catch`.
Поэтому проверять данные удобно в маленьких функциях, а ловить — в одном месте наверху.
