## 1. Что происходит, когда открывается страница

Браузер получает HTML как **обычный текст**. Чтобы с ним можно было работать, он проходит несколько шагов:

1. **Разбор HTML (парсинг).** Браузер читает текст сверху вниз и для каждого тега создаёт объект. Объекты связываются в дерево: у каждого есть родитель и дети. Это дерево и называется **DOM** — *Document Object Model*, «объектная модель документа».
2. **Разбор CSS.** Из стилей строится похожее дерево правил — CSSOM.
3. **Дерево отрисовки.** Браузер соединяет DOM и CSSOM: какие элементы видны и как они выглядят. Элементы с `display: none` в него не попадают.
4. **Раскладка (layout, reflow).** Вычисляются размеры и положение каждого элемента на экране.
5. **Отрисовка (paint).** Пиксели выводятся на экран.

JavaScript работает с результатом **первого** шага — с деревом объектов. Когда вы меняете DOM из скрипта, браузер сам повторяет шаги 3–5 для изменившейся части страницы. Именно поэтому, поменяв `textContent` у заголовка, вы сразу видите новый текст: вы поменяли объект, а браузер перерисовал страницу.

> **Важно понимать:** DOM — это не HTML-файл. Файл на диске не меняется. Меняется дерево объектов в памяти браузера. Если перезагрузить страницу, браузер снова прочитает исходный HTML и построит дерево заново — все изменения из JavaScript пропадут (если вы их где-то не сохранили, об этом в части 7).

## 2. Дерево на примере

```html
<!DOCTYPE html>
<html lang="ru">
  <head>
    <title>Библиотека</title>
  </head>
  <body>
    <h1 id="title">Новые книги</h1>
    <!-- список книг -->
    <ul class="books">
      <li>Мастер и Маргарита</li>
      <li>Тихий Дон</li>
    </ul>
  </body>
</html>
```

Браузер построит такое дерево (упрощённо):

```text
document                        ← корень, объект всего документа
└── html                        ← document.documentElement
    ├── head                    ← document.head
    │   └── title
    │       └── "Библиотека"    ← текстовый узел
    └── body                    ← document.body
        ├── h1#title
        │   └── "Новые книги"
        ├── <!-- список книг --> ← узел-комментарий
        └── ul.books
            ├── li → "Мастер и Маргарита"
            └── li → "Тихий Дон"
```

Отношения в дереве называют «семейными» словами:

- **родитель (parent)** — `body` для `h1` и `ul`;
- **дети (children)** — два `li` для `ul`;
- **соседи (siblings)** — `h1` и `ul` (у них общий родитель);
- **предки (ancestors)** — все элементы выше по дереву: для `li` это `ul`, `body`, `html`;
- **потомки (descendants)** — все элементы ниже: дети, дети детей и т. д.

## 3. Узлы: не только теги

Каждый объект дерева — **узел** (`Node`). Узлы бывают разных типов:

| Тип узла | `nodeType` | Пример | Что это |
|---|---|---|---|
| Элемент | `1` (`Node.ELEMENT_NODE`) | `<li>`, `<div>` | Тег. С ним работают чаще всего |
| Текст | `3` (`Node.TEXT_NODE`) | `"Тихий Дон"` | Текст внутри тега, в том числе пробелы и переносы строк |
| Комментарий | `8` (`Node.COMMENT_NODE`) | `<!-- список -->` | HTML-комментарий |
| Документ | `9` (`Node.DOCUMENT_NODE`) | `document` | Корень всего дерева |

```js
const h1 = document.querySelector("h1");

console.log(h1.nodeType);   // 1 — это элемент
console.log(h1.nodeName);   // "H1" — имя тега большими буквами
console.log(h1.tagName);    // "H1" — то же самое, но есть только у элементов

const text = h1.firstChild; // первый дочерний УЗЕЛ — текст внутри h1
console.log(text.nodeType); // 3 — текстовый узел
console.log(text.data);     // "Новые книги" — сам текст
```

**Откуда берутся «лишние» текстовые узлы.** Переносы строк и отступы между тегами в HTML — это тоже текст. Между `<ul>` и первым `<li>` в примере выше стоят перенос строки и пробелы, и браузер создаёт для них текстовый узел. Поэтому в части 2 мы будем различать свойства, которые возвращают **все узлы** (`childNodes`, `firstChild`), и свойства, которые возвращают **только элементы** (`children`, `firstElementChild`). В повседневной работе почти всегда нужны вторые.

## 4. Объект `document` и его главные свойства

`document` — глобальный объект, через который JavaScript получает доступ ко всему дереву.

```js
console.log(document.documentElement); // элемент <html>
console.log(document.head);            // элемент <head>
console.log(document.body);            // элемент <body>
console.log(document.title);           // текст из <title> — "Библиотека"

document.title = "Библиотека (3 новые)"; // меняет текст вкладки браузера

console.log(document.URL);             // адрес страницы
console.log(document.readyState);      // "loading" | "interactive" | "complete"
```

У объектов DOM есть **цепочка наследования**: каждый элемент «умеет» всё, что умеют более общие типы.

```text
EventTarget        ← умеет addEventListener (события)
  └── Node         ← умеет быть в дереве: parentNode, childNodes, appendChild
      └── Element  ← умеет атрибуты, классы, querySelector
          └── HTMLElement           ← общие свойства HTML-тегов: hidden, style, dataset
              ├── HTMLInputElement  ← value, checked, type
              ├── HTMLAnchorElement ← href
              └── HTMLButtonElement ← disabled …
```

Поэтому у `<input>` есть `value`, а у `<div>` его нет; зато и у того, и у другого есть `classList` и `addEventListener`. Посмотреть, какой у элемента тип, можно так:

```js
const input = document.querySelector("input");
console.log(input instanceof HTMLInputElement); // true
console.log(input.constructor.name);            // "HTMLInputElement"
```

## 5. Как и когда запускается скрипт

Браузер разбирает HTML **сверху вниз**. Когда он встречает обычный тег `<script>`, он **останавливает разбор**, загружает и выполняет скрипт и только потом продолжает. Отсюда главная ошибка начинающих:

```html
<head>
  <!-- ❌ Скрипт выполнится, когда <body> ещё не разобран -->
  <script src="script.js"></script>
</head>
<body>
  <h1 id="title">Новые книги</h1>
</body>
```

```js
// script.js
const title = document.querySelector("#title");
console.log(title);          // null — элемента ещё нет в дереве!
title.textContent = "Привет"; // TypeError: Cannot set properties of null
```

Есть несколько способов это исправить. Сравним их:

| Способ | Когда выполняется скрипт | Блокирует разбор HTML | Порядок нескольких скриптов |
|---|---|---|---|
| `<script>` в конце `<body>` | Когда парсер дошёл до тега (весь HTML выше уже в DOM) | Да, но HTML уже почти весь разобран | По порядку в коде |
| `<script defer>` | После разбора всего HTML, перед `DOMContentLoaded` | Нет, загружается параллельно | По порядку в коде |
| `<script async>` | Сразу, как только загрузился | Только на время выполнения | **Не гарантирован** |
| `<script type="module">` | Как `defer` (по умолчанию отложен) | Нет | По порядку в коде |

```html
<head>
  <!-- ✅ Рекомендуемый способ: скрипт загрузится параллельно с разбором HTML
       и выполнится, когда всё дерево уже построено -->
  <script src="script.js" defer></script>
</head>
```

`async` подходит для независимых скриптов (счётчики посещений, реклама), которым не важен порядок и не нужен готовый DOM. Для своего кода, который работает со страницей, используйте `defer` или `type="module"` (о модулях — в части 8).

## 6. События загрузки страницы

Иногда скрипт подключён так, что выполняется раньше, чем построен DOM (например, его подключил кто-то другой в `<head>` без `defer`). Тогда можно дождаться события.

```js
// DOMContentLoaded: HTML полностью разобран, дерево DOM построено.
// Картинки, шрифты и стили могут ещё загружаться.
document.addEventListener("DOMContentLoaded", () => {
  console.log("DOM готов");
  document.querySelector("#title").textContent = "Можно работать";
});

// load: загружено ВСЁ — картинки, стили, шрифты, iframe.
// Нужно редко: например, чтобы узнать настоящие размеры картинок.
window.addEventListener("load", () => {
  console.log("Страница загружена полностью");
});

// beforeunload: пользователь закрывает вкладку или уходит со страницы.
window.addEventListener("beforeunload", (event) => {
  // Если есть несохранённые данные, браузер спросит «Покинуть сайт?»
  event.preventDefault();
});
```

Свойство `document.readyState` подсказывает, на каком этапе страница:

```js
// Универсальная функция: выполнить код, когда DOM готов,
// даже если событие DOMContentLoaded уже прошло.
function onReady(callback) {
  if (document.readyState === "loading") {
    // DOM ещё строится — ждём событие
    document.addEventListener("DOMContentLoaded", callback);
  } else {
    // "interactive" или "complete" — DOM уже готов, запускаем сразу
    callback();
  }
}

onReady(() => console.log("Готово"));
```

## 7. Инструменты разработчика (DevTools)

DOM удобно изучать прямо в браузере. Нажмите **F12** (или Ctrl+Shift+I):

- **Elements (Элементы)** — текущее дерево DOM. Это не исходный HTML, а живое дерево: если скрипт что-то поменял, вы увидите изменения здесь. Элементы можно редактировать двойным щелчком.
- **Console (Консоль)** — здесь можно выполнять JavaScript и видеть ошибки.

Полезные приёмы в консоли:

```js
// $0 — элемент, выбранный сейчас во вкладке Elements
$0.textContent;

// $ и $$ — короткие версии querySelector и querySelectorAll (только в консоли!)
$("h1");
$$("li");

// console.dir показывает элемент как объект со всеми свойствами,
// а console.log — как кусок HTML
console.dir(document.body);
```

> Если в консоли красная ошибка — читайте её целиком: там написано, что случилось и **в какой строке** какого файла. По ссылке справа от ошибки можно перейти прямо к этой строке.

## 8. Итоги части 1

- DOM — дерево объектов, которое браузер строит из HTML. JavaScript меняет это дерево, а браузер перерисовывает страницу.
- В дереве есть узлы-элементы, текстовые узлы (включая пробелы и переносы строк) и комментарии.
- Доступ к дереву — через глобальный объект `document`.
- Скрипт, работающий со страницей, подключайте с `defer` (или `type="module"`), иначе он может выполниться до того, как появятся нужные элементы.
- `DOMContentLoaded` — DOM готов; `load` — загружено всё.
