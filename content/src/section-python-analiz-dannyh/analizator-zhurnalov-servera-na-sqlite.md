# Анализатор журналов сервера на SQLite

Задание выполняется в редакторе на странице (файл `main.py`). Программа запускается кнопкой «Запустить» прямо в браузере; в окружении доступен модуль `sqlite3`. Ввод с клавиатуры недоступен — все данные программа готовит сама, а результат печатает в вывод (это и есть ваш «терминальный» отчёт).

## Легенда

Веб‑сервер за сутки записал журнал доступа — десятки тысяч строк. Разобрать такой объём «вручную» или держать в обычном списке и перебирать циклами — медленно и неудобно. Правильный путь: загрузить записи в базу данных **SQLite**, построить индексы и получать ответы запросами. В этом задании вы пишете программу, которая:

1. **порождает** журнал доступа заданного размера по описанному ниже формату;
2. **загружает** его в базу SQLite (пакетная вставка в транзакции, индексы);
3. печатает **аналитический отчёт** по базе — разделами, как вывод консольной утилиты.

## Запись журнала

Одна запись — один HTTP‑запрос. Таблица `requests`:

| поле | тип | смысл |
|---|---|---|
| `ip` | TEXT | адрес клиента |
| `ts` | TEXT | время в ISO 8601, вида `2026-11-01T09:12:44` |
| `method` | TEXT | `GET` / `POST` / `PUT` / `DELETE` |
| `path` | TEXT | путь запроса, например `/api/users` |
| `status` | INTEGER | код ответа (200, 404, 500 …) |
| `bytes` | INTEGER | размер ответа в байтах |
| `resp_ms` | INTEGER | время ответа в миллисекундах |

## Как порождать данные

Задайте в начале программы размер журнала `N` (возьмите `N = 20000`; код должен оставаться правильным и при большем `N`). Зафиксируйте случайность — `random.seed(2026)` — чтобы результат был воспроизводимым. Для каждой из `N` записей выбирайте значения случайно из наборов:

- **ip** — один из: `10.0.0.5`, `10.0.0.6`, `192.168.4.9`, `192.168.4.21`, `203.0.113.7`, `203.0.113.44`, `172.16.0.3`;
- **ts** — время в пределах одних суток `2026-11-01` (случайные час/минута/секунда);
- **method** — один из `GET`, `POST`, `PUT`, `DELETE` (чаще `GET`);
- **path** — один из: `/`, `/api/users`, `/api/login`, `/api/report`, `/img/logo.png`, `/static/app.js`, `/api/orders`;
- **status** — в основном `200`, иногда `301`, `404`, `401`, `500` (ошибок должно получаться заметное меньшинство);
- **bytes** — целое от 0 до ~60000;
- **resp_ms** — целое от 1 до ~2000 (у части путей — заведомо больше).

Кроме того, **примерно 1–2 % записей сделайте «битыми»**: в таких строках одно из полей пустое или не число. Формируйте журнал как список строк (каждая строка — поля через пробел, запрос в кавычках: `<ip> <ts> "<method> <path> HTTP/1.1" <status> <bytes> <resp_ms>`) и затем **разбирайте** эти строки обратно при загрузке — битые строки должны отсеиваться на разборе, а не ломать программу.

## Что должна печатать программа (разделы отчёта)

1. **Сводка** — загружено записей, пропущено битых, уникальных IP, период (`min(ts)` и `max(ts)`), суммарный объём `bytes`.
2. **Топ‑5 IP** по числу запросов — адрес и количество, по убыванию.
3. **Ошибки по классам статуса** — для классов `2xx`, `3xx`, `4xx`, `5xx` количество и доля в процентах (один знак после запятой).
4. **Пиковый час** — час суток (`00`–`23`) с наибольшим числом запросов и само число.
5. **Самые медленные пути** — для каждого `path` среднее `resp_ms`; вывести пути со средним выше 500 мс, топ‑5 по убыванию среднего (путь, число запросов, среднее).

Заголовок каждого раздела отделяйте строкой‑разделителем (например `===== Сводка =====`), значения — по одному в строке. Все числа в разделах 2–5 должны быть получены **SQL‑запросами к базе**, а не досчитаны на Python по спискам.

## Требования

- Все запросы — **параметризованные** (значения через `?`), без склейки SQL строками.
- Загрузка — **пакетами** через `executemany(...)` внутри одной транзакции (а не по одной `INSERT` на запись).
- Создайте **индексы** по `status`, `path` и `ts`; в комментарии поясните, какие разделы отчёта они ускоряют.
- Разбор записи и подсчёт битых строк — аккуратный: пустое/нечисловое поле → строка пропускается и учитывается в счётчике, программа не падает.
- Аналитику разнесите по **функциям** (загрузка, и по функции на раздел отчёта); «магические» ответы в коде не зашивать.
- База — в памяти (`sqlite3.connect(":memory:")`) достаточно.

## Как сдать

Напишите решение в редакторе (`main.py`), проверьте вывод кнопкой «Запустить», затем нажмите «Сдать». Преподаватель смотрит ваш код и результат: потоковую/пакетную загрузку, схему и индексы, параметризованные запросы, корректность всех пяти разделов и обработку битых строк.
